Qwen3 — 工业 OPD 的标准范本

Canonical Alibaba Qwen Team2025.05
Qwen3 的 OPD Pipeline 详解

Qwen3 的技术报告是目前工业 OPD 文档化最完整的参考。以下是其 post-training pipeline 的 OPD 部分：

阶段 1：Off-Policy SFT 冷启动（~1B token）
数据 A：来自 Qwen3-72B-Instruct（/think 教师）生成的带推理链样本
数据 B：来自 Qwen3-72B-Instruct（/no_think 教师）生成的无推理链样本
→ 学生（7B/14B/32B）在教师数据上做标准 SFT，建立思维模式基础

阶段 2：On-Policy KD（核心 OPD 阶段，~500M token）
→ 学生生成 rollout：y ~ π_S(·|x)（含 /think 和 /no_think 两种 prompt）
→ 教师在学生 rollout 上计算 logit-KL：
L = E_{y~π_S}[D_FKL(π_T(·|x,y_<t) ‖ π_S(·|x,y_<t))]
→ 教师 = Qwen3-72B-Instruct（始终不变，满足"教师一致性"）

关键参数：
KL 系数 β = 0.03；Top-K logits K = 150；学生 rollout 温度 T = 0.7
为什么 FKL 而非 RKL？

Qwen3 选择 FKL（前向 KL，mean-seeking）而非 RKL，与大多数学术论文推荐相反。Qwen 团队的实验发现：在已有冷启动 SFT 基础上（学生已经和教师思维模式对齐），FKL 的"覆盖所有教师模式"特性反而更有利——学生已经具备基础能力，需要的是全面覆盖教师的长尾知识，而非集中于主模式。

成本对比数据（论文原文）
方法相对计算成本Qwen3-7B MATH-Hard
纯 SFT-on-Teacher1×60.2%
纯 RL（GRPO）~10×71.8%
OPD（SFT冷启动+on-policy KD）~1.2×（≈ 1/8.3 of RL）71.2%（-0.6pp vs RL）

10× 成本差距是 OPD 在工业界快速普及的根本原因。

为什么 Qwen3 成为工业标准范本？

Qwen3 是首个完整公开 OPD pipeline 超参数（β、K、T、数据比例、冷启动规模）的 SOTA 模型报告，且代码（verl recipe）和模型均开源。全世界的研究者都在用 Qwen3 的参数作为 OPD 超参数的起点——这就是为什么 Thinking Machines Lab 博客说"复现 Qwen3"而非"复现 GPT-4"。

DeepSeek-V4 — 首个用 OPD 替代 RL 统一阶段的模型

里程碑 DeepSeek-AI2026.04
背景：为什么 DeepSeek-V4 放弃 RL 统一阶段？

DeepSeek-V3 和 DeepSeek-R1 使用大规模 GRPO RL 训练，虽然效果优秀，但有两个工程痛点：(1) RL 统一阶段（将多域专家整合为通用模型）需要极大的计算资源和精细调参；(2) 多域专家 → 通用学生的知识迁移用 RL 效率低（稀疏奖励无法同时覆盖所有域）。V4 用多教师 OPD 解决了这两个问题。

多教师 OPD（MOPD）架构
各专家独立训练（阶段 1）：
数学专家 T_math：SFT + GRPO，只训练数学数据
代码专家 T_code：SFT + GRPO，只训练代码数据
... 其他域专家同理

MOPD 统一阶段（阶段 2，替代 RL 统一）：
学生生成 rollout：y ~ π_S(·|x)（在所有域的混合 prompt 上）
根据 prompt 域 d，选对应专家 T_d 计算 logit：
L = E_{(x,d)~data}[D_RKL(π_S(·|x,y_<t) ‖ π_{T_d}(·|x,y_<t))]

专家不一致处理（关键工程细节）：
当 prompt 属于多个域（如"写一个数学证明的代码"），
多个专家 T_math 和 T_code 的 logit 可能冲突
→ 使用全词汇表 KL（全 softmax，非 top-K）：
梯度在不一致 token 上相互抵消，自然稳定训练
全词汇表 KL vs Top-K KL
方法通信成本梯度稳定性（多专家不一致时）最终效果
Top-K KL（K=200）低差（不一致梯度叠加放大）基线
全词汇表 KL高（~64× vs K=200）好（全分布 KL 自然平滑）+2.1pp（MATH-Hard）

DeepSeek-V4 选择了全词汇表 KL，牺牲通信效率换取梯度稳定性——这在多专家场景下是正确的权衡。

V4-Pro vs V4-Flash 规模
  • V4-Pro：1.6T 参数 MoE，128 个专家，每步激活 16 个
  • V4-Flash：284B 参数 MoE，更适合部署
  • 两者共享同一套 MOPD pipeline，只在模型规模上有差异
历史意义

DeepSeek-V4 标志着 OPD 从"RL 的辅助手段"升级为"可以完全替代 RL 统一阶段的主要方法"。这是继 Qwen3 证明 OPD 在单教师场景有效之后，DeepSeek 在多专家/多域场景的验证。下一步可能：更多模型放弃独立的 RL 统一阶段，直接用 MOPD 完成专家整合。

GLM-5 — Cross-Stage OPD as Pipeline Glue

Zhipu AI / Z.ai2026.02
OPD 作为"阶段粘合剂"

GLM-5 提出了一个与 Qwen3/DeepSeek 不同的 OPD 使用模式：在各 post-training 阶段之间施加 OPD，防止知识遗忘和分布漂移。

GLM-5 六阶段 Pipeline：
1. Pre-training（预训练）
2. SFT（指令跟随）
→ OPD 粘合：SFT 后 OPD 锚定，防止 SFT 造成的分布漂移
3. Reward Modeling
4. PPO/RLHF
→ OPD 粘合：RL 后 OPD 锚定，防止 RL 造成的过优化
5. Safety Alignment
→ OPD 粘合：安全对齐后 OPD 锚定，防止安全训练损害能力
6. Final Post-Training
OPD 锚定的具体实现

每次阶段切换时，用"前一阶段末的模型"作为教师，在新阶段初的学生 rollout 上做少量（1K-5K 步）KD：

  • 成本极低（只需少量步骤）
  • 防止灾难性遗忘（保留上一阶段的核心能力）
  • 不影响新阶段的训练目标（KL 系数小，β=0.01-0.02）
GLM-5 OPD 模式的推广价值

GLM-5 的"阶段间 OPD 锚定"思路非常实用——它不需要专门设计一个 OPD 阶段，而是在每次阶段切换时做"迷你 OPD"，维护连续性。这比 Qwen3 的"专门 OPD 阶段"代价更小，且几乎没有副作用。对于已有多阶段 post-training pipeline 的团队，这是一个低风险的 OPD 入门方式。

MiMo-V2-Flash — Multi-Teacher OPD（MOPD）

Xiaomi AI2026.01
MOPD 优势公式

MiMo-V2-Flash 是工业界首个公开 MOPD（Multi-teacher On-Policy Distillation）实现细节的报告，比 DeepSeek-V4 早 3 个月。

逐 token MOPD 优势（directional advantage）：
A_MOPD(t) = Σ_d w_d · [log π_{T_d}(y_t|·) - log π_S(y_t|·)]
w_d = 领域权重（根据 prompt 所属领域 d 动态分配，Softmax 归一化）

与 RL 优势的组合：
A_total(t) = A_RL(sequence level) + α · A_MOPD(t)
A_RL = GRPO 序列级奖励优势；A_MOPD = token 级多教师 OPD 优势
三个领域特定教师
  • 数学教师：在 MATH/AMC/AIME 上微调的 72B 模型
  • 代码教师：在 HumanEval/Leetcode 上微调的 72B 模型
  • 通用推理教师：Qwen3-72B-Instruct（通用）

根据 prompt 的领域标签，动态加权三个教师的 logit 贡献。

Gemma 2 — 首批工业模型显式命名 OPD

Google DeepMind2024.07
历史地位

Gemma 2 是首批（与 Qwen2.5 同期）在技术报告中显式使用"on-policy distillation"这一术语的生产模型报告，原文：

"We also use on-policy distillation, where the student generates completions from the SFT prompts. We then use knowledge distillation of the teacher model on the student completions, computing the KL divergence of teacher and student logits over student-generated text."

这段原文完美定义了 OPD 的核心操作，也是"工业界认可 OPD 作为独立范式"的标志性文本。

Gemma 2 的 OPD 实现特点
  • 教师 = Gemma 2 27B；学生 = Gemma 2 9B 或 2B
  • 仅在 SFT 之后做一轮 OPD（而非 Qwen3 那样专门的 OPD 阶段）
  • 无公开的超参数细节（保密）
  • OPD 被描述为"辅助"而非"核心"——这与后来 Qwen3 的定位形成对比

Nemotron Cascade 2 — 极高样本效率的多域 OPD

NVIDIA Research2026.03
核心数据：30-160 步匹配 RL 效果

Nemotron Cascade 2 报告了令人震惊的样本效率数字：

方法训练步数MMLU ProHumanEvalMATH
纯 RL (PPO)1,200 步72.1%85.3%68.4%
OPD（SFT冷启动+on-policy KD）120 步71.8%（-0.3pp）85.1%（-0.2pp）68.0%（-0.4pp）

10× 步数节省，性能损失 <0.5pp。Cascade 2 的解释：教师 token-level logit 信号（密集，每步 4096 个信号点）远比 RL 的标量奖励（稀疏，每步 1 个信号点）高效。

学生采样公式（论文原文）
论文原话："We sample y ~ π_inf(·|x)"（y 从推理策略 π_inf 采样）
注：π_inf 即学生当前的推理策略，这正是 OPD 的 C1 条件（学生自身分布采样）

可复制的工业 OPD Checklist
  1. 选教师：同系列更大模型（4-10× 参数），同 tokenizer 优先
  2. 冷启动：教师数据 SFT 1-2 epoch，建立思维模式一致性
  3. OPD 超参：从 β=0.03, K=150, T=0.7, FKL 开始；如果教师和学生能力差距大 → 改用 RKL
  4. 数据混合：/think 和 /no_think 各占约 50%（参考 Qwen3）
  5. 停止条件：当学生在验证集上的性能曲线趋于平稳时停止（通常 500-2K 步）
  6. 验证：OPD 结束后在 MATH/HumanEval/MT-Bench 上评估，与纯 RL 基线对比
工业 OPD 的未来方向

(1) 多教师 MOPD 普及：DeepSeek-V4 和 MiMo-V2-Flash 证明多教师 OPD 可以在单一 pass 中整合多域知识，预计这将成为下一代旗舰模型的标准 pipeline。
(2) 自适应 β 调度：目前工业界都用固定 β，AutoNPO 等方法的自适应调度有望成为下一个被工业采纳的改进。
(3) OPD + 持续学习：GLM-5 的阶段间锚定思路预示 OPD 将成为所有 post-training 阶段的标准防遗忘组件。
