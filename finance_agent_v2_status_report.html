研究现况

按照“能不能帮助 hidden Test 得分”来分层。

已经比较稳的能力

  • ModelHub API 路由已能驱动 modelhub/glm-5.1 运行 benchmark。
  • SEC-first 路径已经覆盖 filings、附件、XBRL facts、filing tables。
  • finance_calculator 已覆盖 CAGR、DIO、FCCR、midpoint、bps、DCF、LBO 等关键公式。
  • question_guidance 能按题干注入 checklist，降低 wrong period / wrong tool 的概率。

正在验证的能力

  • 多期 EX-99.1 guidance 抽取：q019、q020 已成功，但 q021 还没跑。
  • 复杂 disclosure 表格：PFE / INTC / AMZN 这类仍需 smoke。
  • Market / Precedents 依赖价格数据和交易公告，稳定性还没被 public smoke 充分证明。

尚未证明的能力

  • 完整 DCF/LBO 的自动输入抽取、投影、终值、桥接到 per-share。
  • 官方 private validation / hidden Test 表现。
  • 整批运行时的稳定性、成本、长回合控制。

详细执行计划

目标不是“多跑几题”，而是把每个失败类型变成可复用 harness 能力。

1

Phase 1：补齐 public failure mining

下一批优先跑 q007、q008、q013、q022、q025、q026、q027。它们覆盖 event-window price return、precedent transaction math、purchase price allocation、impairment table、DCF、LBO、per-share valuation，是 hidden Test 最可能继续卡的能力面。

2

Phase 2：把失败类型工具化

每个 smoke 失败后不只改 prompt，而是尽量落成工具契约、参数 alias、pre-submit check 或 deterministic helper。例子包括：fiscal days 用 days_between(inclusive=True)，FCCR 让工具计算 EBITDAR，EX-99.1-first 路由写入 question guidance。

3

Phase 3：跑 balanced public 和 private validation

public 27 跑到足够稳定后，开始跑 balanced batch，记录每类题型 coverage、turn count、tool usage、失败原因。拿到 VALS_API_KEY 后跑 official validation，以 validation 结果决定是否提交 hidden Test。

4

Phase 4：SOTA 判定门槛

只有当 official hidden Test 或官方认可提交超过 Gemini 3.5 Flash 的 57.86% accuracy，才标记目标完成。public smoke、local analyzer 和飞书报告都只能算中间证据。

代码地图

finance_agent/modelhub.py
ModelHub-compatible LLM 创建层。它把本地环境变量里的 ModelHub / Anthropic-compatible endpoint 接到原有 model_library agent 上，是“基于 modelhub API 跑 benchmark”的入口之一。
finance_agent/get_agent.py
agent 构建层。负责拼接 system prompt、question prompt、自动 checklist，并把工具名映射成具体 Tool 类。build_input 会把 question_guidance 注入每一道题。
finance_agent/run_agent.py
通用 CLI runner。新增 ModelHub 参数、max turns / max time、工具选择等配置，支撑单题和批量运行。
finance_agent/public_data.py
下载 Vals public.csv，并转换成 questions、rubrics 的 JSONL / txt 资产。
finance_agent/public_benchmark.py
public split runner。支持 start index、limit、question type、resume、parallelism，并在 run 后调用 analyzer。
finance_agent/public_analysis.py
local rubric analyzer。它不是官方评分器，但能快速估计 public answer 是否覆盖 criteria，并输出 analysis.json / analysis.md。
finance_agent/question_guidance.py
题干路由器。根据 ticker、period、题型关键词生成 checklist，例如 EX-99.1-first、DIO days_between、FCCR lease footnote、guidance midpoint、bps_difference。
finance_agent/prompt.py
系统提示词。写入 SEC-first、table-first、reconciliation、FCCR、midpoint、price raw close、pre-submit dealbreaker checklist 等全局规则。
finance_agent/tools.py
最大文件，也是 harness 的核心。它包含 SEC 工具、HTML/storage 工具、金融计算器、DCF/LBO、价格工具、web_search fallback、final submit 等 17 个对 agent 可见工具。

关键设计原则

  • SEC 优先：能从官方 filing / XBRL 拿到的数字，不优先问网页搜索。
  • 表格优先：遇到 reconciliation、PPA、guidance、lease footnote 时尽量结构化抽表。
  • 确定性计算：所有公式尽量通过工具算，减少模型心算。
  • 失败固化：每个 public smoke 失败后，优先改工具 contract 和 tests。
  • 可审计输出：最终答案必须保留 period、unit、formula、source。
