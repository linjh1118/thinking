金融基模训练 Topic 组合
TL;DR

金融 AI 的战略上限不是把客服做得更像人，而是把研究、投顾、合规和财务等专业任务变成可审计、可执行的工作。对基模训练团队而言，真正的价值是让同一 Harness 更强，并把达到同等质量所需的工具调用、脚本分支和人工复核压下来。

01 · PRODUCT
金融 AI 的壁垒不在“回答”，而在“完成工作”。

最终交付物应该是带来源的研究、可复算的模型、可编辑的工件、受控的业务动作。

02 · SYSTEM
Harness 决定系统下限，模型决定能否走向未知任务。

已知流程靠编排兜底；未见实体、时间、工具组合与冲突规则依赖模型泛化。

03 · TRAINING
少写规则、少调工具、少返工，就是基模智能的业务价值。

不要只报静态 QA 分数；要报 episode 成功率、调用成本和人工编辑距离。

三件优先做，三件不要先做

做：Mira Research OS

把财报复盘、公司深研、筛选发现、估值与监控串成长期研究记忆，而不是再做一个研报生成器。

做：Advisor OS

从会前、会中、会后占领客户事实生成时刻，再连接确定性规划和 next-best-action。

做：Finance Runtime & Evals

把工具、证据、权限、审批、回归评测做成两条产品线共用的运行时。

不先做：金融聊天壳

没有专有数据、动作和评测的问答入口，会迅速被通用模型与 Office 平台吸收。

不先做：自动荐股 / 交易

智能上限、适当性和系统性风险尚不支持跨过持牌专业人士的最终批准。

不先做：平台先行

Runtime 必须由真实任务倒逼生长；没有专业用户修改与拒绝数据，就没有训练飞轮。

TL;DR

28 个样本指向同一条扩张路径：先拿下窄而高频、结果可验的专业任务，再沿数据、工件、审批与系统记录扩成 OS。创业公司的产品不是“金融更懂的聊天”，而是“更少人工搬运的工作系统”。

窄任务切入先解决一个高频痛点，再进入上下游。

TL;DR

基模训练师不该与 Harness 团队争论“谁更重要”。正确问题是：哪些能力必须进入参数，才能让系统在未知任务上泛化，并用更少的规则、调用和复核达到相同或更高质量。

基模训练价值 = 质量增益 + Harness 压缩 + 泛化半径 + 风险边界 − 通用能力回退 不是数学等式，而是汇报口径：每项都必须有独立指标和对照组。

把责任边界说清楚

DATA / PRODUCT

提供“工作真相”

  • 真实专业任务与修改记录
  • 授权数据与 point-in-time 语料
  • 工件模板和业务成功标准
  • 持牌专家的拒绝原因
BASE MODEL

学习可迁移能力

  • 任务分解与证据覆盖规划
  • 时间、数值、情景与反事实推理
  • 工具选择、参数构造与结果综合
  • 政策推理、不确定性与拒答
HARNESS

保证可控执行

  • 连接器、权限、状态与重试
  • 计算器、代码、Office 与 CRM
  • 证据账本和工件编译
  • 审批、回滚、观测与回归
DETERMINISTIC ENGINE

承担硬约束

  • 税务、现金流、估值公式
  • 适当性与合规硬规则
  • 账本、余额与交易限制
  • 同输入同输出的高责任计算

为什么金融基模训练不是“多喂金融语料”

XFinBench
论文事实 4,235 道研究生级多模态金融题；最佳文本模型 67.3%，仍落后人类专家 12.5 个百分点，时间与情景推理尤其弱。
知识不是主要剩余误差
FrontierFinance
论文事实 共同 Harness 下最强系统仅 56.0%；筛选发现和行业宏观最高仅 33% / 39%。
开放任务仍有巨大上限
FinToolBench
论文事实 760 个可执行工具、295 个必须调用工具的问题，并单独评测时效、意图与监管领域对齐。
Tool use 必须原生训练
DianJin-R1
论文事实 结构化监督与 RL 训练后的单次推理模型，在真实合规集上匹配或超过更高计算成本的多 Agent 系统。
模型能压缩 Harness 复杂度
CNFinBench
论文事实 从单模块进入完整执行链，模型平均下降 15.4；多轮攻击第二轮平均违规上升 159.05%。
能力与合规必须共同训练

基模训练师的四个价值证明

01 · 同 Harness 更强

锁定数据、工具、Prompt 与预算，只替换 base model；hard slice 的 episode 成功率提升才算模型增益。

02 · 同质量更省

在不降低质量和合规的前提下，减少 tool calls、tokens、分支脚本、延迟与人工复核。

03 · 未见任务更稳

在未见公司、事件窗口、工具组合和工作流上保持增益，证明学到能力而不是记住模板。

04 · 风险边界更清楚

在证据不足、规则冲突和越权请求中校准不确定性，主动补证、降级或请求批准。

TL;DR

老板给的“提高金融基座大模型智能上限”适合作为总纲，但需要拆成六个可评测 Topic。前三个直接提高专业任务能力，第四个守住高风险边界，第五个专门证明训练 ROI，第六个形成中文与跨市场差异化。

建议汇报的 9 个指标

Episode success最终专业任务是否完成，不只看最后一句。
Evidence coverage关键事实是否被来源支持，是否遗漏评分点。
Numeric integrity数值、单位、币种、期间、公式与可复算性。
Tool efficiency选对工具、参数正确、无效调用与重试次数。
Scenario consistency假设变化是否沿模型与结论一致传播。
Risk & calibration越权、违规、证据不足时的拒绝与置信度。
Artifact correctnessExcel 公式、PPT 数字、CRM 字段和业务动作。
Human edit distance专家从初稿到可用结果需要改多少、为何改。
Cost / latency / calls相同质量下，真实系统复杂度下降多少。

建议的 Go / No-Go 门槛

以下为路线建议，不是外部 Benchmark 官方标准；团队应在基线跑通后校准。

模型增益

同 Harness 的目标 hard slice 至少出现清晰、统计稳定的绝对提升；不能只靠总体平均分掩盖。

压缩收益

非劣质量和风险下，tool calls / tokens / latency / 人工复核中至少两项显著下降。

泛化保留

未见实体、事件窗口与工具组合仍保留大部分增益；近邻样本泄漏必须阻断。

回退控制

通用能力与高风险合规不能因金融增强而明显退化；关键违规采用零容忍门禁。

90 天最小闭环

0–2 周 · 定义

选择 3 个 hard slices；冻结相同 Harness、工具预算、数据截止日与评分器。

3–5 周 · 数据

采集专家 episode、证据账本、失败恢复和工件修改；按实体图与时间窗切分。

6–9 周 · 训练

先做可回放 SFT；每轮同时跑 A/B/C/D 四格，不只报训练集内分数。

10–13 周 · 影子

进入研究员/投顾影子流量，收集编辑距离、拒绝原因、调用成本与风险事件。

TL;DR

关键判断尽量回链论文、公司公告和官方产品页。融资、用户数、资产规模与效率数据均为公司公开口径；本页使用它们识别产品方向，不把它们当成独立审计结论。
