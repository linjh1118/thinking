PROJECT BATTLE MAP · P001

AI 智能分诊：不是“上线模型”
而是验证一条业务因果链

规则约束风险、AI 处理语义、人工低成本覆盖：减少跨队列转派，缩短首次响应，同时守住 SLA 与重大错分。

23.4%基线转派率
≤10%成功阈值
<0.3%重大错分护栏
主假设 H1：首次正确分诊率提高 → 无效队列等待减少 → 首次响应缩短 → SLA 更稳定；若结果只提高模型准确率，却没有改变这条链，就不算项目成功。

1为什么现在做

至少一次跨主队列转派23.4%
转派工单首次响应中位数71m
新客服错分 / 成熟客服2.1×
主管人工搬运 / 人 / 日47m
分诊动作空间有限、结果可追踪、可人工覆盖；相比自动回复，更适合作为首个 AI 自动化项目。

2目标与非目标

✓ 首期要证明
  • 转派率 ≤10%
  • 首次响应 ≤27m
  • SLA 不恶化
  • 覆盖可审计
× 首期明确不做
  • 自动生成回复
  • 图片 / 语音理解
  • 在线自学习
  • 高风险自动执行

3角色行为改变

坐席：从人工选队列 → 接受 / 覆盖建议
主管：从搬运工单 → 处理低置信度与异常
运营：从堆关键词 → 管硬约束与分类体系
管理员：从被动救火 → 管开关、审计与回滚

4决策架构：风险不是平均分类误差

1工单创建 · 标准化、去重、输入完整度
2硬规则先行 · VIP / 安全 / 退款 / 地域 / 权限
3AI 语义分类 · 类型、优先级、队列、置信度
4策略决策 · 风险 × 置信度 → 自动 / 确认
5执行与反馈 · 接受、覆盖、最终队列、结果
高风险
人工确认
普通 + 高置信
自动执行
普通 + 低置信
人工确认

5真正关键的产品需求

R1模型建议、策略动作与最终结果全链审计
R2租户 / 类型级建议模式与自动模式
R3两次点击内完成人工覆盖与原因反馈
R4高风险无论置信度均强制人工确认
R5AI 超时 3 秒回退原规则，不阻塞建单
R7平台与租户双层一键停用，2 分钟生效

6指标与护栏

转派率23.4% → ≤10%
首次响应中位数38m → ≤27m

SLA ≤8.1% · 覆盖 ≤15% · 重大错分 <0.3% · P90 延迟 <10s

自动化率只是解释变量，不是成功指标。

7灰度路径

8停止线

重大错分 ≥0.3% → 停止自动执行
SLA 较基线上升 ≥1.5pp → 回滚
跨租户数据事件 → 全局停用
P90 延迟 ≥10s 持续 30m → 降级
问题先于方案

用行为与结果证据立项，而不是因为“AI 能做”。

目标必须可证伪

明确基线、阈值、观察窗和护栏，避免事后改口径。

风险进入架构

规则、确认、覆盖、审计和回滚是方案主体，不是上线附录。
