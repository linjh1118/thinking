♻️ 自蒸馏 OPSD — 特权上下文（9 篇深度解读）

本节 TLDR

OPSD（On-Policy Self-Distillation）的核心洞察：不需要外部更强的教师——同一个模型在"有特权信息"和"无特权信息"两种条件下表现差异，可以作为自我蒸馏的信号。特权上下文可以是：已验证的推理链、正确答案、"请简洁"指令前缀、更长的上下文窗口、知识文档……OPSD 是目前最符合"自力更生"精神的 OPD 变体，无需外部大模型。

OPSD: Self-Distilled Reasoner

Canonical OPSD UCLA / Meta FAIR2026.01 Code
OPSD 的定义性论文

这篇论文正式定义了 OPSD（On-Policy Self-Distillation）这个概念，并建立了"特权上下文"的操作化定义。核心思想：对于数学/推理任务，如果给模型已验证正确的推理链作为前缀，它能生成更好的答案分布——这个"更聪明的自己"就是教师。

训练流程详解
教师端（同一个模型，有特权上下文）：
输入：(x, c*)  其中 c* = 已验证正确的推理链
计算：log π_θ(y_t | x, c*, y_{<t})  对所有 token 位置

学生端（同一个模型，无特权上下文）：
采样：y ~ π_θ(·|x)  （on-policy，C1 满足）

损失（Point-wise Clipped RKL）：
L = Σ_t min(π_T(y_t|·)/π_S(y_t|·), clip_max) · log π_S(y_t|·)
clip_max = 10（防止重要性权重爆炸）

注意：教师和学生共享同一套权重 θ！
训练时只有学生端反向传播，教师端 frozen（no_grad）
已验证推理链的获取方式
  1. 用 beam search 或多次采样生成候选推理链集合
  2. 用验证器（数学题 = 答案比对；代码 = 单元测试）筛选正确的推理链
  3. 从正确推理链中随机采样 c*，作为特权上下文输入教师端
关键实验：vs GRPO 的成本对比
方法MATH 准确率GPU 小时消耗rollout 数量
GRPO72.4%160 GPU·h8×16=128/step
OPSD72.8%18 GPU·h（1/8.9×！）1×8=8/step
SFT-on-Teacher68.1%40 GPU·h—

OPSD 以约 1/9 的计算成本实现了与 GRPO 相当的效果。核心原因：RKL 的逐 token 密集信号比 GRPO 的稀疏序列奖励高效得多。

基于 TRL GOLD Trainer 的实现
from trl.experimental import GOLDTrainer

# GOLD（Gold On-policy Learning via Distillation）是 OPSD 的 TRL 实现
trainer = GOLDTrainer(
    model=model,  # 教师和学生共享同一个 model 对象
    privileged_context_fn=get_verified_chain,  # 获取已验证推理链的函数
    loss_type="clipped_rkl",
    clip_max=10.0,
    rollout_batch_size=8,
)
OPSD 的核心哲学突破

OPSD 证明了"超越当前自己"不需要外部更大的模型。模型在有额外信息时（已知答案）的表现，可以作为其在无信息时（正常推理）表现的"上限目标"。这种"借助外部验证，指导内部学习"的模式，与 STaR（Self-Taught Reasoner）有深刻联系，但 OPSD 用 KL 蒸馏代替 SFT，保留了更多分布信息。

CRISP / OPSDC: Reasoning Compression via Self-Distillation

LinkedIn2026.03
问题：Long CoT 太冗长，但压缩损失质量

DeepSeek-R1、QwQ 等推理模型生成 4000-8000 token 的长链推理，实际有效内容可能只有 30%。传统压缩方法（RL + 长度惩罚）会导致熵坍缩：模型为了减少 token 开始走捷径，跳过重要推理步骤，质量下降。

CRISP 的特权上下文：指令前缀
教师 = 同模型 + "请简洁回答" 前缀：
输入：("请用最简洁的方式回答，不要废话 " + x)
输出：y_concise ~ π_θ(·|"简洁指令" + x)  （短而精的推理链）

学生 = 同模型，正常推理：
输入：x
采样：y_student ~ π_θ(·|x)  （可能很长）

目标：在学生的 rollout y_student 上，用教师的 y_concise 分布做 RKL 蒸馏
→ 学生逐渐学会"不用指令也能简洁推理"
为什么不产生熵坍缩？

RL + 长度惩罚的问题：奖励函数直接惩罚"长"，模型学到的是"尽量少输出"，不管质量。

CRISP 的 KL 蒸馏信号：教师的"简洁版"在每个 token 位置都提供了"下一步往哪走"的方向，学生学到的是正确的简洁推理路径，而不是"尽量截断"。

压缩效果
方法平均推理长度MATH 准确率质量保留率
原始 Long CoT4,200 tokens74.2%100%（基线）
RL + 长度惩罚1,800 tokens（-57%）68.1%（-6.1pp）82%

应用价值

CRISP 是目前最优雅的 Long CoT 压缩方案。如果你正在做"推理模型推理速度优化"，CRISP 是首选工具：压缩率 ~60%，质量损失 <2pp，且不需要任何外部模型。唯一前提：你的模型必须能理解"简洁推理"这个指令（需要一定的指令遵循能力）。

OPCD: On-Policy Context Distillation

Microsoft Research2026.02
核心任务：将上下文知识内化到模型权重

RAG（Retrieval-Augmented Generation）每次都需要外部检索，推理时开销大。OPCD 的目标是：把 RAG 教师（模型 + 知识文档上下文）的知识内化到学生权重，使学生在没有文档的情况下也能正确回答。

训练框架
教师 = 同模型 + 相关知识文档：
输入：(x, doc)  其中 doc = 检索到的相关文档
输出分布：π_θ(·|x, doc)  （有"外挂知识"的更聪明版本）

学生 = 同模型，无文档：
采样：y ~ π_θ(·|x)  （on-policy rollout）

损失：在学生 rollout y 上，最小化
D_RKL(π_S(·|x, y_{<t}) ‖ π_T(·|x, doc, y_{<t}))
→ 学生被推动向"知道文档内容"的教师靠拢
知识内化的数学直觉

训练后，学生权重 θ 吸收了大量 (x, doc) 对的 KL 梯度，等价于将"doc 的信息"以参数化形式存储在权重中。这类似于"显式记忆（RAG）→ 隐式记忆（模型权重）"的知识蒸馏。

局限性

OPCD 只能内化训练时见过的知识文档类型的"知识模式"，对新领域（训练集中没有的文档类型）泛化能力有限。对于需要完整、精确事实（如特定日期、具体数字）的查询，RAG 仍优于 OPCD 内化。两者可以结合：OPCD 内化通用推理模式，RAG 提供精确事实。

Apple SSD: Embarrassingly Simple Self-Distillation

Apple Machine Learning Research2026.04
"极其简单"的自蒸馏

Apple SSD 的名字里有"Embarrassingly Simple"——它用最简单的特权上下文：不同的解码配置（温度/截断采样）。高温度采样生成多样性样本（宽探索），低温度采样生成高质量样本（深利用），两者组合作为自蒸馏的两端。

三阶段流程
阶段 1：高温采样（教师端）
y_diverse ~ π_θ(·|x, T=1.2)  （temperature=1.2，生成多样性候选）

阶段 2：验证过滤
y_verified = filter(y_diverse, verifier)  （只保留正确的）

阶段 3：SFT 或 OPD 蒸馏
用 y_verified 做 SFT（Apple SSD 论文）或 RKL 蒸馏（退化为 OPSD 风格）

特权上下文 = 高温度配置 → 验证过滤 → 高质量样本集
与 STaR 的对比
维度STaRApple SSD
采样策略固定 greedy / beam高温多样性采样
训练方式SFT on correctSFT on correct（相同）
OPD 程度低（off-policy SFT）中（on-policy 采样，off-policy 训练）
创新点首次提出自举高温采样 + 大规模验证
Apple SSD 是严格 OPSD 吗？

有争议。Apple SSD 的训练阶段用的是验证后的"高质量样本"做 SFT，不是在学生当前 rollout 上做 KL——严格说是 off-policy SFT，不满足 OPD 的 C1 条件（训练时学生采样）。AwesomeOPD 将其归类为"退化的 OPSD"，论文作者也承认这一点。但其采样策略（on-policy 高温采样）使其具有 OPD 精神。

其余 OPSD 方法速览

5 篇
SDFT-Continual（MIT / ETH, 2026.01）—— Demo 条件化的自蒸馏，解决持续学习中的遗忘问题。教师 = 同模型 + 已完成任务的 demonstration，学生 = 同模型在新任务上生成 rollout。在不遗忘旧任务的前提下持续学习新任务。
OEL: Online Experiential Learning（Microsoft Research, 2026.03）—— 最接近"具身自蒸馏"的方案。同模型在交互式游戏环境中生成轨迹，成功轨迹的条件分布作为特权上下文。面向游戏规划/导航领域，RKL 在交互轨迹上进行。
MTP Self-Distill（UMD / LLNL, 2026.02）—— Multi-Token Prediction（MTP）模型的自蒸馏：单 token 预测头（无特权）向 multi-token 预测头（有特权：知道未来多个 token）学习。特权上下文 = 未来 token 的 lookahead。
GATES（UMD, 2026.02）—— 文档条件化的同模型教师，RKL 由教师共识门控。消融实验显示：off-policy 轨迹级蒸馏是主要增益来源（约 80%），on-policy 部分贡献约 20%——诚实的消融，值得关注。
OPSDL: Long-Context Self-Distillation（Baidu, 2026.04）—— 用短上下文同模型（教师）蒸馏到长上下文学生。特权上下文 = 更短的历史（教师处理更精炼的 context），学生在长历史上做 rollout，逐 token Point-wise RKL。解决长上下文 LLM 训练中的"位置编码外推"问题。
