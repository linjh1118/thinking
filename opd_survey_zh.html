🎯 核心定义：什么是 OPD？

On-Policy Distillation（在策略蒸馏）= C1 + C2

  • C1（在策略采样）：学生在训练过程中采样自己的轨迹 y ~ π_student(·|x)，而非在固定的教师数据上训练。
  • C2（教师监督）：教师在这些学生生成的样本上提供逐 token / 序列级别的监督信号（logits、奖励、评分等）。
  • OPSD（在策略自蒸馏）：特殊情况——教师和学生是同一个模型，但教师拥有特权上下文（已验证的推理链 / 答案 / "请简洁"前缀 / 更长上下文等），或教师是更早的 checkpoint。

四维设计轴

  • 教师来源：外部模型 · 同模型+特权上下文 · 早期 checkpoint · 多教师 · 判别器
  • 监督信号：logits / top-k / 序列奖励 / 口头评分 / 判别器 / 验证器 / 特征
  • rollout 消耗方式：全部 / 筛选 / 截断 / 替换 / 作为 PG 样本
  • pipeline 位置：冷启动 / 中期 / RL 替代 / RL 内部 / 跨阶段 / 压缩 / 持续锚点

TLDR — 一句话总结 OPD 为什么重要

OPD 让小模型（学生）在自己生成的数据上获得大模型（教师）的指导，比 SFT 更高效（避免了分布偏移），比 RL 更稳定（教师的 logit 信号比稀疏奖励更密集）。Qwen3 报告 OPD 仅用 RL 十分之一的成本达到了同等性能；DeepSeek-V4 用多教师 OPD 替换了 RL 统一阶段。

📚 综述 & 基础论文（7 篇）

元参考和奠基性工作，为理解 OPD 全景提供理论根基。GKD 和 MiniLLM 是"命名 OPD"的两篇开创性论文。
GKD: On-Policy Distillation of Language Models — Learning from Self-Generated Mistakes
ICLR 2024 Google DeepMind2023.06
开创性论文——首次正式命名"On-Policy Distillation"的概念。使用广义 JSD（可配置 FKL/RKL），在学生和教师数据之间通过 λ 参数混合。核心洞察：让学生在自己犯错的分布上接受教师指导，比在教师数据上训练更高效。已在 TRL 中实现为 GKDTrainer。
MiniLLM: Knowledge Distillation of Large Language Models
ICLR 2024 Microsoft / Tsinghua2023.06
与 GKD 同期的另一篇开创性工作。使用 Reverse KL + policy gradient 进行序列级蒸馏。Mode-seeking 特性使小模型更集中学习教师的众数，避免"平均化"问题。比 GKD 早几天发布。
Thinking Machines Lab — On-Policy Distillation Blog
Thinking Machines Lab (Kevin Lu et al.)2025.10 tinker-cookbook
最清晰的 OPD 入门教程——"将 RL 训练器中的 KL 参考模型换成更强的教师"即可，仅需一行代码修改。在约 1/10 RL 成本下复现了 Qwen3 的结果。配套 tinker-cookbook 提供可复现的实现。
A Survey of On-Policy Distillation for LLMs
综述 Tencent2026.04
收录 50+ 方法的系统性综述，适合作为参考索引使用。涵盖了 OPD 的各种变体、损失函数选择、数据策略等。
Rethinking On-Policy Distillation: Phenomenology, Mechanism & Recipe
THUNLP Tsinghua2026.04
"OPD 理论"——识别出两个成功条件：(1) 教师和学生思维模式兼容 (2) 教师确实拥有学生不具备的新能力。提出实用 Recipe：off-policy 冷启动 + 教师对齐的 prompt 筛选。
Revisiting OPD: Failure Modes & Simple Fixes
CASIA2026.03
排错指南——诊断了三种失败模式：不平衡的单 token 信号、不可靠的前缀引导、tokenizer 不匹配。修复方案：截断 Reverse KL + top-p 采样 + 特殊 token 掩码。读这篇能省一周调试时间。
Lightning OPD: Efficient Post-Training with Offline OPD
Wu, Han, Cai2026.04
提出"离线 OPD"——预计算教师 log-probs，消除训练时需要在线教师服务器的需求。引入"教师一致性"概念：SFT 和 OPD 必须使用同一教师，否则梯度有偏。

🔬 白盒 OPD — 使用教师 Logits（17 篇）

白盒方法利用教师的 logits/log-probabilities在学生生成的 rollout 上进行逐 token 级别的监督。这是最"正统"的 OPD 形式。
DistiLLM: Streamlining Distillation via Skewed KL
ICML 2024 KAIST / Microsoft2024.02 Code
使用 Skewed-KL（FKL 和 RKL 的混合），通过参数 α 在前向和反向 KL 之间插值。配合重要性重加权的学生样本，实现自适应的 off→on-policy 过渡。
DistiLLM-2: Contrastive On-Policy Distillation
ICML 2025 Oral KAIST / Microsoft2025.03 Code
在教师数据上用 Skew-FKL、学生数据上用 Skew-RKL 的非对称损失设计。ICML 2025 Oral，是 DistiLLM 的显著升级版。
G-OPD: Generalized On-Policy Distillation
RUC / Tencent2026.02 Code
将 OPD 泛化为KL 约束的 RL，允许奖励缩放 >1 来"超越教师"。关键理论贡献：OPD = KL-constrained RL with reward extrapolation。
REOPOLD: Relaxed On-Policy Distillation
KAIST / Microsoft2026.03
将 OPD 视为带教师-学生 log-ratio 奖励的策略优化。使用混合奖励裁剪 + 基于熵的动态采样。"Relaxed"体现在放松了严格 KL 约束。
SCOPE: Signal-Calibrated On-Policy Distillation
USTC / Meituan / Fudan2026.04 Code
双路径自适应加权：在错误 rollout 上用教师-PPL 加权的 KL；在正确 rollout 上用学生-PPL 加权的 MLE。验证器路由机制。
TSD-KD: Token-Selective Dual Knowledge Distillation
ICLR 2026 Korea Univ.2026.03
混合方法：学生提议 + 教师重排的间接路径 + 选择性 logit KD 的直接路径。在 token 级别进行筛选。
HPD: Hybrid Policy Distillation
Code2026.04
将 KD 统一为 token 级别重加权似然，同时覆盖 FKL + RKL。轻量级近似在策略采样保持训练效率。后端支持 LlamaFactory 和 verl。
Speculative KD: Interleaved Propose-and-Correct
ICLR 2025 UCSB / Google2024.10
交织式提议-修正机制（gated KL），学生提议、教师修正。通过交错采样弥合师生差距。
DSKDv2: Cross-Tokenizer Distillation
BJTU2025.04 Code
在对齐的双重空间中计算 KL，支持跨词汇表蒸馏。同时支持 on/off-policy 模式。
Veto: Stable On-Policy Distillation
ACL 2026 Findings SNU2026.01
Logit 空间的几何桥接 + 自适应梯度否决机制（Adaptive Target Reformulation），提升 OPD 训练稳定性。
Fast OPD: Prefix-Truncated Distillation
Industrial2026.02
通过推理前缀截断减少 FLOPs，实现 2× 到 47× 加速。直觉：推理链的前缀大多是"模板"，教师和学生的差异集中在后半段。
Entropy-Aware OPD
KAIST / IBM2026.03
根据教师熵动态切换：教师熵高 → 用 FKL（覆盖多模式）；教师熵低 → 用 RKL（集中学习）。简单但有效。
TIP: Token Importance for On-Policy Distillation
Meta / LinkedIn2026.04
仅对 top-50% 高熵学生 token 施加 OPD 损失。节省约 47% 内存。
PACED: Frontier Curriculum Self-Distillation
LinkedIn2026.03
在学生能力边界构建前沿课程，难度加权 w(p)=p(1−p)。自蒸馏风格（特权上下文/早期 checkpoint）。
AdaSwitch: Adaptive On/Off-Policy Switching
RUC / Baidu2025.10
基于散度阈值动态在教师数据和学生 rollout 之间切换。
Constrained OPD (CMDP)
Huawei Noah's Ark2025.09
将 KL 约束建模为约束马尔可夫决策过程（CMDP），使用硬 KL 约束而非软惩罚。处于 OPD-RL 边界。

🎭 黑盒 OPD — 无教师 Logits（3 篇）

教师是 API-only（无 logits），OPD 使用标量奖励、口头评分、偏好或对抗判别器——全部基于学生 rollout评估。
GAD: Generative Adversarial Distillation — Black-Box OPD
Microsoft Research2025.11
黑盒 OPD 种子论文——训练判别器区分学生输出和教师（如 GPT-5）响应，minimax 博弯使判别器共演化为在策略奖励模型。Qwen2.5-14B 学生达到接近 GPT-5-Chat 的 LMSYS 评分。
OVD: On-Policy Verbal Distillation
HKU / Huawei2026.01
用口头评分（0-9分）替代逐 token logit 匹配。比基线高 +25.7%。
ORPO-Distill
Industrial2025.09
"混合策略"：学生生成的输出作为负样本，教师输出作为正样本，使用 ORPO 对比损失。NeurIPS 2025 Workshop。

♻️ 自蒸馏 OPSD — 特权上下文（9 篇）

同一个模型 = 教师 = 学生，但教师拥有特权上下文（已验证推理链、答案、前缀、更长上下文等）。差异来自条件而非权重。
OPSD: Self-Distilled Reasoner
Canonical OPSD UCLA / Meta FAIR2026.01 Code
OPSD 的定义性论文——用已验证推理链作为特权上下文，逐 token RKL + point-wise 裁剪。在 1×8 rollout、1024 长度下匹配 GRPO（8×16 / 16k）的效果。基于 TRL 的 GOLD trainer 构建。
CRISP / OPSDC: Reasoning Compression via Self-Distillation
LinkedIn2026.03
用"请简洁"指令前缀作为特权上下文。压缩长 CoT 时不产生熵坍缩（不像 RL+长度惩罚那样）。
SDFT-Continual: Self-Distillation for Continual Learning
MIT / ETH2026.01
Demo 条件化的同模型自蒸馏，实现持续学习而不遗忘。
OPCD: On-Policy Context Distillation
Microsoft Research2026.02
上下文内知识增强的同模型 → 移除上下文后的知识内化。学生在自己的 rollout 上用 RKL 学习教师（带知识上下文的同模型）。
OEL: Online Experiential Learning
Microsoft Research2026.03
同模型 + 交互式游戏环境。在交互轨迹上进行自蒸馏，面向游戏/规划领域。
MTP Self-Distill: Multi-Token Prediction
UMD / LLNL2026.02
多 token 预测同模型的自蒸馏。作者声明的 on-policy 方法。
Apple SSD: Embarrassingly Simple Self-Distillation
Apple MLR2026.04
"极其简单"——用 temperature/截断采样生成数据，然后 SFT。退化的 OPSD：特权上下文 = 不同的解码配置。接近 STaR 风格的自举。
GATES: Self-Distillation under Privileged Context
UMD2026.02
文档条件化的同模型教师，RKL 由教师共识门控。作者的消融实验显示 off-policy 轨迹级蒸馏是主要增益来源，on-policy 部分仅有"适度改进"。
OPSDL: Long-Context Self-Distillation
Baidu2026.04
短上下文同模型教师蒸馏给长上下文学生。逐 token Point-wise RKL。

🔁 迭代自举（2 篇）

同模型作为冻结的早期 checkpoint 教师。教师 snapshot 冻结一轮 → 学生训练 → snapshot 前滚。
SPIN: Self-Play Fine-Tuning
ICML 2024 UCLA2024.01 Code
学生采样（C1✓），但监督是序列级 DPO 偏好（对比前一个冻结 checkpoint），不是逐 token logit KL。更准确地说是"迭代 on-policy DPO"。
rStar / rStar-Math / rStar2-Agent
Microsoft Research2025.01
MCTS 筛选的学生样本 + SFT。教师信号是步骤级 PPM/判别器评分，不是逐 token logit KL。迭代自改进而非经典 OPD。

🤝 OPD-RL 混合 — RL 内部的 OPD（17 篇）

将 OPD 与 RLVR/GRPO/PPO/DPO 融合。教师 logits 变为 RL 目标内的密集奖励塑形或信赖域锚点。
SDPO: Self-Distillation Policy Optimization via RL
ETH / MIT2026.01
学生采样 rollout → 获取 token 化反馈 → 反馈条件化的自教师重评估 → 将修正后的 next-token 分布蒸馏回策略。面向代码、工具使用、科学推理。
OpenClaw-RL: GRPO + OPD Unified Trainer
Gen-Verse2026.03
判别模型提取后知之明提示，教师 token-logprob 差距 = 方向优势。在单一 trainer 中统一二值 RL 和 OPD。覆盖终端/GUI/SWE/工具调用。
AlignDistil: RLHF-Equivalent KD
ACL 2025 BJTU / Tencent2025.03
将 DPO 重新框架化为策略蒸馏。DPO 模型 + ref-model logits 的组合作为教师信号。
LUFFY: Mixed-Policy GRPO with Off-Policy Traces
Westlake U.2025.04
"在离策略指导下学习推理"。一半 on-policy 学生 rollout + 一半离策略 R1 trace 混入 GRPO。混合策略 OPD。
NPO / AutoNPO: Learn from Your Near-Future Self
IIE CAS / UCAS / JD.COM2026.04
"向未来的自己学习"——从同一训练运行的更后 checkpoint 选取验证器过滤的轨迹作为教师。选"足够强"（Q > 当前策略）又"足够近"（V 低）的教师。AutoNPO 自适应调度干预时机。
RLAD: Reinforcement-Aware KD
AWS2026.02
PPO/GRPO 的比率锚定到教师-旧策略混合体。信赖域似然比设计。
KDRL: Joint KD + RL
HIT / Huawei2025.06
统一的 Reverse-KL + GRPO 规则奖励目标。外部教师（Skywork-OR1）提供 KD 信号。
RLSD: Self-Distilled RLVR
Multi-org2026.04
RLVR 方向 + 教师证据比率调节幅度。将自蒸馏幅度与 RLVR 方向结合。
HDPO: Hybrid Distillation PO
NVIDIA2026.03
大部分 prompt 用 RL；在"悬崖"prompt 上生成特权 rollout 并自蒸馏。自蒸馏作为 RL 的回退机制。
SD-Zero: Self-Distillation Zero
Princeton / Toronto / CMU2026.04
生成器 + 修订器共享权重；修订器提供密集监督。将二值奖励转化为密集信号。
