金融 Agent 的小判断，
模型、数据和训练怎么选？

按六章组织技术报告。第 2–4 章提供备选方案，第 5 章说明用什么评测、怎样证明有效。

基于 BrainHao 调研、exp1 已检出的源码和现有实验记录。建议不等于已批准；本页不会提交训练任务。
论文主线是金融 Agent 的证据判断与动作选择。Introduction 用一个 Related Work 段落概括 Jev 工作；Eikos 是重要金融基线，篇幅与其证据价值相称。

Introduction 怎么写

动机：年份、单位、实体、证据充分性和工具参数的小错误，会放大为最终答案错误。目标：在明确候选集上输出可检验的决定及概率，支撑执行、继续检索或升级。

研究问题：金融适配是否改善判断？概率在新公司、新证据下是否可靠？相同工具和答案生成器下，是否改善整题成功率与成本？贡献待实验证实后再定稿。

Related Work 的覆盖范围

Jev 提供闭源类型化决策参照；AnyJev 研究冻结 LLM 的读出和校准；Kev 引入候选读出头；Laya 探索小型编码器与概率分布训练；JevK5、Eikos、decider、Tev1 代表 LLM 决策适配的不同实现；Decision 1.0 代表多尺寸的类型化评分路线。比较输出机制、监督与评测口径，不按公开榜单分数堆砌优劣。

源码与模型入口：Kev · AnyJev · Laya · JevK5 · Eikos · decider · Tev1 · Decision 1.0。Kev 的已检出版本与其余项目证据索引见第 6 页。

当前证据边界：exp1 只有 Kev 的 8 步 CPU 工程训练和小样本评测；没有 Eikos 实测、GPU 完整训练或 RLCD 结果。20 个评测状态来自单一公司，60 个类型化决定存在相关性，不能用来证明金融能力提升。
回答“在普通 LLM 上增添什么”。建议优先讨论 A2，A1 是必要的同骨干对照；现阶段不把新结构写成既定贡献。
A1 · 最少改动

使用已有 LM head，将候选映射为字母，在一个决策位置归一化；主要新增提示协议、训练和校准。

好处：易与 Eikos / JevK5 路线比较，改动小。

风险：字母及顺序偏置、token 映射；多问题的实际前向成本要实测。

消融：相同骨干冻结 vs LoRA，选项置换前后。

A2 · 建议候选

复用 Kev 的决定位置与候选表示读出，增加小型打分头；显式支持变化的候选文本。

好处：已有 exp1 编码与训练链路可用；接口自然。

风险：不是天然顺序不变；换头收益可能与预训练权重混杂。

消融：同一个基础 checkpoint、同数据预算下与 A1 比较。已发布 Kev 另作外部基线。

A3 · 成本方向

沿 Laya 等路线，用双向编码与候选标记评分。它是独立的小模型路线，不是普通生成式 LLM 上只加一个头。

好处：适合短证据、密集判断和低成本部署。

风险：长文截断与中文能力需单测；不同骨干无法隔离“头”的贡献。

消融：短证据等输入比较，另报长文端到端性能。

架构、初始化、参数规模分别控制

原始 Qwen 初始化、已发布 Kev 初始化、已发布 Eikos 初始化不是同一个因素。第一轮可复用 0.8B 做工程验证；论文级对照再选同规模骨干。Eikos 4B 作为外部金融基线，不用 0.8B 与 4B 的差异推导架构结论。

“答案有效性”辅助头也只是可选消融。动作概率受工具成本与效用影响，不能直接称为答案正确概率。

回答“普通数据集改造了什么”。建议 D1 为起点、D2 补独立的相关性监督；D3 需要真实或可回放的工具环境。可以组合选择。
D1 · 优先

从 FinQA 的表格与程序构造年份、指标、单位、实体一致性判断；生成只改变一个因素的正确/错误证据对。

标签：可执行核验 + 人工抽审。Noul 标注“证据是否支持”，Choice 标注下一动作。

缺口：现有单位是合成契约；母子公司需真实实体标注。不能把同一规则变形跨集合当 OOD。

D2 · 建议补充

从有文档、段落相关性标注的数据构造文档类型 Choice、片段相关性 Score；保留多相关答案。

价值：Score 有独立标签，不再只是动作标签的另一种编码。

代价：核验语料与标注访问，明确分级标准；负样本要有真实难例。

D3 · 闭环扩展

记录可见状态、候选工具/参数绑定、执行结果与修复路径，监督“执行 / 重查 / 升级”。

价值：覆盖基金代码、用户 ID、时间范围等实际错误，可接环境奖励。

代价：工具权限、响应快照、失败语义和泄漏审计；不能拿教师偏好代替执行成功。

所有方案共用的数据门槛

  • 以源财报、实体及时间分组，训练 / 验证 / 校准 / 阈值选择 / 测试隔离；同页衍生题不得跨集合。
  • 另外留出生成器家族和自然错误，不只切公司。检查与外部 benchmark 的文档及问题重叠。
  • 保留来源 ID、证据跨度、披露时点、标签生成规则和审核记录。教师软标签表达教师分歧，不自动代表真实概率。
  • 现有 7,530 个状态 / 22,590 个相关决定尚无人审；先补审核与多公司评测，再扩大训练。
第 4 章可以写 RLCD，但先选清具体算法。建议 C1 做第一轮研究候选，C0 必跑对照；C2 在工具环境准备好后讨论。
C0 · 必需对照

硬 / 软交叉熵；分别消融 Brier、有序 Score 的 RPS；独立集合温度校准。

优点：稳定、诊断直接，可验证数据是否有效。

边界：这是监督训练，不是 RLCD。若只选此路线，第 4 章标题应改为 Training and Calibration。

C1 · 建议候选

参考 Laya：在 logits 周围采样中心化高斯扰动，用 log / spherical score、有序 RPS 评价概率分布，以组基线策略梯度更新，并保留 CE。

优点：不依赖完整 Agent 环境，可复用可验证标签。

风险：可能只增加 CE 的噪声和计算；评分截断与教师标签影响概率解释。

关键对照：CE-only、直接优化相同评分损失、CE+分布策略梯度；匹配数据、初始化及计算预算，报告多随机种子。

C2 · 环境要求高

在受控工具环境执行动作，以最终核验成功、错误动作与调用成本构造奖励；比较短轨迹策略优化与监督学习。

优点：可研究局部判断到整体任务的收益。

风险：奖励漏洞、归因和在线噪声；策略效用概率不是正确概率。

前提：D3 或同等回放环境；另设独立验证目标。只能称自己的 RLCD-inspired 配方，不能称复现官方配方。

C1 的可审核实验定义

z = stopgrad(logits) + ε；q = softmax(z)。以同题采样奖励相对组均值形成 advantage，用高斯采样密度的 log-probability 构成策略梯度，另加 CE。先检查梯度、奖励和评分方向，再扫探索尺度与 RL 权重。

这与“抽样一个动作并执行”不同。源码参考：Laya 的 laya/common.py 与 typed-decisions notebook；BrainHao 已拆解 G=4、完整 CE 权重等实现细节。我们还没有实施该算法。

建议用三层证据：通用决策保留 → 金融原子判断 → 固定 Agent 闭环。先完成可获取的小型证据评测，再扩展检索和工具任务。下列都是评测提案，不是已跑成绩。
Benchmark / 来源事实我们怎么打指标与访问门槛
FinanceBench
原始金融 QA；公开子集 150 题，非全部 10,231 题。		优先。原生整题 QA 与派生证据支持判断分开；固定答案生成器，仅更换决策层。保留原证据答案供评分，不能泄漏给策略。原生答案正确、引用有效；派生支持判断 NLL/Brier。数据公开，适配器待实现；150 题按公司聚类给区间，不包装成大样本。
FinAgentBench v4
26K 专家标注文档 / 片段检索例。早期摘要 3,429 与 v4 不同；区别于 Vals Finance Agent。		优先核验数据访问。原生文档与片段排序适配 Choice / Score，保留多相关等级；同时报告文档阶段和后续片段阶段。MRR / MAP / nDCG，候选集固定。论文已核验；实际数据包、划分及许可尚待落实，不预设 26K 全量可下载。
FailSafeQA
金融长上下文 QA 与扰动。		优先候选。测试无关、缺失证据与问题扰动时继续检索 / 拒答；用干净与扰动成对比较。原生 QA + 派生错误自动通过率 / 覆盖率。数据访问待核验；截短证据实验只能称派生测试。
Eikos finance suites
作者构造的金融组合与适配脚本。		重要外部基线与能力保留测试。锁定脚本 commit、原数据版本和题目 ID；相同输入测试原版 Eikos 与我们的模型。分别报金融子项及宏平均；不能作为唯一独立测试。FinQA-judge 等存在数据重叠风险；尚未运行 Eikos。
JevBench
v1.4.2 区分旧题与新增封存题，综合分不等于准确率。		通用类型化能力保留。公开题只作公开回归；独立封存成绩需要评测方实际访问。准确率、概率指标与成本分别报。不同硬件榜单延迟不可横比；不能声称本地获得封存成绩。
FinQA
财报 QA 与可执行推理程序。		训练改造与诊断为主。原生数值回答 / 程序执行，与我们生成的决定准确率分表。同财报去重隔离；人工审核反事实标签。已有派生数据，完整独立评测未完成。
FinToolBench
论文描述 760 个工具、295 个工具需求查询。		闭环首选候选。固定工具检索器、工具环境与回答器，只替换动作判断。先取候选工具再决策，不硬塞 760 选项。工具 Recall@k、条件决策准确率、所有查询上的任务成功及属性违规。论文写将开放代码；执行环境和访问尚未确认。
FinRetrieval
金融数字检索及不同工具配置评估。		补充闭环。固定结构化 API / 网页工具集合比较策略；工具变化另作消融。数值正确率、来源与调用成本。数据 / API 访问待核验；不要把更好的 API 收益算到决策头上。
Fin-RATE
跨文档的实体与时间推理。		第二阶段 OOD。检验跨实体 / 期间干扰；保留完整原生任务，不将合成局部判断称作原生成绩。原生 QA 分项 + 派生证据判断；长文代价较高，数据及 harness 待核验。
BigFinanceBench
928 个工作流任务、36,241 个 rubric 检查点。		第三阶段。衡量研究流程与产出质量，决策层只替换局部控制。评分 rubric 不作为策略输入。固定 judge 的原生 rubric、证据有效率、成本。完整任务 / 评分环境访问待核验，不直接当二分类集。
Vals Finance Agent v2
可参考运行框架；与 Finance Agent Benchmark v1 的任务规模分开。		第三阶段候选 harness。先核验平台与题目访问；小规模可运行子集应明确标为 pilot。整题成功率、工具数、p50/p95、总成本；不能预设完整评测集开放。

三张主结果表，避免刷一个总分

  1. 原子判断：按任务、公司、自然 / 合成错误分层的 accuracy、NLL、Brier、ECE、Score RPS；置换稳定性，按源文档 bootstrap 区间。
  2. 选择性执行：风险—覆盖曲线；阈值只在 policy 集选择；测试中报自动处理样本的错误率及区间、升级率。不能凭几个样本承诺 1% 风险。
  3. 固定 Agent：始终大模型、规则、AnyJev、发布版 Kev / Eikos、FinJev；固定检索器、工具、上下文预算及回答器，报成功、引用、调用数、GPU 小时、峰值显存、吞吐和实测每千决定成本。

模型侧延迟与工具侧延迟分开。比较冷启动 / 预热、batch size、硬件、token 长度；CPU 与 GPU 结果不混排。不同骨干的外部基线表与同骨干的因果消融表分开。

Case study 怎么选

提前定义四类：年份错配、单位错配、无关证据干扰、参数绑定 / 过早作答。每类展示成功、失败与低置信升级例，包含模型可见输入、全部候选、概率、实际执行与来源核验；不要只挑成功案例。

建议讨论起点：A2 + D1/D2 + C1，C0 为必要对照；先补独立评测与数据审核。这里不预选，最终由你拍板。
