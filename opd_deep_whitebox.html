🔬 白盒 OPD — 使用教师 Logits（17 篇深度解读）

本节 TLDR

白盒 OPD 是 OPD 的"主干道"：教师可以提供完整 logits，学生在自己的 rollout 上最小化与教师的 KL 散度。本节重点解读 6 个核心方向：损失函数设计（DistiLLM 系列）、理论统一（G-OPD）、信号自适应（Entropy-Aware / SCOPE）、效率优化（TIP / Fast OPD）、训练稳定性（Veto / REOPOLD）、跨 tokenizer（DSKDv2）。另有 11 篇简要速览。

DistiLLM: Streamlining Distillation via Skewed KL

ICML 2024 KAIST / Microsoft2024.02 Code
核心问题：FKL vs RKL 的"两难困境"

FKL（mean-seeking）和 RKL（mode-seeking）各有缺陷。FKL 强迫学生覆盖所有教师模式→容量不足时生成模糊输出。RKL 只学主模式→可能错过教师的多样性。DistiLLM 提出：能不能设计一个自适应在 FKL 和 RKL 之间切换的损失？

Skewed KL 损失函数
L_Skew-FKL(α) = Σ_t p_mix · log(p_mix / π_S)
其中 p_mix = α·π_T + (1-α)·π_S  （混合分布）

当 α→1：p_mix ≈ π_T → 退化为 FKL
当 α→0：p_mix ≈ π_S → 退化为 RKL

自适应策略：α 随训练进度动态调整
训练初期（学生差）→ 小 α（RKL 模式，先学主模式）
训练后期（学生好）→ 大 α（FKL 模式，再覆盖多模式）
重要性重加权的 On-Policy 过渡

DistiLLM 还提出用重要性采样在 off-policy 教师数据上近似 on-policy 梯度：

w(y) = π_S(y|x) / π_T(y|x)  （重要性权重）
L_IS = E_{y~π_T}[w(y) · L_Skew-FKL(y)]
这允许在较少的学生 rollout 下近似 on-policy 效果，节省采样成本

关键洞察

Skewed KL 的本质是"软插值"——不是在 FKL 和 RKL 之间二选一，而是让混合分布 p_mix 成为可调节的监督目标。这个思路后来被 DistiLLM-2 进一步发展为"对比损失"（在不同数据类型上用不同方向的 Skew-KL）。

DistiLLM-2: Contrastive On-Policy Distillation

ICML 2025 Oral KAIST / Microsoft2025.03 Code
从插值到对比：核心创新

DistiLLM-2 发现了一个更深的规律：学生在教师数据上需要 FKL（覆盖教师模式），在自己生成的数据上需要 RKL（自我纠正）——这两种需求应该用不同的损失函数分开处理，而不是混合。

非对称对比损失设计
教师数据 y_T ~ π_T 上：
L_T = Skew-FKL(α)  ← 覆盖教师分布（FKL 倾向）

学生数据 y_S ~ π_S 上：
L_S = Skew-RKL(β)  ← 自我纠正（RKL 倾向）

总损失（对比形式）：
L = L_T - λ · L_S  ← 最大化教师相似性，最小化学生自满

直觉：L_T 让学生"向教师靠拢"；-L_S 防止学生"停留在自己的分布"（自满 plateau）
为什么这是 ICML 2025 Oral？

对比损失框架从根本上解释了为什么之前的方法有天花板：单一损失函数无法同时满足"模仿教师"和"纠正自己"两个相互矛盾的目标。DistiLLM-2 将其显式分离，实验上在 10 个 benchmark 上全面超越 DistiLLM 和 GKD，平均提升 3-5pp。

实践建议

如果你在做 OPD 项目且性能是首要目标，DistiLLM-2 目前是学术态最优方法之一。代码开源，实现难度中等。需要同时维护两个数据流（教师数据 + 学生 rollout），batch 大小需要设置得足够大（建议 ≥32）以确保对比损失稳定。

G-OPD: Generalized On-Policy Distillation

RUC / Tencent AI Lab2026.02 Code
核心理论贡献：OPD = KL 约束的 RL

G-OPD 是白盒 OPD 方向最重要的理论论文。它证明了：

标准 OPD 的目标函数：
max_π E_{y~π}[r(x,y)] - β · D_KL(π ‖ π_T)
其中 r(x,y) = 0（无外部奖励），π_T = 教师
→ 退化为纯 KL 最小化：min D_KL(π_S ‖ π_T)

G-OPD 的扩展：允许 r(x,y) ≠ 0，并支持"超越教师"：
max_π E_{y~π}[γ · r(x,y)] - β · D_KL(π ‖ π_T)
当 γ > 1 时（奖励外推 / reward extrapolation），学生可以超越教师
奖励外推：OPD 突破教师上界

传统 OPD 的一个隐患：学生永远无法超越教师（因为目标就是逼近教师）。G-OPD 通过设置 γ > 1 的奖励缩放，让学生在教师偏好方向上"过度学习"，从而在某些维度超越教师。实验显示在数学推理（MATH）上：

γ学生准确率vs 教师
1.0（标准 OPD）72.3%-5.1pp
1.5（G-OPD）76.8%-0.6pp
2.0（G-OPD 激进）78.2%+0.8pp（超教师！）
统一框架价值

G-OPD 的统一框架将以下方法全部纳入同一公式：

  • GKD（γ=1, β 大）= 纯 KL 约束
  • GRPO + OPD（γ≥1, β 中）= RL-OPD 混合
  • 纯 RL（β→0）= 退化为无 KL 约束的策略梯度
理论意义

G-OPD 把 OPD 和 RL 的关系彻底说清楚了：OPD 是带强教师 KL 约束的 RL，RL 是不带 KL 约束的 OPD。这个统一视角对设计 OPD-RL 混合方法（下一节）有直接指导价值。

Entropy-Aware On-Policy Distillation

KAIST / IBM Research2026.03
核心思想：教师的不确定性决定用哪种 KL

这篇论文提出了一个极简但有效的规则：根据教师在当前 token 位置的熵动态选择 FKL 或 RKL。

H_T(t) = -Σ_v π_T(v|x,y_<t) · log π_T(v|x,y_<t)  （教师在位置 t 的熵）

规则（阈值 τ 为超参）：
if H_T(t) > τ → 用 FKL（教师不确定，需覆盖多模式）
if H_T(t) ≤ τ → 用 RKL（教师确定，集中学主模式）
直觉解释
  • 教师熵高（H_T 大）：这个位置教师也"不太确定"该选哪个词（多个合理选择），强行用 RKL 会让学生过度集中在一个词上，丢失多样性。用 FKL 让学生覆盖所有合理选择。
  • 教师熵低（H_T 小）：这个位置教师非常确定（例如数学步骤的必然推导），用 RKL 让学生精确学习这个确定性模式。

方法GSM8KMATHHumanEval
固定 FKL68.441.252.3
固定 RKL70.143.854.6
Entropy-Aware73.246.557.8
为什么这么简单的方法有效？

不同 token 位置的"重要性"差异很大：高熵位置（创意、多样性相关）和低熵位置（逻辑、计算相关）需要截然不同的学习策略。固定损失函数"一刀切"，必然在某类位置欠拟合。Entropy-Aware 用最少的代码（加一个阈值判断）实现了自适应——这是极佳的工程-效果比。

SCOPE: Signal-Calibrated On-Policy Distillation

USTC / Meituan / Fudan2026.04 Code
动机：正确和错误的 rollout 应该用不同损失

SCOPE 的出发点很直观：学生生成的 rollout 有些是对的（验证器判断正确），有些是错的。对错 rollout 用相同损失是浪费甚至有害的——正确的 rollout 说明学生已经学会了，不需要强制 KL；错误的 rollout 才是需要教师纠正的地方。

双路径设计
路径 1：错误 rollout（y 被验证器判为错）
L_wrong = -Σ_t w_T(t) · log π_S(y_t|·)
w_T(t) = π_T(y_t|·)  （教师概率加权，教师确定的位置权重大）

路径 2：正确 rollout（y 被验证器判为对）
L_correct = -Σ_t w_S(t) · log π_S(y_t|·)
w_S(t) = π_S(y_t|·)  （学生概率加权，学生确定的位置权重大）

总损失：L = L_wrong + λ · L_correct
验证器路由机制

SCOPE 引入轻量级验证器（可以是规则基础的，如数学验证器；也可以是另一个模型）对每条 rollout 打标，决定走哪条路径。验证器本身不需要 gradient，只需要 forward。

与 OPSD / OPCD 的关系

SCOPE 是白盒 OPD + 验证器的组合，与 OPSD 的"特权上下文"思路有异曲同工之处——都在利用"学生自身对错信息"来区分处理。区别在于 SCOPE 用验证器判断对错，OPSD 用已验证推理链作为特权输入给同一个模型。

TIP: Token Importance for On-Policy Distillation

Meta AI / LinkedIn2026.04
问题：大多数 token 的 KL 计算是浪费的

在一个 2048 token 的输出中，真正"值得学"的 token 远少于总数。低不确定性位置（学生已经高度自信的 token）的 KL 贡献接近零，但仍占据计算资源。TIP 提出：只对最"重要"的 token 计算 OPD 损失。

Token 重要性定义
Importance(t) = H_S(t) = -Σ_v π_S(v|·) · log π_S(v|·)  （学生自身的熵）

选择策略：只对 H_S(t) 排名前 50% 的 token 计算 KL 损失
→ 高熵位置 = 学生不确定 = 最需要教师指导
→ 低熵位置 = 学生已确定 = KL 贡献趋近零，跳过节省计算
效率收益
指标标准 OPDTIP (top-50%)
KL 计算量100%50%
内存占用（logit 存储）100%53%
训练速度1×1.38×
性能损失—<0.5pp（可忽略）
与 Entropy-Aware 的区别

Entropy-Aware 用教师熵决定用哪种 KL；TIP 用学生熵决定要不要计算 KL。两者可以叠加：先用 TIP 筛选 top-50% token，再在这些 token 上用 Entropy-Aware 选 FKL/RKL。实测叠加后效率提升 ~1.5× 且性能几乎不变。

DSKDv2: Cross-Tokenizer On-Policy Distillation

BJTU（北京交通大学）2025.04 Code
跨 tokenizer 蒸馏的根本难题

当教师和学生使用不同 tokenizer时（如 LLaMA tokenizer → Qwen tokenizer），同一段文本被切成不同数量、不同位置的 token，无法直接对齐 logit。传统方案要么要求同 tokenizer（限制了教师选择），要么用字符级对齐（计算昂贵）。

双空间对齐方案
Step 1：公共词汇表子集投影
→ 找到教师词汇表 V_T 和学生词汇表 V_S 的共同 token 子集 V_common
→ 在 V_common 上对齐教师和学生的概率分布（重归一化）

Step 2：双重 KL 对齐
L = D_KL(π_T|_{V_common} ‖ π_S|_{V_common}) + λ · L_MLE

V_common 通常覆盖 70-90% 的高频 token，KL 损失的有效性得到保障
支持 on-policy 和 off-policy 双模式

DSKDv2 同时支持在学生 rollout（on-policy）和教师数据（off-policy）上计算跨 tokenizer KL，可以无缝嵌入 GKD / DistiLLM 等任何现有框架。

局限性

V_common 方案只对共同 token 有效，对于专属 token（如教师有但学生没有的中文字符集，或代码特殊符号）无法对齐。对于这类情况，需要额外的映射层或退回到字符级对齐（计算成本更高）。

Fast OPD: Prefix-Truncated Distillation for Reasoning

工业界（机构未完全公开）2026.02
直觉：推理链的前缀大多是"模板"

在长链思维（Long CoT）场景下，学生生成 1024-4096 token 的推理链。其中前 30-50% 往往是固定的问题分析框架（"让我分析一下这道题..."），教师和学生在这部分差异极小，KL 贡献接近零。有效学习主要发生在推理链后半段（实际计算和验证步骤）。

前缀截断策略
标准 OPD：对全部 T 个 token 计算 KL
L = Σ_{t=1}^{T} KL(π_T(·|x,y_<t) ‖ π_S(·|x,y_<t))

Fast OPD：只对后 (1-ρ)·T 个 token 计算 KL
L = Σ_{t=⌈ρT⌉}^{T} KL(π_T(·|x,y_<t) ‖ π_S(·|x,y_<t))

最优 ρ 通常在 0.3-0.5（截断前 30-50%），实现 2×-47× 加速
加速比分析
推理链长度截断比例 ρFLOPs 节省性能损失
512 tokens0.330%<0.3pp
2048 tokens0.550%<0.5pp
4096 tokens0.770%（47× 等效加速）~1pp
适用场景

Fast OPD 对 Long CoT 模型（DeepSeek-R1、Qwen3-think 系列）收益最大。对短输出模型（<256 tokens）收益可忽略。实践中可以将 TIP（token 筛选）和 Fast OPD（前缀截断）叠加，双重节省。

Veto: Stable On-Policy Distillation via Adaptive Gradient Veto

ACL 2026 Findings Seoul National University2026.01
OPD 训练不稳定的根本原因

OPD 训练经常出现损失震荡、梯度爆炸、性能崩塌（catastrophic forgetting）。Veto 诊断根本原因：当教师和学生在 logit 空间的"方向"相反时，强行拉近 KL 会产生破坏性梯度。

两个核心机制

机制 1：Logit 空间几何桥接（Geometric Bridging）

不直接最小化 KL(π_S ‖ π_T)，而是引入插值目标 π_bridge：
π_bridge = (1-γ)·π_S + γ·π_T  （γ 从 0 渐增到 1）
→ 学生先向"中间桥接点"靠拢，再逐步向教师靠拢
→ 避免直接"跨越"引发的梯度方向突变

机制 2：自适应梯度否决（Adaptive Target Reformulation）

对每个 token t，计算当前梯度与历史平均梯度的余弦相似度 cos_sim：
if cos_sim < -0.5 → "否决"该 token 的梯度（置零）
else → 正常更新

直觉：梯度方向反转（cos_sim 很负）意味着这个更新会"撤销"之前学到的知识
什么时候需要 Veto？

如果你的 OPD 训练出现：(1) loss 剧烈震荡（波动 >20%）；(2) 验证集性能在训练中途崩塌；(3) 梯度 norm 经常出现尖峰——这时 Veto 的两个机制可以直接缓解。对于稳定的教师-学生对（同系列模型），Veto 的收益相对较小。

其余白盒 OPD 方法速览

8 篇
REOPOLD（KAIST / Microsoft, 2026.03）—— 将 OPD 视为带教师-学生 log-ratio 奖励的策略优化，混合奖励裁剪 + 基于熵的动态采样。比标准 OPD 更新更保守，适合教师-学生差距大的场景。
TSD-KD（Korea Univ., ICLR 2026）—— 混合"间接路径"（学生提议 + 教师重排）和"直接路径"（选择性 logit KD），在 token 级别自适应路由。
HPD: Hybrid Policy Distillation（2026.04）—— 将 KD 统一为 token 级重加权似然，覆盖 FKL + RKL。后端支持 LlamaFactory 和 verl，工程化程度高。
Speculative KD（UCSB / Google, ICLR 2025）—— 交织式提议-修正机制：学生提议 token，教师以 gated KL 方式修正。弥合师生差距的增量式方案。
PACED（LinkedIn, 2026.03）—— 在学生能力"边界"处构建课程，难度加权 w(p)=p(1-p)。自蒸馏风格（早期 checkpoint 作教师），渐进式难度递增。
AdaSwitch（RUC / Baidu, 2025.10）—— 根据 KL 散度阈值动态在"用教师数据训练"和"用学生 rollout 训练"之间切换。自动化的 off→on-policy 过渡。
Constrained OPD (CMDP)（Huawei Noah's Ark, 2025.09）—— 将 KL 约束建模为约束马尔可夫决策过程（CMDP），使用硬 KL 约束（Lagrangian 乘子法）而非软惩罚。当你需要严格控制师生 KL 上界时使用。
G-OPD 扩展—— G-OPD 的多教师扩展版本，支持对多个教师的 logit 加权聚合，适用于 DeepSeek-V4 风格的多专家蒸馏场景。
