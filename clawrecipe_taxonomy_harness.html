一条原则：错误分类和 harness 分类不要混

Agent 错误是诊断标签，Harness 分类是工程旋钮。前者看轨迹，后者看运行时插入点。

Agent 错误分类
描述 agent 在行为轨迹中的失败形态，例如规划不合理、动作落地错、记忆检索错、反思误判。它不应该直接写成 “需要加 preflight” 或 “需要加 memory”。
Harness 优化分类
描述运行时可调模块，例如 skill 注入、tool schema、control loop、memory store。它回答 “我能改哪个开关、阈值、触发器或 schema 来降低失败率”。

clawRecipe 原版：failure taxonomy 加 recipe mapping

原版贡献在于把失败归因和修复实验连接起来，但分类与 recipe 绑定过紧。

原 failure category定义重构判断
A Goal Grounding误解任务需求、约束或成功标准。容易吞掉 planning、reflection、action 问题。
B Action Instantiation知道要做什么，但工具、参数、路径或格式落地失败。可保留为 Action 类的一部分。
C State Representation跨步骤状态维护与调和失败。可保留为 Memory 类的一部分。
D Outcome Verification缺少检查、错误检测或恢复。更像 Reflection/Control 策略，不适合独立 harness 模块。
E Skill Activation有技能但不会激活、组合或排序。行为上应拆进 Planning、Action 或 Skill 脚手架。
F External Factorsruntime、evaluator、权限、依赖等外部因素。不是 agent 行为错误，归 System-level 或 harness/runtime。
原 recipe包含的机制新 harness 归属
T1 Controlplan-first、preflight、replan、failure reflection。Control Loop + Tool。
T2 Memorytask-local episodic memory buffer。Memory。
T2s Structured Memoryconstraints、derived facts、pending subgoals、artifact paths。Memory。
T3 Executor-Verifier执行者和验证者协作。Control Loop 策略，验证内容来自 Skill，检查动作依赖 Tool/Memory。
T4 Procedural Cardsprogram goal、prerequisites、steps、common pitfalls。Skill。
T5 ComboT2s + T1 + T3。Memory + Control Loop + Tool 的组合实验条件。

最终 Agent 行为错误分类：5 类

这张表只描述 agent 轨迹里的行为失败，不描述该加哪个 harness 组件。

M记忆模块 Memory

信息回忆或检索出错，扭曲后续推理。

过度简化总结虚假记忆检索失败遗忘约束

R反思模块 Reflection

进度评估、结果解读或因果归因失效，无法修正路线。

进度误判结果误读归因错误反思幻觉

P规划模块 Planning

策略逻辑不合理或不可执行，引发连锁失误。

无视约束低效规划子目标混乱停早/绕圈

A动作模块 Action

执行层操作出错，也常掩盖上游根源。

规划-动作脱节格式错误参数错误无效动作

S系统级 System-level

外部工具或基础设施引发故障，非智能体推理问题。

步骤上限耗尽工具执行报错LLM 接口限制环境故障

B边界原则

如果一个失败可以同时解释为上游策略错和下游动作错，先标可观察行为，再记录上游怀疑。

最终 Harness 优化分类：4 个可调模块

这张表对应真实 harness 中的可实现模块。Verification 不作为一级模块，而是由 Skill + Tool + Control Loop + Memory 共同实现。

模块 核心定义 典型细粒度优化 像调参一样怎么改
Skill 给 agent 注入任务流程、技能说明、检查清单、领域程序知识。 skills summary、procedure cards、tool inventory、common pitfalls、verification checklist、few-shot。 调 `card top_k`、`score_threshold`、注入时机、是否展示工具清单、是否在 unexpected result 后重新注入。
Tool 定义工具集合、调用契约、参数校验、执行环境。 tool registry、schema、preflight、path guard、sandbox、timeout、retry、error format。 调 schema 严格度、必填字段、路径约束、timeout、retryable/fatal errors、工具错误是否结构化。
Control Loop 控制每轮如何推进、何时计划、何时反思、何时停止、何时触发检查。 max turns、plan-first、replan trigger、reflection trigger、verify trigger、stop condition、tool-loop breaker。 调 `max_iterations`、`plan_first.trigger`、`replan.signal_threshold`、`max_replans`、reflection 连续失败阈值、停止规则。
Memory 保存、更新、检索任务过程中的状态、事实和产物。 session store、episodic memory、structured slots、constraints、pending subgoals、artifact paths、retrieval policy。 调 `max_items`、`retrieval_max`、retrieval policy、slot limits、`llm_update_interval`、artifact tracking、subgoal completion detection。
Verification 的正确放置：检查清单属于 Skill，触发时机属于 Control Loop，实际检查依赖 Tool，待检查对象来自 Memory。Benchmark judge 和 eval script 则是评测适配层，不是 agent harness 的一级模块。

特别边界：Reflection trigger 和 Verification 不是一回事

这也是为什么 Verification 没有作为一级 harness 维度保留。

Reflection trigger 属于 Control Loop
它在失败后或连续失败后触发，输入是失败日志、工具错误、重复动作和当前计划，输出是 root cause、correction 和 retry 决策。它回答的是 “下一步策略怎么改”。
Verification 是跨模块检查策略
checklist 属于 Skill，何时触发属于 Control Loop，实际检查依赖 Tool，检查对象来自 Memory。它回答的是 “产物是否满足任务要求”。

代码锚点：为什么这 4 个 harness 维度足够

来自 simple-agent-lab 和 OpenClawPro harness 的实现边界。

simple-agent-lab: runtime 主循环 `run()` 每轮构造 context view、调用模型、记录 trace、dispatch tools、判断停止。核心边界是 Skill/Tool/Control/Memory 的最小骨架。
OpenClawPro: Skill `agent/procedure/config.py` 定义 program support cards 和 skill activation prompt，包括 `program_goal`、`prerequisites`、`steps`、`common_pitfalls`。
OpenClawPro: Tool `nanobot.py::_register_tools()` 注册 filesystem/shell/web tools；`control/preflight.py` 负责参数、路径、URL、危险命令检查。
OpenClawPro: Control Loop `control/config.py` 暴露 `PlanFirstConfig`、`ReplanConfig`、`RetryConfig`、`ReflectionConfig`、`VerifyConfig`；主 loop 负责何时触发这些策略。
OpenClawPro: Memory `memory_structured/config.py` 将运行状态分成 constraints、derived facts、pending subgoals、artifact paths，说明 Memory 是状态表示和更新策略，不只是上下文文本。
保留为一级模块 跨模块策略 从 agent 错误中移出

最终一句话

Agent 错误：Memory、Reflection、Planning、Action、System-level。Harness 优化：Skill、Tool、Control Loop、Memory。

不要用 harness 模块去命名 agent 错误，也不要用 agent 错误去命名 harness recipe。
正确流程是：先标 agent 轨迹中的行为错误，再选择可能改善该错误的 harness knobs，最后用 CRR、NIR、成本和 trace 可复盘性评估调参效果。
