把开放规划留给 VLM，让 Jev 只在当前屏幕的受限动作集里执行，可以显著降低成本与执行延迟，同时维持接近的任务成功率。

01 · 问题

为什么重要

逐步调用 VLM 既昂贵又慢；完全让小模型规划又能力不足。论文采用 hierarchical split：planner 低频制定意图，Jev 高频选择具体动作。

02 · 方法

1. VLM planner 生成高层目标或子任务。
2. 从 UI 状态构造当前合法动作候选。
3. Jev executor 在候选集中决策；失败或不确定时再规划。

结果怎么读

Jev 更适合作为明确动作空间内的执行器，而不是承担视觉理解与长期规划；分层系统保留了大模型的高层能力。

04 · 研究判断

对 FinJev 的启发

FinJev 可复制 planner–executor 分工：LLM 负责研究计划，Jev 负责检索/计算/继续阅读/回答等高频路由。

05 · 边界

  • AndroidWorld 覆盖有限，真实设备噪声更复杂。
  • 受限候选依赖可靠的 UI 状态抽取。
  • 79% 仍低于逐步 VLM 的 84%。
