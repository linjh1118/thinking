Type-Safe ≠ Error-Free

Typed Decision Models Follow the Option Name
Yu Sun, Junhao Xu

📚 专题导航：返回 Jev 专题调研与论文海报索引

输出永远落在候选集合，只能证明类型安全。交换 option name 与 definition 的绑定后，模型仍可能追随 yes/no 的名称语义。

01 · 问题

为什么重要

若模型真正读取候选定义，交换名称—定义绑定后应保持 definition-level choice，只改变返回名称。传统 canonical accuracy 无法发现这种错误。

02 · 方法

1. 保持 question、state、名称和定义文本全部不变。
2. 只交换 name–definition binding，gold 跟随 definition。
3. 比较 definition-level flip、balanced accuracy、AUC 与重复调用噪声。

结果怎么读

0/1 与随机字符串接近中性控制，说明罪魁是名称的语义极性，而不只是重排。多分类循环错配会改变 79.7% 的决定。

04 · 研究判断

对 FinJev 的启发

Noul 的内部 ID 应保持中性，yes/no 只作为展示层；训练加入 binding randomization，评测把 name-invariance 设为硬门槛。

05 · 边界

  • 主要数据为英文。
  • 只覆盖少数 readout geometry。
  • 论文提出随机化修复，但没有训练并验证修复后模型。
