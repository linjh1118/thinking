RL 训练调参 101 — pg_loss 全解

从公式到曲线，从正常到异常，4 个 Tab 带你彻底理解 Policy Gradient Loss

📚 源文档： Train MOC
TL;DR pg_loss 不是"越低越好"的有符号损失函数。它衡量的是「当前策略相比旧策略，沿 advantage 方向更新了多少」。理解它的关键在于：它是一个有方向的信号，而非一个要最小化的标量。

1 PPO 的总目标函数

在 PPO 中，总 Loss 由三部分组成：

LPPO = - Lpg + c₁ · LVF + c₂ · LENT
其中 c₁ (value loss 系数) 通常 = 0.5，c₂ (entropy 系数) 通常 = 0.01

训练时 最大化 总目标（等价于最小化负值）。三个子 loss 各司其职：

Loss作用含义
Lpg策略梯度让策略朝高 advantage 动作方向更新
LVF价值函数让 value prediction 更准（MSE）
LENT熵正则防止策略坍缩到确定性行为

2 pg_loss 的核心公式（逐步拆解）

Step 2.1 — 重要性采样比率

rt(θ) = πθ(at | st) / πθold(at | st)
# 新策略在该状态选择该动作的概率 ÷ 旧策略的概率
# r = 1 表示新旧策略一致；r > 1 表示新策略更倾向该动作；r < 1 反之

Step 2.2 — Clip 机制（PPO 的核心创新）

clip(rt, 1-ε, 1+ε)
# ε 通常 = 0.2，即把 ratio 限制在 [0.8, 1.2] 区间
# 目的：防止单步更新过大，导致策略崩溃

Step 2.3 — 优势函数 Advantage

Ât = Q(st,at) - V(st)
# 该动作比"平均水平"好多少
# Â > 0：这个动作比期望好，应该提高概率
# Â < 0：这个动作比期望差，应该降低概率
# 实际中用 GAE(λ) 来估计，引入 bias-variance tradeoff

Step 2.4 — PPO-Clip 目标（最终公式）

LCLIP = 𝔼t [ min( rt(θ) · Ât, clip(rt(θ), 1-ε, 1+ε) · Ât ) ]

# 取 min = 在 "无clip的原始目标" 和 "clip后的目标" 中选更保守的那个
# 训练代码中 pg_loss = -LCLIP（取负号因为优化器是 minimize）
关键直觉：pg_loss 的值 = -1 × LCLIP。训练越好 → LCLIP 越大 → pg_loss 越小（越负）。但 pg_loss 不是单调下降的！因为每轮 rollout 产生新的 advantage，它的正负和大小都在变化。

pg_loss = +2.00 # 正值 → 策略在错误方向上偏移，需要被纠正

4 clipfrac 是什么？怎么解读？

clipfrac = 被 clip 的 token / 总 token 数。它告诉你有多少比例的更新被"截断"了。

clipfrac 范围含义应对
0.05 ~ 0.15健康，大部分更新在合理区间正常训练
0.2 ~ 0.3偏高，策略变化较大考虑降低学习率
> 0.3过高，大量更新被截断降低学习率或增大 batch size
< 0.01过低，更新可能太保守考虑增大学习率

5 QA：被 clip 的样本是不是就"没用了"？

一个常见的困惑：如果 r(θ) 被 clip 住了，梯度回不到策略网络，那这个样本是不是白白浪费了？

先搞清楚：clip 不是在所有情况下都阻断梯度

关键发现：4 种情况中只有 2 种梯度被阻断。clip 的逻辑是：当策略已经沿 advantage 方向走得够远了（r 偏离 1 超过 ε），就踩刹车。但如果策略在"反向走"（好动作概率反而降了 / 差动作概率反而涨了），clip 不干预，梯度正常纠正。

即使策略梯度被 clip 阻断了，样本仍然有两个学习通道

LVF（Value Function）
Value network 的 MSE loss 不受 clip 影响。被 clip 的样本仍然参与 V(s) 的更新。

→ 改善 future advantage 估计的准确性
→ 间接帮助策略在后续 step 做更好的决策
LENT（Entropy Bonus）
Entropy 正则项 不依赖 r(θ)，始终提供梯度。

→ 防止策略坍缩到确定性行为
→ 即使策略梯度被 clip，entropy 仍在"拉"着策略保持探索

用刚才的数值例子验证

# 回顾：π_old=0.3, π_new=0.4, r=1.33, Â=+2.0, ε=0.2

# r=1.33 > 1+ε=1.2，且 Â>0 → 梯度被阻断的情况
# 但这个样本仍然参与了：

1. Value update：V(st) 的目标值（return）被用来算 MSE loss
# 如果 value 预测不准，value loss 会大 → value network 会学到更好的估计

2. Entropy update：π(·|st) 的熵被计算并加入 entropy bonus
# 即使策略梯度被 clip，entropy 梯度仍然流过
总结：被 clip 的样本不是"没用了"。策略梯度信号被保护性截断了（只截了一半方向），但 value function 和 entropy 仍在学习。这正是 PPO 相比 TRPO 的巧妙之处——用简单的 clip 替代昂贵的 KL 约束优化，同时在"安全区间外"保留了其他学习通道。
TL;DR 正常训练的 pg_loss 不会单调下降。它初期波动大（随机策略 + 噪声 advantage），中期逐步收敛（策略变好），后期在小区间波动（稳定训练）。关键看它和 reward 是否协同变化。

1 训练前：检查清单

  • ☐
    Reward 设计：reward 信号是否清晰？range 是否合理？有没有明显的 hacking 途径？
  • ☐
    Baseline（Value Network）：能否准确预测 return？如果 value loss 不降，advantage 估计就不准。
  • ☐
    超参初始值：LR=1e-6 ~ 3e-6，KL coef=0.02~0.05，clip epsilon=0.2，entropy coef=0.01
  • ☐
    Batch Size：rollout batch 至少 512+，mini-batch 64~128。太小 → 噪声大；太大 → 内存不够。

2 训练中：看什么 + 怎么判

指标组合✅ 健康信号❌ 危险信号
pg_loss + reward pg_loss 下降趋势 ≈ reward 上升趋势 pg_loss 下降但 reward 不涨 → 学到坏策略
pg_loss + KL 两者同步平稳下降 KL 突然 spike → 策略一步跳太远
pg_loss + clipfrac clipfrac 在 5~15% clipfrac > 30% → 大量更新被截 → LR 太大
entropy 缓慢下降到 ~0.5-0.8 快速降到 <0.1 → 策略坍缩到少数动作
value_loss 稳步下降 → value 预测越来越准 不降或暴涨 → value network 没学到东西

4 常见调参场景

场景 A：「pg_loss 震荡 + KL 爆了」

# 诊断：更新太激进
操作：LR × 0.5 → 观察 50 steps
# 如果 KL 仍高 → KL coef × 2.0
# 如果 clipfrac > 30% → LR 再减半

场景 B：「pg_loss 平了 + reward 不涨」

# 诊断：学习信号太弱或 KL 限制太死
操作：先查 reward 是否有效 → 如果 reward 有梯度但 pg_loss 不动
→ KL coef × 0.5 → 释放更新空间
→ 或 LR × 2.0 → 加大步长
# 如果 entropy 已经很低 → 增大 entropy coef

场景 C：「entropy 快速降到 0」

# 诊断：策略坍缩到少数确定性行为
操作：entropy coef × 3.0
# 如果还不行 → 从 checkpoint 重启 + 更大 entropy coef
# 检查 reward 是否只奖励少数 action

场景 D：「pg_loss 巨幅负 + reward 暴涨」

# ⚠️ 这看起来像"好事"但很可能是 reward hacking
操作：
1. 立即 inspect 生成样本 → 模型是否在刷 reward？
2. 检查 reward 函数是否有漏洞（格式 trick、shortcut）
3. 加 rule-based penalty 或多维度 reward
