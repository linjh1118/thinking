一句话解释

Finance Agent v2 衡量模型能不能完成初级金融分析师的真实工作：从 SEC filings、press releases、市场价格、财务报表脚注里找到正确数字，套用正确金融口径，完成多步计算，并给出可审计答案。

为什么难

难点不是单纯“会不会算数”，而是找到正确文件、正确 period、正确 entity、正确 GAAP/non-GAAP 口径，并避免单位、日期、季度 guidance、lease footnote、continuing operations 等细节错误。

当前指标怎么读

现在的 6/27 public smoke 不是 leaderboard 分数，而是 harness 健康度信号：我们把最容易出错的财务口径变成了工具和 checklist，并在对应公开题上拿到 100% rubric 覆盖。真正指标仍然是官方 hidden Test accuracy。

不能提前宣称 SOTA：公开题样例通过只说明路径有效，不代表 450 道 hidden Test 上超过 57.86%。页面里的“当前指标”用于决策下一步，不用于对外排名。

执行计划

阶段目标下一步动作
Phase 1把 public split 中未覆盖题型跑出失败样本优先 q007/q008 Market、q013 Precedents、q022 Disclosure、q025/q026/q027 Modeling。
Phase 2把失败转成 harness 能力价格数据、交易公告材料、PPA/impairment 表格、DCF/LBO 输入抽取逐项工具化。
Phase 3跑 balanced public 和 private validation有官方 key 后用固定 seed / temperature=0 做整批评估并生成 error taxonomy。
Phase 4冲官方 SOTA在 validation 明显超过 57.86% 后再提交 hidden Test。

当前卡点

卡点影响解除方式
无 VALS_API_KEY不能跑官方 validation/test，无法证明 SOTA。配置 key 后跑完整 Vals evaluation。
价格数据 key 缺失Market/Precedents 对历史股价依赖强，Yahoo fallback 不够稳。配置 Tiingo 或 pricing provider key；同时保留 raw close 规则。
未覆盖题型仍多Financial Modeling、Precedents、Disclosure 可能藏着最大丢分。按题型逐个 smoke，失败就补工具和 tests。
模型偶发长回合 / hang整批跑分成本和稳定性受影响。继续减少无效 web_search、增加 task-specific checklist 和 deterministic tools。
aiohttp session warning当前不影响答案，但说明工具生命周期还有清理债务。统一 client/session 管理或显式 close。

下一步怎么逼近 SOTA

把 public smoke 的成功路径扩展成 hidden Test 上稳健的 harness。

1

补齐未跑 public 类别

优先跑 Market、Precedents、Disclosure、Financial Modeling 中复杂题，找到检索/价格/建模缺口。

2

失败类型工具化

把每次失败变成工具契约或 checklist，而不是靠 prompt 祈祷模型记住。

3

官方验证

拿到 VALS_API_KEY 后跑 private validation / hidden Test。只有官方 hidden Test 超过 57.86%，才可以严谨宣称达到 SOTA。
