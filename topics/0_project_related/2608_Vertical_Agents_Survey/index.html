RESEARCH LANDSCAPE

The Vertical-Agent Landscape at a Glance

Four research branches share the same six-dimensional domain loop. Benchmarks measure systems, data pipelines produce executable tasks, harnesses implement and record the loop, and open problems determine whether evidence transfers to deployment.

Figure 1 Original research mind map. T/K/A/E/V/G denote tasks, knowledge, actions, environment, verifiers, and governance; the arrows emphasize that all six must form an executable loop.

THE CENTRAL CLAIM

Verticality is a closed-loop property,
not a topic label.

A strong vertical agent changes domain state, is judged by domain-relevant standards, and is constrained by domain policy. Prompts, retrieval, or specialized vocabulary alone demonstrate domain augmentation, not domain execution.

01

Benchmarks measure systems

The same model behaves differently under different tool representations, retry policies, runtimes, and verifiers. Fair comparison must lock the model, harness, task version, and budget.

Model × Harness × Task × Budget
02

Data should produce verifiable tasks

High-value vertical data is not a larger prompt collection. It is an executable task package with initial state, tools, constraints, terminal verifiers, and success, failure, and recovery rollouts.

Task spec ⊕ Rollout set
03

The harness is a research variable

Reset semantics, permission boundaries, observations, verifiers, and logs determine what the agent can see and do, and therefore what a score actually means.

Runtime · Verifier · Governance

LIMITS & OPEN QUESTIONS

From Public V3 to Governed V4

The next bottleneck is not more specialized prompting, but a measurement regime that can be maintained over time, separate causal contributions, and expose tail risk.

01

Construct validity

Knowledge, interface control, state, and governance collapse into one success rate. We need six-dimensional profiles and orthogonal interventions.

02

Benchmark half-life

Public-task contamination, dependency decay, and live-service drift require frozen cores, refreshed shadow sets, and sealed canaries.

03

Verifier reliability

A correct terminal state can still hide an invalid process. We need mutation suites, equivalent solutions, and human false-positive/false-negative audits.

04

Model–harness attribution

Retries, context policy, tool representation, and infrastructure jointly change scores. We need dual-track protocols and component ablations.

05

Failure, recovery, and tail risk

Pass@1 hides stochastic failures and catastrophic side effects. Report passk, worst-seed results, recovery rate, and risk–coverage curves.

06

Governance and accountability

Correct outcomes do not prove authorization, disclosure, escalation, or audit compliance. We need executable policies, approval, revocation, and independent replay.

METHOD & BOUNDARY

A maintainable scoping review,
not a longest-list contest.

We prioritize papers, official data cards, repositories, and benchmark project pages. Provider system cards identify evaluations in actual use; their scores are not compared across different harnesses and budgets.

Included resources contribute domain knowledge, policy, tools, delivery standards, or reusable data pipelines, runtimes, control loops, verifiers, and observability. Static QA and general function calling remain boundary evidence or horizontal substrate rather than industry-vertical V3 evidence.
