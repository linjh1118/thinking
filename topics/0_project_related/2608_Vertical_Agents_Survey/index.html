01 Landscape

A vertical is defined by the loop it closes.

Topic vocabulary is not enough. Vertical evidence appears only when a system can act through a domain interface, change state, satisfy a domain verifier, and remain inside governance boundaries.

01 · INDUSTRY

Industry vertical

Professional policy, regulated state, domain tools, and delivery standards close the loop.

02 · FUNCTION

Functional vertical

A role such as research, analytics, or operations spans industries but still has executable standards.

03 · INTERFACE

Interface domain

Browser, desktop, mobile, and terminal control establish action competence—not industry validity.

04 · BOUNDARY

Substrate or evidence gate

Tool calling and static QA are necessary capabilities, but they do not establish closed-loop verticality.

Knowledge ≠ execution
Expert answers do not prove stateful work.

Interface ≠ industry
Computer use does not encode professional policy.

Tools ≠ trust
A contract does not grant permission or accountability.

Success ≠ safety
Terminal correctness can hide invalid processes.

02 Vertical Benchmarks

A benchmark measures a coupled system.

Scores belong to a model, harness, task version, budget, and intervention policy. The evidence ladder records how much of the domain loop is actually observable.

V0

Static capability

QA · examinations

V1

Grounded outcome

rubrics · deliverables

V2

Tool grounding

APIs · interfaces

V3

Stateful workflow

reset · transitions

V4

Governed execution

approval · rollback

Measurement boundary

Freeze the system, not only the question.

  • Task and initial-state version
  • Tool schema and environment image
  • Retry, budget, and assistance policy
  • Verifier and infrastructure revision

Evidence profile

Report dimensions before a single score.

  • Knowledge and policy fidelity
  • Action and state-transition validity
  • Verifier reliability and alternatives
  • Governance, disclosure, and escalation
!

Attribution warning

Harness gains can masquerade as model gains.

Context policy, tool representation, retries, and infrastructure can all change the measured capability.

I

Environment first

Generate tasks backward from a controllable world, rather than inventing prompts that cannot be executed.

II

Failures are data

Localize the first failure, preserve the minimal repair, and retain same-state alternatives for causal learning.

III

Refresh with lineage

Version generators, environments, verifiers, and splits so evaluation does not disappear into the training flywheel.

04 Vertical Harnesses

Infrastructure is an experimental variable.

A harness implements the domain specification in evaluation, training, or deployment mode. Its six layers determine what the agent can observe, change, prove, and audit.

ImplementationHd(m) = (Cd, Wd, Ld, Fd, Od, Ud)m ∈ {evaluation, training, deployment}
C

Contract

Tools, schemas, identity, permissions, approvals, and effect declarations.

W

World

Resettable runtime, services, state snapshots, isolation, and reproducibility.

L

Control loop

Observation, memory, planning, retries, stopping rules, and budgets.

F

Feedback

Scoring, process checks, terminal verifiers, arbitration, and decisions.

O

Observability

Messages, actions, states, costs, errors, traces, replay, and re-scoring.

U

Runtime governance

Orchestration, policy enforcement, escalation, revocation, and rollback.

05 Limits & Open Problems

Public V3 is not governed V4.

The next bottleneck is a maintainable measurement regime that separates model and harness effects, survives environmental drift, and exposes tail risk.

01

Construct validity

Separate knowledge, interface control, state management, verification, and policy adherence.

02

Benchmark half-life

Use frozen cores, refreshed shadow sets, and sealed canaries under dependency and service drift.

03

Verifier reliability

Test valid alternatives, mutations, and human false-positive and false-negative rates.

04

Model–harness attribution

Run component ablations and dual-track protocols before assigning credit to model weights.

05

Recovery & tail risk

Report repeated-run reliability, worst seeds, recovery, and catastrophic side effects.

06

Governance evidence

Make authorization, disclosure, escalation, revocation, and independent replay executable.
