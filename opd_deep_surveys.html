GKD: On-Policy Distillation of Language Models

ICLR 2024 Google DeepMind2023.06 TRL GKDTrainer
背景动机

传统知识蒸馏（SFT-on-Teacher）在教师分布上训练学生，但推理时学生在自己的分布上生成文本——训练分布与推理分布不匹配（exposure bias / distribution mismatch），导致错误累积。GKD 的核心洞察：让学生在自己犯错的分布上获得教师纠正，效果远优于纯教师数据训练。

方法核心

GKD 引入广义 JSD（Generalized Jensen-Shannon Divergence），通过参数 λ 在前向 KL（FKL）和反向 KL（RKL）之间插值：

L_GKD = λ · D_FKL(p_T ‖ p_S) + (1-λ) · D_RKL(p_S ‖ p_T)
其中数据来自混合分布：以概率 β 从学生采样，以 (1-β) 从教师采样
关键参数：λ=0（纯 RKL，mode-seeking）; λ=1（纯 FKL，mean-seeking）; λ=0.5（JSD）

训练流程：

  1. 从混合分布采样 x（prompt），用学生生成 y ~ π_S(·|x)（on-policy 部分）
  2. 教师计算 log p_T(y_t | x, y_{<t})（逐 token 概率）
  3. 在学生生成的 y 上计算 GKD 损失并反向传播
为什么 RKL 比 FKL 更适合小模型？

FKL（前向 KL）是 mean-seeking：最小化 FKL 时，学生必须覆盖教师分布的所有模式，小模型容量不足时会生成模糊的"平均"输出。RKL（反向 KL）是 mode-seeking：学生集中学习教师的主要模式，忽略次要模式，结果更清晰具体，适合容量受限的小模型。

核心贡献
  • 命名了 On-Policy Distillation——首次把"在学生分布上做 KD"作为独立范式提出
  • 统一的 GKD 框架覆盖所有 KL 散度变体（λ 插值）
  • TRL 中的 GKDTrainer 直接实现此方法，工程可复现
关键洞察

GKD 的 β 参数（混合比例）等价于"在策略程度"：β=0 就是纯 SFT-on-Teacher（off-policy），β=1 就是纯 OPD。实践中 β=0.5 往往表现最佳，因为纯 on-policy 时初期学生太弱，教师损失信号噪声很大。

MiniLLM: Knowledge Distillation of Large Language Models

ICLR 2024 Microsoft Research / Tsinghua2023.06（比 GKD 早 5 天） Code
背景与动机

MiniLLM 与 GKD 同月独立发现了 OPD 的核心思想，但从策略梯度优化角度出发，而非 KL 插值。关键问题：为什么前向 KL（SFT-on-Teacher）会产生"幻觉"？因为 FKL 要求学生在所有教师有概率的地方都有概率——当教师在某位置有高概率而学生没有时，梯度会强迫学生胡乱填充，产生 unlikely 的 token 组合。

核心方法

MiniLLM 最小化Reverse KL + Policy Gradient：

L_MiniLLM = D_RKL(π_S ‖ π_T) = E_{y~π_S}[log π_S(y|x) - log π_T(y|x)]
梯度展开（策略梯度形式）：
∇L = E_{y~π_S}[(log π_S(y|x) - log π_T(y|x)) · ∇log π_S(y|x)] + 1
即：奖励 r(x,y) = log π_T(y|x) - log π_S(y|x)（教师比学生更喜欢的程度）
与 GKD 的关键对比
维度GKDMiniLLM
优化目标广义 JSD（可配置）纯 Reverse KL
优化视角散度最小化（token 级）策略梯度（序列级）
方差控制无专门处理多步 REINFORCE 基线
采样策略混合 β 参数纯学生 rollout
工程复杂度低（类 SFT）中（需 PG 稳定训练）
为什么 Reverse KL = mode-seeking？

RKL 的梯度项 (log π_S - log π_T) 是负数时（学生比教师概率低），梯度会推动学生提高这个 token 的概率。但这只对学生已有一定概率的 token 有效（否则 π_S 接近 0 导致梯度消失）。因此 RKL 自然形成了"集中学习教师主模式"的行为。

历史地位

MiniLLM 比 GKD 早 5 天挂出，但 GKD 有更好的框架推广（TRL 集成）。两篇论文的同期独立发现证明了"在学生分布上做 KD"是当时的时代需求，而非偶然。2023.06 是 OPD 正式诞生的时间节点。

Rethinking On-Policy Distillation: Phenomenology, Mechanism & Recipe

THUNLP Tsinghua University2026.04
论文定位

这是目前最系统的"OPD 为什么有效，何时失败"理论分析。论文从现象学、机制、配方三层递进展开，给出了 OPD 实践者最需要的答案。

两个成功条件（核心理论）

论文发现 OPD 成功需要同时满足：

  1. 思维模式兼容（Thinking Pattern Compatibility）：教师和学生的推理风格要兼容。例如：将 DeepSeek-R1（中英混合推理）蒸馏到纯英文学生时，风格不匹配导致 OPD 无效，需先做 off-policy 冷启动对齐风格。
  2. 教师具备学生缺乏的新能力（Teacher Superiority）：如果教师在某类题目上与学生性能相当，OPD 收益极小；教师必须在目标任务上有实质领先。
实用 Recipe
Step 1：Off-policy 冷启动（2-3 epoch SFT on teacher data）
→ 让学生思维模式向教师靠拢，确保条件 1 满足

Step 2：教师对齐的 prompt 筛选
→ 过滤掉教师无优势的 prompt（避免无效梯度）

Step 3：渐进 top-K Reverse KL OPD
→ 先用大 K（覆盖更多教师知识），随训练收敛缩小 K
→ 公式：L = -E_{y~π_S}[Σ_t min(π_T(y_t|·), topK) · log π_S(y_t|·)]
失败模式图谱
失败模式症状原因修复
风格不匹配学生困惑，损失震荡思维模式不兼容off-policy 冷启动
教师无优势收益接近零教师 ≈ 学生能力换更强教师 / 换任务
梯度主导错误易题学好，难题无收益未筛选 prompt教师-胜率加权采样
最重要的实践启示

OPD 不是银弹——如果直接在 Raw 学生上做 OPD 而不冷启动，效果经常不如纯 SFT。这篇论文解释了为什么：教师的"语言"学生还听不懂。冷启动是 OPD 成功的前提条件，而不是可选步骤。

Revisiting OPD: Failure Modes & Simple Fixes

CASIA（中国科学院自动化所）2026.03
论文价值

这是一篇经验性排错论文，不提新算法，专门诊断 OPD 实现时最常踩的三个坑。读完能省一周调试时间。

三大失败模式与修复

失败模式 1：不平衡的单 token 信号

问题：RKL 在每个 token 位置独立计算，高概率 token 主导梯度（高概率位置的 KL 贡献大），低概率位置的信号被淹没。

修复：截断 Reverse KL（Truncated RKL）
L_trunc = -Σ_t [min(1, π_T(y_t)/π_S(y_t))] · log π_S(y_t)
类似 PPO 的 clip 机制，防止单 token 梯度爆炸

失败模式 2：不可靠的前缀引导（Prefix Guidance Failure）

问题：OPD 采样时用教师的前缀引导学生（教师生成前 k token，学生续写），但教师前缀在学生分布上概率极低，导致后续采样完全偏离。

修复：纯学生 rollout（不使用前缀引导），用 top-p 核采样（p=0.95） 代替贪心采样，增加多样性

失败模式 3：Tokenizer 不匹配

问题：教师和学生用不同 tokenizer 时，同一段文本的 token 序列不同，无法直接对齐 logit。

修复：使用 特殊 token 掩码（Special Token Masking）
对 BOS/EOS/PAD 位置的 KL 贡献清零；或使用子词对齐（见 DSKDv2）
踩坑警告

失败模式 3 在跨架构蒸馏（如 LLaMA→Qwen 或 DeepSeek→Mistral）时必然出现。如果你的教师和学生是同一系列（如 Qwen3-72B → Qwen3-7B），tokenizer 相同，可以忽略这个问题。

Lightning OPD: Efficient Post-Training with Offline OPD

Wu, Han, Cai2026.04
解决的工程痛点

标准 OPD 要求训练时同时运行教师和学生（教师在线提供 logit），导致：(1) GPU 内存翻倍（要同时载入两个模型）；(2) 教师推理成为训练瓶颈（每个 batch 都需要教师 forward）；(3) 分布式训练时教师和学生需要在不同节点通信。

核心方案：预计算教师 log-probs
离线阶段（一次性）：
1. 用当前学生（或初始化模型）生成 rollout 数据集 D = {(x_i, y_i)}
2. 用教师计算所有 (x_i, y_i) 的 log p_T(y_t|x,y_<t)，存储到磁盘

在线训练阶段：
3. 读取预计算的教师 log-probs，直接计算 KL 损失
4. 无需运行教师模型 → 内存减半，训练加速 2-3×
教师一致性约束（核心理论贡献）

论文证明了 Lightning OPD 要求 SFT 冷启动和 OPD 使用同一教师，否则梯度有偏：

如果 SFT 用教师 T1，OPD 用教师 T2（T1 ≠ T2）：
→ 学生先向 T1 靠拢，OPD 再向 T2 靠拢
→ 两个梯度方向冲突，训练不稳定
→ 实验验证：混合教师导致性能下降 1.5-3pp
离线 OPD 的关键局限

预计算 log-probs 在学生初始分布上，随着训练推进，学生分布偏移，预计算数据逐渐过时（distribution drift）。实践中需要每隔 N 步重新生成 rollout 并重新计算教师 log-probs（周期性刷新），论文推荐 N=500-2000 steps。

工程价值

Lightning OPD 是资源受限场景（单节点、内存不足以同时运行教师和学生）下的首选方案。如果你有两台 A100 节点，一台运行教师服务，一台训练学生，则不需要 Lightning OPD，直接用标准在线 OPD 效果更好（分布 drift 更小）。

Thinking Machines Lab Blog: On-Policy Distillation

Thinking Machines Lab (Kevin Lu et al.)2025.10 tinker-cookbook（<200 行实现）
为什么强烈推荐这篇博客

这是最适合初学者的 OPD 入口。一句话解释："将 RL 训练器中的 KL 参考模型（ref model）换成更强的教师模型"即可实现 OPD，仅需一行代码修改。

GRPO 到 OPD 的一行代码转换
# 标准 GRPO（ref model = 学生的初始化版本）
kl_penalty = log π_student(y) - log π_student_init(y)

# OPD（只改这一行！ref model → 教师模型）
kl_penalty = log π_student(y) - log π_TEACHER(y)

# 效果：student 越像 teacher，惩罚越小
# 梯度方向：学生被推向教师的分布

超参数值说明

最重要的一行话

OPD = RL，但把"奖励信号"从"稀疏的标量奖励"换成"教师 logits 提供的密集概率监督"。这就是 OPD 比 RL 更稳定、更高效的根本原因。
