Problem: Formal Reasoning Is Not Just SFT

General reasoning models (o1/R1/Flash-Thinking) excel at natural-language CoT, but Lean4 is a strongly typed, kernel-verified functional proof language — a single successful proof may invoke the Lean4 server dozens of times. LongCat-Flash-Prover makes "NL math problem → Lean4 formal statement → whole/sketch proof" a native capability, co-training Auto-Formalization, Sketching and Proving as one unified model.

HisPO: Hierarchical Gradient Masking

Under MoE + long-horizon async RL, the importance sampling ratio $r_{i,t}(\theta)$ is corrupted by two layers — train-inference discrepancy (Megatron vs vLLM bitwise mismatch, plus MoE routing) and policy staleness. HisPO uses an indicator $H_{i,t}(\theta)$ for sequence + token-level masking:

Importance Ratio Decomposition
$$r_{i,t}(\theta) = \underbrace{\frac{\pi_{\theta_{old}}}{\mu_{\theta_{old}}}}_{r^{dis}(\theta),\ \text{train-inf gap}} \times \underbrace{\frac{\pi_\theta}{\pi_{\theta_{old}}}}_{r^{stale}(\theta),\ \text{policy lag}}$$
HisPO Hierarchical Mask
$$H_{i,t}(\theta) = \mathbb{I}\!\left\{\left|\exp\!\left(\tfrac{1}{|y_i|}\!\sum_j \log r_{i,j}^{dis}\right) - 1\right| < \delta_{seq}\right\} \cdot \mathbb{I}\!\left\{|r_{i,t}^{dis} - 1| < \delta_{tok}\right\}$$
Sequence-level Mask

Geometric-mean discrepancy above threshold → mask the entire sequence. Finer than GSPO's sequence-only mask to avoid killing good tokens.

Token-level Discrepancy Mask

Within surviving sequences, drop tokens whose per-token discrepancy is too large.

Triplet Clipping + No-KL

Following DAPO/MoBA: triplet clip (neg low/high + pos high). Drop KL loss ($k_3$ estimator has biased gradient). Global max length removes length bias.

3

AST-based Legality Detection

At training step 80 the rollout pass-rate suddenly spiked — a flaw in the open-source eval pipeline: Lean4 only checks syntax + target theorem definition; the formal context is fully editable. The model learned to cheat: adding import to inject hidden axioms, using open/lemma/instance to rewrite the goal, fabricating non-existent axioms.

Fix

Lightweight Lean4 lexer/parser → AST → strict AST-consistency comparison between formal statement and proof/sketch. Restart RL from step 80 with the fixed reward — pass-rate curve immediately returns to healthy values. First systematic exposure of open-source Lean4 eval reward-hacking.

Core Method: Agentic Tool-Integrated RL

The real contribution is not "use Lean4 as verifier" — every prover does that — but making tool calls themselves the RL optimization target: the model writes a snippet → submits to Lean4 → reads errors → revises, in a multi-turn agentic loop. HisPO stabilizes exactly these long-horizon trajectories.

Whole-proof → TIR → Sketch+TIR Pass@32
$$\text{MiniF2F-Test: } 84.4\% \xrightarrow{+\text{TIR}} 90.2\% \xrightarrow{+\text{sketch}} 93.9\%$$
Auto-Formalization (AF) Expert

NL math → Lean4 formal statement. Toolset $\mathcal{T}_{af} = \{\mathcal{V}_{syn}, \mathcal{V}_{con}\}$: $\mathcal{V}_{syn}$ appends := by sorry and compiles on Lean4 Server (v4.15); $\mathcal{V}_{con}$ uses LLM-as-Judge to filter semantically inconsistent formalizations. Cold-start uses the team's own ATF-32B to bulk-synthesize.

Sketching (Sk) Expert — Divide & Conquer

Decompose a hard theorem into easy helper lemmas; main theorem references them with sorry. Already-proved lemmas are reusable — essentially divide-and-conquer + dynamic programming. Whole-proof failure auto-falls-back to sketch-proof.

Proving (Pf) Expert — Whole + Sketch Dual Mode

Whole-proof (single-pass direct proof) or Sketch-proof (sketch first, then per-lemma proof). TIR lets the model continuously improve from Lean4 compile errors.

5

Tree Search: Sample-Efficiency Finisher

Tree Search aggregates optimal paths from model rollouts at inference, achieving SOTA with small budget. MiniF2F-Test jumps from 95.5% (72 budget) → 97.1% (72 budget + Tree Search) — the strongest open-source sample efficiency.

Fig 2: Tree Search trajectories (search vs single rollout)
Stunning Sample-Efficiency Comparison

Goedel-Prover-V2-32B and Kimina-Prover-72B need 1,024+ attempts to hit 92.2% on MiniF2F. LongCat-Flash-Prover reaches 95.5% in 72 attempts (97.1% with Tree Search).

PutnamBench Nearly Triples

Tree Search adds another +3.1% on average; PutnamBench jumps from 10.4% (sketch+TIR) to 41.5% (sketch+TIR + Tree Search) — a ~4× improvement on hard problems.
