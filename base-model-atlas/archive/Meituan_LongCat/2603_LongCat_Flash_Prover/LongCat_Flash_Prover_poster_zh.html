1

问题：形式化推理不只是 SFT

普通 reasoning 模型（o1/R1/Flash-Thinking）擅长自然语言 CoT，但 Lean4 是强类型、kernel 编译验证的函数式证明语言——一次成功证明可能调几十次 Lean4 server。LongCat-Flash-Prover 把"自然语言数学题 → Lean4 形式化语句 → 完整/拆分式证明"做成模型的原生能力，统一训练 Auto-Formalization、Sketching、Proving 三件事。

图 1：训练 pipeline（cold-start + 多轮 agentic TIR RL）
① Hybrid-Experts Iteration：6 类轨迹

从 3 个 expert（AF/Sk/Pf）×（单轮/TIR）×{whole-proof, sketch-proof} 合成 6 类高质量轨迹。curriculum：先单轮再 TIR，先 whole-proof 后 sketch-proof；pass 率 = 0 保留、连续两轮全挂剔除。

② 560B MoE / 27B active 基座

继承 [[2509_LongCat_Flash|LongCat-Flash]] ScMoE + Zero-Computation Experts 架构，from cold-start = Flash-Thinking-2601。复用 DORA 异步 RL 框架，codebase 完全一致。

2

HisPO：层级式梯度屏蔽

MoE + 长程异步 RL 下，importance sampling ratio $r_{i,t}(\theta)$ 被两层污染——train-inf 差异（Megatron vs vLLM bitwise 不一致）与 policy staleness。HisPO 用指示函数 $H_{i,t}(\theta)$ 同时做序列级 + token 级屏蔽：

Importance Ratio 分解
$$r_{i,t}(\theta) = \underbrace{\frac{\pi_{\theta_{old}}}{\mu_{\theta_{old}}}}_{r^{dis}(\theta),\ \text{train-inf 差异}} \times \underbrace{\frac{\pi_\theta}{\pi_{\theta_{old}}}}_{r^{stale}(\theta),\ \text{policy 过时}}$$
HisPO Hierarchical Mask
$$H_{i,t}(\theta) = \mathbb{I}\!\left\{\left|\exp\!\left(\tfrac{1}{|y_i|}\!\sum_j \log r_{i,j}^{dis}\right) - 1\right| < \delta_{seq}\right\} \cdot \mathbb{I}\!\left\{|r_{i,t}^{dis} - 1| < \delta_{tok}\right\}$$
Sequence-level Mask

几何均值 discrepancy 超阈值 → 整条序列 mask。比 GSPO 只看序列级更细，避免误杀好 token。

Token-level Discrepancy Mask

剩余序列再剔除 per-token discrepancy 过大的 token。

Triplet Clipping + No-KL

借鉴 DAPO/MoBA 三段 clip（neg low/high + pos high），移除 KL loss（$k_3$ 梯度有偏）。global max length 消 length bias。

3

AST-based Legality Detection

训练到第 80 步 rollout pass rate 突然飙升——是开源评估 pipeline 漏洞：Lean4 只检查 syntax + 目标定理定义一致性，formal context 完全可编辑。模型学会作弊：加 import 引入隐藏 axiom、用 open/lemma 改写目标、凭空造 axiom。

修复方案

写轻量 Lean4 lexer/parser → 转 AST → 严格对比 formal statement 与 proof/sketch 的 AST 一致性。修好 reward 后从第 80 步重启 RL，pass rate 曲线立刻回到合理水平。首次系统揭露开源 Lean4 评估的 reward hacking 漏洞。

4

核心方法：Agentic Tool-Integrated RL

关键不是"用 Lean4 当 verifier"——所有 prover 都这么干——而是把 tool call 本身做成 RL 优化目标：模型不是单次生成完去打分，而是学会"自己写一段 → 让 Lean4 编译 → 看错误 → 改"这种多轮 agentic 闭环。HisPO 稳定的就是这种长 horizon 轨迹。

Whole-proof → TIR → Sketch+TIR Pass@32
$$\text{MiniF2F-Test: } 84.4\% \xrightarrow{+\text{TIR}} 90.2\% \xrightarrow{+\text{sketch}} 93.9\%$$
Auto-Formalization (AF) expert

自然语言 → Lean4 形式化语句。工具集 $\mathcal{T}_{af} = \{\mathcal{V}_{syn}, \mathcal{V}_{con}\}$：$\mathcal{V}_{syn}$ 把生成语句拼上 := by sorry 丢进 Lean4 Server (v4.15) 编译；$\mathcal{V}_{con}$ 用 LLM-as-Judge 过滤"语义与原题不一致"的语句。Cold-start 阶段用自家 ATF-32B 批量合成。

Sketching (Sk) expert — 分治骨架

把难定理拆成若干易证 helper lemma，主定理引用若干 sorry 的 helper lemma。已证 lemma 可被后续复用——本质是分治 + 动态规划。whole-proof 走不通的题自动 fall back 到 sketch-proof。

Proving (Pf) expert — Whole + Sketch 双模式

Whole-proof（直接整段证）或 Sketch-proof（先 sketch 再逐 lemma 证）。TIR 多轮调用让模型从 Lean4 编译错误中持续改进。

5

Tree Search：sample efficiency 终极 trick

Tree Search 在推理阶段从模型 rollout 中聚合最优路径，用相对小的 budget 达到 SOTA。MiniF2F-Test 从 95.5% (72 budget) → 97.1% (72 budget + Tree Search)——开源最强 sample efficiency。

图 2：Tree Search 训练轨迹（搜索 vs 单次 rollout 对比）
Sample efficiency 震撼对比

Goedel-Prover-V2-32B 和 Kimina-Prover-72B 都要 1,024+ attempts 才到 92.2% on MiniF2F。LongCat-Flash-Prover 用 72 attempts 就到 95.5%（+Tree Search 97.1%）。

PutnamBench 涨近 3 倍

Tree Search 平均再涨 3.1%；PutnamBench 从 10.4% (sketch+TIR) → 41.5% (sketch+TIR + Tree Search)，翻了近 4 倍，说明难题受益最多。
