模型家族
  • Scout：17B 激活 / 109B 总参，16 experts，极长 10M token context，单 GPU 可部署
  • Maverick：17B 激活 / 400B 总参，128 experts，定位 frontier performance，多数 benchmark 超越 GPT-4o
  • Behemoth：288B 激活 / 约 2T 总参，作为 teacher model 继续训练，已超越 GPT-4.1 和 Gemini 2.0 Ultra

关键创新
  • iRoPE：Interleaved Rotary Position Embedding，支撑 10M context 外推
  • MetaP 初始化：跨规模超参数迁移，训练稳定性
  • FP8 训练：混合精度，支持大规模 MoE 高效训练
  • Early Fusion：图片/文本在同一序列统一融合，无需独立视觉塔
关键设计
  • 从头联合训练文本和图像，而非后接视觉模块——原生多模态架构
  • MoE 让激活参数保持可控，同时扩大总容量，稀疏激活效率高
  • 超长上下文让多文档、代码库和长会话任务可直接纳入上下文
  • Behemoth 作为 teacher，通过蒸馏将前沿能力迁移到 Scout/Maverick

稀疏激活：每个 token 仅触发少数 expert，激活参数远小于总参数量，在保持输出的质量的同时大幅降低计算成本
Early Fusion（早期融合）
图片和文本在输入层即被融合到统一序列中，而非使用独立的视觉 encoder + cross-attention 塔。这种早期融合策略使多模态表征在预训练阶段即深度对齐，支撑更强的视觉推理能力。
训练流程
  • 预训练：在海量多模态语料上联合训练文本 + 图像
  • 蒸馏：Behemoth teacher → Scout/Maverick students
  • 后训练：SFT + RLHF，提升指令跟随与安全性
  • 长上下文扩展：Scout 扩展至 10M token 上下文窗口

启发与意义
  • Llama 4 的核心是开源权重 + 多模态 + 超长上下文的组合
  • Scout 展示了"效率优先"的长上下文路线，Maverick/Behemoth 承接性能上限
  • 对 Agent 开发：长上下文可减少检索复杂度，但仍需要状态压缩和验证机制
  • MoE 证明了小激活参数能跑出大模型性能，降低了部署门槛
