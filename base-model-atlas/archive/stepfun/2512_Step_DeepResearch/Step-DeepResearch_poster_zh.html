问题与动机

核心痛点
Search ≠ Research
现有评测基准（BrowseComp）关注学术多跳搜索，与真实开放域研究需求差距大。Search 有明确答案；Research 需要意图分解、规划、工具使用、跨源验证、结构化报告。
多跳 QA 作为优化目标的问题
压力导致 Agent 过度偏向检索行为，像"高效网络爬虫"而非"研究者"。信息碎片化、推理链断裂、幻觉等问题阻碍实际部署。
2

原子能力体系

四大原子能力
① 规划与任务分解
Reverse Engineering：从高质量报告逆向推导"项目任务"，利用摘要作为 hindsight 约束，轨迹一致性过滤。
② 深度信息检索
Graph-based：Wikidata5m/CN-DBpedia 子图采样 + BFS 扩展 + 多跳问题生成；Multi-document：Wiki-doc 拓扑游走。
③ 反思验证
Error-Reflection Loop：生成→验证→反思（最多3次）；Deep Verification Workflow：Extract/Plan/Verify/Replan/Report 多智能体协作。
④ 报告生成
Mid-training 学领域风格，SFT 学指令遵循和格式规范。
核心设计原则
将"预测下一个 token"重塑为"决定下一个原子动作"：原子动作子空间 $\mathcal{A}_{\text{atomic}} \subset \mathcal{A}_{\text{token}}$，最小化剪枝误差 $\epsilon_{\text{pruning}}$ + RL 难度 $\epsilon_{\text{RL}}$。
3

三阶段训练 pipeline

Stage 1: Agentic Mid-training
32K Context：原子能力注入（规划/检索/反思/报告），无工具调用，纯文本推理。150B tokens 规模未收敛。
128K Context：引入工具调用，检索/规划/工具增强推理，覆盖 Web 交互、搜索、多工具协作。
Stage 2: Post-training SFT
全链路轨迹对齐：Deep Search + Deep Research。
"正确且最短"轨迹效率优化；受控噪声注入（工具错误→反思-纠正）；N-gram 去重；严格引文格式对齐。
Stage 3: Reinforcement Learning
Two-Step Reverse Synthesis：强模型生成隐藏任务摘要 + 细粒度评分标准 → 反向合成目标任务 → 一致性验证。
Rubrics Judge：从强模型学习评分逻辑 → SFT + RL 训练。
Strict Reward Mapping：正 rubric 全满足=1，否则=0；负 rubric 反之（二值化消除中间状态噪声）。
PPO + GAE(γ=1, λ=1)：actor-critic 支持 token 级学习信号，适合长周期、多工具场景。
Base Model
Qwen2.5-32B-Base
32B 参数，128K 上下文，接近 72B 模型的指令跟随和逻辑推理能力，大幅降低训练成本，确保性能提升来自训练范式和数据策略。
