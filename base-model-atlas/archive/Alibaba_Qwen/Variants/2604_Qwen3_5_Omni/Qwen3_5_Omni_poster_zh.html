问题与动机

全模态原生智能体的必要性
人类与世界的交互本质上是多模态的：视觉、听觉、语言协同感知，通过文本、语音、工具调用进行响应。现有模型多停留在被动感知-响应范式，缺乏可扩展的智能体行为、实时交互和跨模态推理能力。
Qwen3.5-Omni 的定位
原生全模态 LLM，支持文本、图像、音频、视听联合理解与生成。设计为原生智能体模型：不仅感知和推理跨模态信息，还能自主调用 WebSearch、FunctionCall、流式语音输出，实现实时流式交互。
2

架构设计

Thinker-Talker 架构
Thinker：接收视觉和音频信号，生成文本 Token
Talker：基于 Thinker 的高阶表征，生成流式语音 Token

关键升级：Thinker 和 Talker 均采用 Hybrid MoE 设计，显著提升推理效率。
五大技术升级
① MoE 架构：Hybrid MoE + GDN 模块降低长序列 KV-cache I/O
② 256K 上下文：支持 10+ 小时音频，400 秒 720P 视频
③ 多码本表征：RVQ + MTP 模块实现单帧即时语音合成
④ ARIA 技术：流式解码中文本-语音动态对齐
⑤ 多语言扩展：113 种语言 ASR，36 种语言 TTS
ARIA — Adaptive Rate Interleave Alignment
替代 Qwen3-Omni 的双通道生成范式，统一为单通道交错生成。引入单调交错约束：生成序列前缀的累积语音-文本 Token 比率不超过对应项级全局比率。解决跳词、发音错误、数字渲染歧义等问题。
3

三大新能力

① 可控视听描述
生成可控、详细、结构化描述，包括自动分段、时间戳标注、角色描述及其与音频的关系。支持剧本级细粒度描述。
② 实时交互能力
• 语义打断：原生轮次意图识别
• 端到端语音控制：音量、语速、情感
• 语音克隆：从用户样本零样本克隆
③ 原生多模态智能体行为
Audio-Visual Vibe Coding：从视听指令直接生成可执行代码，无需外部编排。模型自主进行 WebSearch、复杂 FunctionCall 调用，实现实时查询响应。
