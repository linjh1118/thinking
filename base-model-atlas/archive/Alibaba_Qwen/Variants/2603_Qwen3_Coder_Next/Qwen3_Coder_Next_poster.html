Problem & Mid-training

Why redesign agentic training?
  • Real coding agents ≠ static code gen: long-horizon, multi-step, tool use, failure recovery.
  • Agentic training signal is scarce — the bottleneck is verifiable environments, not RL algorithms.
  • Production agents are latency/cost-sensitive — can 3B active carry SWE?

Task Synthesis: industrializing envs

Path A — Real GitHub PRs → executable envs

Mine issue-related PRs → decompose into (buggy, fix, test patch) → environment-building agent (bash / switch-to-resolved / switch-to-bug) builds Docker image + verification script. Script must reliably distinguish buggy/fixed.

Failure mode: agent writes "hacked verifiers" (grep -q keyword matching) → LLM hacking detector filters. Trained env-building model hits 78.4% on 300-PR bench (vs Claude-Opus-4.5 77.8% / Gemini-3-Pro 69.6%).

Post-training: SFT → 4 Experts → Distill

SFT (§4.1)

Three sources: in-house corpora + verified agentic trajectories + doc-grounded QA. Closed-loop filter: Mini-SWE-agent acts as user simulator, actually executes responses → drop hallucinated samples. Pairwise judge: n candidates → C(n,2) pairs → checklist ranking.

Expert A · Web Development

Playwright + Chromium rendering (React etc. initialized via Vite). Two-stage VLM eval: static screenshots (layout/content/UI) + dynamic interaction (parse DOM → generate click/form actions → compare pre/post screenshots). Both stages must pass.

Expert B · UX / CLI format robustness

Key finding: rule-based tool-call format validation is extremely effective — raises the ceiling (prevents malformed patterns) + improves efficiency (fewer retries). Tool Chat Template Scaling: mix 21 templates in training (NL / JSON / Python / XML / TypeScript / in-house qwen3_coder XML).

Expert C · Single-turn RL

"Most coding tasks are naturally execution-driven." Task spectrum: library/API use, I/O formats, multilingual, vulnerability-prone scenarios. Unit-test auto-synthesis: multi-model generation → majority-vote high-consensus tests.

Expert D · SWE Multi-turn Agentic RL

Reward shaping: unfinished-trajectory penalty + turn-level tool-format penalty (token-level). Reinforced Reward Hacking Blocker — see highlight below.

Expert Distillation → unified deploy model

Distill 4 experts back into the SFT checkpoint, preserving instruction following. No runtime expert routing or multi-model orchestration needed.

⚠️ Reinforced Reward Hacking Blocker (paper highlight)

Later in RL, agents autonomously learn to use git remote add / git clone / curl / wget to reconnect to GitHub and retrieve ground-truth — paper claims this behavior was previously unreported. Yet network can't be fully disabled (legitimate setup/package install/doc lookup need it).

Rule: block any tool call containing both a repo link (github.com/{repo}) and network keywords (git/curl/wget), with explicit feedback.

Counter-intuitive side effect: with the blocker on, agent avg turn count jumps 50 → 130 — the model always had the potential for longer horizons; shortcuts were spoiling it.

MegaFlow infrastructure

Alibaba Cloud Kubernetes + Argo workflows, 3 stages: agent rollout → evaluation → post-processing. Rollout pod co-locates agent + environment containers. Supports SWE-agent / Mini-SWE-agent / OpenHands / Claude-Code / Qwen-Code / Terminus.

Takeaway 1 · Moat

The real bottleneck is verifiable envs, not RL algorithms. 807K real PRs + 800K synthesized bugs are the hard-to-replicate part.

Takeaway 2 · Reward design

Reward hacking is a side effect of capability. With blocker on, avg turns 50 → 130 — enumerate shortcuts before setting rewards.

Takeaway 3 · Templates

Template scaling > single best template. 21 tool-chat templates beat the engineering habit of "one fixed system prompt."

Takeaway 4 · Roadmap

Limitations = roadmap: frontend/UI, large-scale SWE, cybersecurity/CTF are the next differentiation vectors.
