<a href=\"/zh/model-studio/qwen-audio-live-client-events#live-session-update\"><code>session.update</code></a> 中设置 <code>session.delegation.type</code>。Responses 模式填 <code>responses</code>，Client 模式填 <p>Qwen-Audio-Live 的前台模型负责听取用户语音、提问和回复。遇到需要调用业务接口或进行推理的任务，可以把任务交给应用或后台模型，继续与用户对话。</p>
<p>以查订单为例，查询期间，前台模型仍可以接收用户补充的订单号，并播报查询进展和结果。Client 模式由应用处理任务并回传结果。Responses 模式由百炼调用配置的后台模型处理任务，并将结果交给前台模型。</p>
<img class="image break" src="https://g-adoc.alcasset.com/media/maas_docs/sfm-cn/zh/images/6a4b3c2d1e0f9009.png" alt="前台模型在订单查询期间继续对话，应用或后台模型根据所选模式处理任务并回传结果。" width="640">
<span id="接入应用"></span>
<p>会话配置、音频收发和用量查询见<a href="#live-sessions">管理会话</a>。接入业务系统或后台模型见<a href="#live-delegation">任务委派与工具</a>。</p>
<h2 id="快速开始">快速开始 <span id="live-quickstart"></span></h2>
<ul>
<li>想先验证接入，可以<a href="#live-first-session">运行本页的 Python 示例</a>，发送一段录音，检查能否收到字幕和音频。</li>
<li>想直接和模型对话，可以<a href="/zh/model-studio/qwen-audio-live-webrtc-access#live-webrtc-browser-demo">运行 WebRTC 浏览器示例</a>，用麦克风说话，并听取模型回复。</li>
</ul>
<h3 id="建立第一个会话">建立第一个会话 <span id="live-first-session"></span></h3>
<p>本例通过 WebSocket 将一段录音发送给模型，并将语音回复保存到 <code>reply.wav</code>。</p>
<h4 id="准备录音和凭证">准备录音和凭证</h4>
<ul>
<li>准备华北<span class="help-letter-space"></span>2（北京）的业务空间 ID 和 <a href="/zh/model-studio/get-api-key">API Key</a>。长期 API Key 保存在应用服务端。</li>
<li>安装 Python 和 FFmpeg。录一句「请从一数到三」，保存为 <code>input.wav</code>。</li>
</ul>
<p>将 API Key 配置到环境变量 <code>DASHSCOPE_API_KEY</code>，然后安装依赖，并将录音转换为 16 kHz、16 位、单声道的 PCM 音频。</p>
<pre data-tag="codeblock" id="code-block" outputclass="language-bash" code-type="xCode" class="pre codeblock language-bash"><code>python -m pip install "websockets&gt;=15"
ffmpeg -i input.wav -ar 16000 -ac 1 -f s16le input.pcm
</code></pre>
<h4 id="发送录音并接收回复">发送录音并接收回复</h4>
<p>Qwen-Audio-Live 仅支持业务空间专属域名。这个示例连接华北<span class="help-letter-space"></span>2（北京），请在代码中填写该地域的业务空间 ID。</p>
<p>示例中的两个模型参数已经填好。连接地址里的 <code>model</code> 用于接入 Qwen-Audio-Live 服务，<code>session.model</code> 则指定与用户交谈的前台模型。本例使用 <code>qwen-audio-4.0-realtime-preview</code>，并将 <code>turn_detection.type</code> 设为 <code>duplex</code>，开启全双工对话。此时模型可以边听边说，在回复时仍能接收用户语音。其他会话设置见 <a href="/zh/model-studio/qwen-audio-live-client-events#live-session-update">session.update</a>。</p>
<p>将以下示例保存为 <code>live_quickstart.py</code>。</p>
<pre data-tag="codeblock" id="code-block-2" outputclass="language-python" code-type="xCode" class="pre codeblock language-python"><code>import base64
import json
import os
import sys
import time
import uuid
import wave
from pathlib import Path

from websockets.sync.client import connect

WEBSOCKET_URL = "wss://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api-ws/v1/realtime?model=qwen-audio-3.1-live"
SESSION_MODEL = "qwen-audio-4.0-realtime-preview"
REPLY_TIMEOUT_SECONDS = 12


def main():
    audio = Path(sys.argv[1]).read_bytes()
    if not audio or len(audio) % 2:
        raise ValueError("请提供非空的 16 位 PCM 文件")
    headers = {"Authorization": f"Bearer {os.environ['DASHSCOPE_API_KEY']}"}
    with connect(
        WEBSOCKET_URL,
        additional_headers=headers,
        close_timeout=2,
    ) as ws:
        def send(event_type, **payload):
            ws.send(json.dumps({
                "type": event_type,
                "event_id": uuid.uuid4().hex,
                **payload,
            }))

        session = {
            "model": SESSION_MODEL,
            "modalities": ["text", "audio"],
            "turn_detection": {"type": "duplex"},
            "delegation": {"type": "client"},
        }
        send("session.update", session=session)

        deadline = time.monotonic() + 20
        while True:
            event = json.loads(ws.recv(timeout=max(0, deadline - time.monotonic())))
            if event["type"] == "session.updated":
                break
            if event["type"] in ("error", "session.closed"):
                raise RuntimeError(event)

        audio += bytes(32000 * 3)
        with wave.open("reply.wav", "wb") as reply:
            reply.setparams((1, 2, 24000, 0, "NONE", "not compressed"))
            start = time.monotonic()
            offset = 0
            deadline = start + len(audio) / 32000 + REPLY_TIMEOUT_SECONDS
            while time.monotonic() &lt; deadline:
                if offset &lt; len(audio) and time.monotonic() &gt;= start + offset / 32000:
                    frame = audio[offset:offset + 640]
                    send("session.input_audio.append",
                         audio=base64.b64encode(frame).decode("ascii"))
                    offset += len(frame)
                try:
                    event = json.loads(ws.recv(timeout=0.02 if offset &lt; len(audio) else 0.25))
                except TimeoutError:
                    continue
                event_type = event["type"]
                if event_type == "session.output_audio.delta":
                    reply.writeframesraw(base64.b64decode(event["delta"]))
                elif event_type == "session.output_transcript.delta":
                    print(event["delta"], end="", flush=True)
                elif event_type == "session.closed":
                    break
                elif event_type == "error":
                    raise RuntimeError(event["error"])
            else:
                send("session.close")
                close_deadline = time.monotonic() + 2
                while time.monotonic() &lt; close_deadline:
                    try:
                        event = json.loads(ws.recv(timeout=max(0, close_deadline - time.monotonic())))
                    except TimeoutError:
                        break
                    if event["type"] == "session.closed":
                        break
            if not reply.getnframes():
                raise RuntimeError("未收到语音回复")


main()
</code></pre>
<pre data-tag="codeblock" id="code-block-3" outputclass="language-bash" code-type="xCode" class="pre codeblock language-bash"><code>python live_quickstart.py input.pcm
</code></pre>
<p>运行后，终端会显示回复字幕。打开生成的 <code>reply.wav</code>，确认能听到模型数数。该文件是 24 kHz、16 位、单声道 WAV。</p>
<p>如果没有收到回复，先检查 API Key、业务空间 ID 和连接地址是否属于同一地域，再确认脚本是在收到 <a href="/zh/model-studio/qwen-audio-live-server-events#live-session-updated"><code>session.updated</code></a> 后才发送录音。其他现象可按<a href="#live-troubleshoot-session">排查接入问题</a>逐项检查。</p>
<h3 id="选择接入方式">选择接入方式</h3>
<p>两种接入方式都先建立 WebSocket 主连接。您可以用这条连接直接收发音频，也可以另外建立一条 WebRTC 或 AOQ 媒体连接来收发音频。</p>
<ul>
<li>
<p><strong><a href="/zh/model-studio/qwen-audio-live-websocket-access">仅用 WebSocket</a></strong>。适合用录音验证接入，或由服务端直接处理音频。音频、字幕和任务事件都走同一条连接。</p>
<img class="image break" src="https://g-adoc.alcasset.com/media/maas_docs/sfm-cn/zh/images/6a4b3c2d1e0f901d.png" alt="应用与百炼共用一条 WebSocket 连接收发音频和事件。" width="620">
</li>
<li>
<p><strong>WebSocket + WebRTC 或 AOQ</strong>。保留 WebSocket 主连接，用它配置会话、协商媒体连接和发送任务请求。媒体连接就绪后，用它收发音频，同时可从 WebSocket 主连接或媒体连接接收服务端事件。</p>
<img class="image break" src="https://g-adoc.alcasset.com/media/maas_docs/sfm-cn/zh/images/6a4b3c2d1e0f9018.png" alt="控制 WebSocket 是主连接。WebRTC 或 AOQ 媒体连接收发音频，也可接收服务端事件。" width="620">
<ul>
<li><strong><a href="/zh/model-studio/qwen-audio-live-webrtc-access">WebRTC</a></strong>。适合在浏览器或应用中实时采集和播放语音。通过控制 WebSocket 交换 SDP。</li>
<li><strong><a href="/zh/model-studio/qwen-audio-live-aoq-access">AOQ</a></strong>。适合已集成 AOQ Client SDK 的应用。通过控制 WebSocket 获取临时凭证，再用 SDK 连接 Relay。</li>
</ul>
</li>
</ul>
<p><a href="/zh/model-studio/qwen-audio-live-api-reference">API 参考</a>按操作提供请求与响应事件的入口。<a href="/zh/model-studio/qwen-audio-3-1-live">模型详情</a>列出地域、限流和价格。</p>
<h2 id="编写提示词">编写提示词 <span id="live-write-prompts"></span> <span id="编写前台和后台指令"></span></h2>
<h3 id="编写前台对话提示词">编写前台对话提示词</h3>
<p>在 <code>session.instructions</code> 中设置前台的角色和语气，说明何时追问、何时委派，以及如何播报结果。</p>
<p>初次配置会话时，省略 <code>session.instructions</code> 会使用内置提示词。如果填写了自定义提示词，它会替换内置提示词，因此请把对话需要遵循的规则写完整。</p>
<p>要让客服先简短回答，再问客户是否需要帮助，可在 <code>session.update</code> 的 <code>session</code> 中加入以下字段，并保留已有的 <code>model</code> 和 <code>delegation</code> 等设置。</p>
<pre data-tag="codeblock" id="code-block-4" outputclass="language-json" code-type="xCode" class="pre codeblock language-json"><code>{
  "instructions": "担任门店客服。先用一句话回答，再询问用户是否需要其他帮助。"
}
</code></pre>
<h3 id="编写任务处理规则">编写任务处理规则</h3>
<p>任务提示词说明处理步骤、输入校验和结果格式。用 Client 模式时，在应用或 Agent 中定义这些规则。用 Responses 模式时，在 <code>session.delegation.responses.instructions</code> 中写明后台模型需要遵循的规则，百炼没有内置的后台提示词。</p>
<h3 id="用提示词分配计算任务">用提示词分配计算任务</h3>
<p>在 Responses 模式下，可以让前台问清计算条件，由后台计算总价。</p>
<ul>
<li><strong>前台提示词</strong>说明何时追问、何时交给后台。例如，缺少单价或数量时，先向用户确认。条件齐全后，把计算任务交给后台模型，并在收到结果后用一句话播报。</li>
<li><strong>后台提示词</strong>说明怎么算、返回什么。例如，根据单价和数量计算总价，返回金额和币种。</li>
</ul>
<p>完整的会话配置和验证步骤见 <a href="#live-use-responses">Responses 模式示例</a>。</p>
<h2 id="管理会话">管理会话 <span id="live-sessions"></span></h2>
<p>建立连接后，先配置会话，确定由哪个前台模型和用户交谈、使用什么音色、如何传输音频，以及任务交给谁处理。</p>
<h3 id="配置会话">配置会话</h3>
<table><thead><tr><th>设置</th><th>配置位置和用途</th></tr></thead><tbody><tr><td>前台模型</td><td>通过 <code>session.model</code> 选择与用户交谈的模型。要开启全双工对话，选择 <code>qwen-audio-4.0-realtime-preview</code>，并将 <code>session.turn_detection.type</code> 设为 <code>duplex</code>。</td></tr><tr><td>对话指令和音色</td><td>通过 <code>instructions</code> 和 <code>voice</code> 设置。见<a href="#live-write-prompts">编写提示词</a>和<a href="#live-configure-voice">配置音色</a>。</td></tr><tr><td>输出类型</td><td><code>modalities</code> 同时包含 <code>text</code> 和 <code>audio</code> 时，服务返回语音和字幕。</td></tr><tr><td>音频传输方式</td><td>通过 <code>session.transport</code> 选择音频走哪条连接。省略时，音频通过 WebSocket 收发。使用 WebRTC 或 AOQ 时，按各自的<a href="/zh/model-studio/qwen-audio-live-api-reference#live-select-transport">接入流程</a>建立媒体连接。</td></tr><tr><td>任务处理模式</td><td>通过 <code>session.delegation</code> 设置。见<a href="#live-delegation">任务委派与工具</a>。</td></tr></tbody></table>
<p>发送 <a href="/zh/model-studio/qwen-audio-live-client-events#live-session-update"><code>session.update</code></a> 后，通过 <a href="/zh/model-studio/qwen-audio-live-server-events#live-session-updated"><code>session.updated</code></a> 确认哪些配置已生效。仅用 WebSocket 时，收到该事件后就可以发送音频。使用 WebRTC 或 AOQ 时，还要等媒体连接就绪。</p>
<h3 id="配置音色">配置音色 <span id="live-configure-voice"></span> <span id="配置对话指令和音色"></span></h3>
<p>在 <code>session.update</code> 的 <code>session</code> 对象中设置音色 ID，保留其余会话配置。</p>
<pre data-tag="codeblock" id="code-block-5" outputclass="language-json" code-type="xCode" class="pre codeblock language-json"><code>{
  "voice": "qingyou"
}
</code></pre>
<p>示例中的 <code>qingyou</code> 对应「青柚」，默认值为 <code>yunshu</code>（云舒）。完整列表见<a href="/zh/model-studio/qwen-audio-live-client-events#live-session-voice">客户端事件</a>。</p>
<h3 id="收发语音和字幕">收发语音和字幕 <span id="live-session-media"></span></h3>
<p>发送麦克风音频和播放模型回复时，使用建连时选定的音频通道。开启全双工对话后，播放回复时也要继续采集并发送用户语音，同时读取服务端事件。</p>
<ul>
<li><strong>WebRTC</strong> 通过媒体轨道收发音频。浏览器收到远端音轨后，将它交给播放器。</li>
<li><strong>AOQ</strong> 通过 SDK 发送用户语音和播放模型回复。上行音频必须通过 AOQ 发送。将 <code>session.transport.aoq.ws_audio</code> 设为 <code>true</code> 后，控制 WebSocket 也会收到一份模型的回复音频。详见 <a href="/zh/model-studio/qwen-audio-live-aoq-access">AOQ 接入</a>。</li>
<li><strong>WebSocket</strong> 通过 JSON 事件收发音频。输入和输出都使用单声道 PCM，采样率见下表。</li>
</ul>
<p>下表的音频收发流程适用于纯 WebSocket 接入。字幕事件适用于三种接入方式。</p>
<table><thead><tr><th>数据</th><th>事件</th><th>处理方式</th></tr></thead><tbody><tr><td>麦克风音频或录音</td><td>发送 <code>session.input_audio.append</code></td><td>将 16 kHz、16 位、单声道 PCM 音频分片并编码为 Base64。快速开始以 20 毫秒为一帧。</td></tr><tr><td>模型回复音频</td><td>接收 <code>session.output_audio.delta</code></td><td>解码事件的 <code>delta</code>，按到达顺序播放 24 kHz、16 位、单声道 PCM。</td></tr><tr><td>字幕</td><td>接收 <code>session.input_transcript.delta</code> 和 <code>session.output_transcript.delta</code></td><td>前者是用户语音的转写，后者是模型回复的字幕。</td></tr></tbody></table>
<p>如果用户在模型播报时补充一句话，用户字幕和模型字幕可能同时更新。将两路字幕分别追加到各自的对话气泡，并根据播放器的实际状态更新界面上的播报指示。</p>
<p>WebRTC 或 AOQ 媒体连接就绪后，控制 WebSocket 和媒体连接都可用于接收字幕。如果两路都收到同一个 <code>event_id</code>，只追加一次。</p>
<p>如果界面有麦克风开关，可在用户切换时发送 <code>session.input_audio.mute</code> 或 <code>session.input_audio.unmute</code>，等服务确认后再更新开关状态。静音期间，会话仍保持连接。</p>

</code></pre>
<h3 id="结束会话和查看用量">结束会话和查看用量</h3>
<p>单次会话没有时长上限，费用按会话时长（秒）计算。连接建立后至少计费 3 秒，超过 3 秒则按实际会话时长计费。发送文字消息、静音和空闲的时间都计入会话时长。百炼调用后台模型时，还会按该模型的实际 Token 用量另行计费。</p>
<p>用户挂断或点击结束时，发送 <code>session.close</code> 并停止采集麦克风音频。等收到 <code>session.closed</code> 后，再关闭连接并释放资源。</p>
<p>会话激活后，服务每 5 秒通过 <code>session.usage.updated</code> 上报 <code>usage.seconds</code>，表示会话累计计费时长（秒）。会话期间取最新值，结束后以 <code>session.closed</code> 中的 <code>usage.seconds</code> 为准。价格及后台模型计费见<a href="/zh/model-studio/model-pricing#qwen-audio-live-pricing">计费说明</a>。</p>
<h3 id="排查接入问题">排查接入问题 <span id="live-troubleshoot-session"></span></h3>
<table><thead><tr><th>问题现象</th><th>排查方法</th></tr></thead><tbody><tr><td>上传音频后没有回复</td><td>先确认收到 <code>session.updated</code>。纯 WebSocket 接入时，检查上行音频是否为 16 kHz、16 位、单声道 PCM。使用 WebRTC 或 AOQ 时，确认媒体连接已就绪，并已通过该连接发送音频。</td></tr><tr><td>收到字幕，未听到语音回复</td><td>纯 WebSocket 接入时，检查是否收到 <code>session.output_audio.delta</code>，并以 24 kHz 播放。使用 WebRTC 或 AOQ 时，检查播放器是否接收到所选通道的下行音频。</td></tr><tr><td>任务已处理，未听到语音播报</td><td>检查应用是否接收并播放前台模型的语音。Client 模式下，确认回传的 <code>delegation_id</code> 与任务一致。</td></tr><tr><td>收到 <code>error</code> 或 <code>session.closed</code></td><td>收到 <code>error</code> 时，按<a href="/zh/model-studio/qwen-audio-live-server-events#live-error">错误事件</a>检查请求。会话关闭后，如需继续通话，重新建连并配置会话。</td></tr></tbody></table>
<h2 id="任务委派与工具">任务委派与工具 <span id="live-delegation"></span></h2>
<p>本节示例沿用<a href="#live-quickstart">快速开始</a>的纯 WebSocket 连接。使用 WebRTC 或 AOQ 时，会话配置和任务请求仍通过控制 WebSocket 发送，音频则通过媒体连接收发。</p>
<h3 id="前后台工具选型">前后台工具选型</h3>
<p>用户在对话中提出业务请求时，前台模型可以直接发起函数调用，也可以把任务委派给后台。接入时，可以根据任务的处理步骤和响应要求，选择把工具配置在哪里。</p>
<ul>
<li><strong>前台工具</strong>适合可直接执行、需要快速响应的操作。例如，用户说「播放音乐」时，前台模型调用通过 <code>session.tools</code> 注册的函数，由应用执行播放指令。</li>
<li><strong>后台工具</strong>适合需要判断条件或依次调用多个工具的任务。例如，办理改签时，后台先查询订单和改签规则，再查找可选班次。前台模型收到结果后，向用户说明有哪些班次可选。</li>
</ul>
<h3 id="选择处理任务模式">选择处理任务模式</h3>
<p>希望百炼调用后台模型并传回结果时，选择 <a href="#live-use-responses">Responses 模式</a>。已有业务接口、工作流或 Agent，或者需要由应用先核对结果再决定播报内容时，选择 <a href="#live-use-client">Client 模式</a>。</p>
<p>在 <a href="/zh/model-studio/qwen-audio-live-client-events#live-session-update"><code>session.update</code></a> 中设置 <code>session.delegation.type</code>。Responses 模式填 <code>responses</code>，Client 模式填 <code>client</code>。</p>
<table><thead><tr><th>要决定的事</th><th>Responses 模式</th><th>Client 模式</th></tr></thead><tbody><tr><td>谁处理任务</td><td>百炼调用配置的后台 Responses 模型。</td><td>应用调用业务接口、工作流、Agent 或模型。</td></tr><tr><td>谁准备任务输入</td><td>百炼根据会话发起后台请求，应用配置后台模型和任务指令。</td><td>应用从委派事件读取任务摘要和上下文，结合业务数据构造请求。</td></tr><tr><td>谁决定回传什么</td><td>后台结果由百炼交给前台模型。</td><td>应用可以校验、汇总或筛选结果，再把适合播报的内容交给前台模型。</td></tr></tbody></table>
<p>例如，只需根据用户给出的单价和数量计算总价，可以用 Responses 模式。查询库存需要按门店权限调用内部接口，并由应用校验结果，可以用 Client 模式。</p>
<p>两种模式都可以<a href="#live-call-frontend-functions">配置前台函数</a>，用 <code>call_id</code> 将函数调用与结果对应起来。Client 模式中的任务委派则使用 <code>delegation_id</code> 关联同一任务的进度、追问和结果。接入业务系统前，先确认应用拥有接口权限，并了解接口需要哪些输入、会返回什么。</p>
<h3 id="使用-responses-模式调用后台模型">使用 Responses 模式调用后台模型 <span id="live-use-responses"></span></h3>
<h4 id="接入准备">接入准备</h4>
<p>准备业务空间可调用的后台 Responses 模型。示例使用 <code>qwen4-max</code> 计算总价，再由前台模型播报。</p>
<h4 id="配置会话-2">配置会话 <span id="live-responses-configuration"></span></h4>

<p>百炼将 <code>session.delegation.responses</code> 中的 <code>model</code>、<code>instructions</code> 和 <code>tools</code> 配置传给所选的后台模型。</p>

<h4 id="接收后台事件">接收后台事件</h4>
<p>自动委派开始时，服务发送 <a href="/zh/model-studio/qwen-audio-live-server-events#live-delegation-created"><code>session.delegation.created</code></a>。后台生成期间，服务通过 <a href="/zh/model-studio/qwen-audio-live-server-events#live-response-event"><code>response.event</code></a> 转发后台事件。按外层的 <code>delegation_id</code>（如有）关联任务，按 <code>event.type</code> 区分后台事件。</p>
<p>在音频接收循环中，将下面两个分支加在 <code>session.output_transcript.delta</code> 分支之后。用内层 <code>response.completed</code> 判断后台何时完成本次生成，再从前台字幕和音频事件获取面向用户的回复。</p>
<pre data-tag="codeblock" id="code-block-8" outputclass="language-python" code-type="xCode" class="pre codeblock language-python"><code>elif event_type == "session.delegation.created":

        print("\n后台生成失败", backend_event.get("response", {}).get("error"), flush=True)
</code></pre>

<h4 id="配置和观察后台工具">配置和观察后台工具</h4>
<p>通过 <code>session.delegation.responses.tools</code> 声明供后台模型使用的工具。工具定义的格式见 <a href="/zh/model-studio/qwen-api-via-openai-responses">Responses API</a>。自动委派中，服务执行受支持的后台工具并处理结果。应用可监听 <a href="/zh/model-studio/qwen-audio-live-server-events#live-response-event"><code>response.event</code></a> 观察执行情况。收到内层 <code>response.output_item.done</code> 且 <code>event.item.type</code> 为 <code>function_call</code> 时，可从 <code>event.item</code> 读取函数名 <code>name</code>、参数 <code>arguments</code> 和调用 ID <code>call_id</code>。</p>
<p>如果业务系统需要由应用执行和校验，使用 <a href="#live-use-client">Client 模式</a>接收任务，或<a href="#live-call-frontend-functions">在前台声明函数</a>以获取结构化参数。</p>
<h4 id="由应用发起后台生成">由应用发起后台生成</h4>
<p>应用已有完整输入时，可通过 <a href="/zh/model-studio/qwen-audio-live-client-events#live-response-item-create"><code>response.item.create</code></a> 提供文本，再通过 <a href="/zh/model-studio/qwen-audio-live-client-events#live-response-create"><code>response.create</code></a> 发起独立的后台任务。结果从 <code>response.event</code> 读取。</p>
<p>将上述示例另存为 <code>live_responses_text.py</code>。保留 Responses 会话配置，删除 <code>main()</code> 开头读取和校验 PCM 文件的代码。将收到 <code>session.updated</code> 后从 <code>audio +=</code> 开始的音频处理代码替换为下方代码，缩进与 <code>send("session.update", session=session)</code> 一致。保留文件末尾的 <code>main()</code> 调用。</p>
<pre data-tag="codeblock" id="code-block-10" outputclass="language-python" code-type="xCode" class="pre codeblock language-python"><code>send("response.item.create", item={
    "type": "message",
    "role": "user",
    "content": [{"type": "input_text", "text": "单价 327 元，数量 13，计算总价。"}],
})
send("response.create")

deadline = time.monotonic() + REPLY_TIMEOUT_SECONDS
while True:
    event = json.loads(ws.recv(timeout=max(0, deadline - time.monotonic())))
    if event["type"] in ("error", "session.closed"):
        raise RuntimeError(event)
    if event["type"] != "response.event":
        continue

    backend_event = event["event"]
    kind = backend_event["type"]
    if kind == "response.output_text.delta":
        print(backend_event["delta"], end="", flush=True)
    elif kind == "response.completed":
        print()
        break
    elif kind == "response.failed":
        raise RuntimeError(backend_event)

send("session.close")
</code></pre>
<p>运行 <code>python live_responses_text.py</code>。终端应输出后台模型返回的金额。</p>
<h3 id="使用-client-模式接入业务系统">使用 Client 模式接入业务系统 <span id="live-use-client"></span></h3>
<h4 id="接入准备-2">接入准备</h4>
<p>可以先用下方的固定库存结果，验证应用能否把任务结果交给前台模型播报。接入真实库存接口时，应用需要有调用权限，能把用户说的商品名称转换为接口所需的商品 ID，并把查询结果整理成包含商品名称的回复。</p>
<h4 id="配置会话-3">配置会话</h4>
<p>将<a href="#live-first-session">快速开始</a>的原始脚本另存为 <code>live_client.py</code>，用于验证固定结果的回传和播报。保留 <code>delegation</code> 中的 <code>"type": "client"</code>，可将 <code>REPLY_TIMEOUT_SECONDS</code> 设为 30 秒，为任务处理和播报留出时间。在发送 <code>session.update</code> 前为 <code>session</code> 添加以下指令。</p>
<pre data-tag="codeblock" id="code-block-11" outputclass="language-python" code-type="xCode" class="pre codeblock language-python"><code>session["instructions"] = "将库存查询交给应用，收到结果后用语音回复用户。"
seen_delegation_events = set()
</code></pre>
<h4 id="接收任务并准备上下文">接收任务并准备上下文</h4>
<p>收到 <a href="/zh/model-studio/qwen-audio-live-server-events#live-delegation-created"><code>session.delegation.created</code></a> 后，用 <code>event_id</code> 去重，并保存 <code>delegation_id</code>，用于关联后续更新。从 <code>summary</code> 和 <code>context</code>（如有）提取任务信息，再结合应用保存的业务状态准备请求。例如，查库存时，可以用任务里的商品名称和当前门店，找到库存接口所需的商品 ID。</p>
<p>如果用户没说要查哪件商品，先请前台模型追问。收到后续的 <code>session.delegation.created</code> 时，用 <code>delegation_id</code> 关联同一任务。如果事件带有 <code>supplements</code>，可以从中读取补充内容。等查询条件齐全后再执行。</p>
<h4 id="回传进度-补充问题和结果">回传进度、补充问题和结果</h4>
<p>根据要回传的是进度、追问还是结果，选择下表中的事件。发送时填入当前任务的 <code>delegation_id</code>。</p>
<table><thead><tr><th>要回传的内容</th><th>发送的事件</th><th><code>content</code> 示例</th></tr></thead><tbody><tr><td>更新进度，暂不播报</td><td><a href="/zh/model-studio/qwen-audio-live-client-events#live-thinking-append"><code>session.thinking.append</code></a></td><td>正在查询该门店的库存。</td></tr><tr><td>需要向用户追问的条件</td><td><a href="/zh/model-studio/qwen-audio-live-client-events#live-instruction-append"><code>session.instruction.append</code></a></td><td>请询问用户要查询哪件商品。</td></tr><tr><td>要让前台模型播报的结果</td><td><a href="/zh/model-studio/qwen-audio-live-client-events#live-commentary-append"><code>session.commentary.append</code></a></td><td>黑色折叠伞还有七把。</td></tr></tbody></table>
<p>业务调用较慢时，可以在应用后台执行，让主循环继续收发音频和处理事件。核对业务结果后，再把适合播报的内容交给前台模型。</p>
<p>在快速开始的音频接收循环中，紧接在 <code>session.output_transcript.delta</code> 分支后添加以下两个分支。它们复用示例中的 <code>send</code> 函数。</p>
<pre data-tag="codeblock" id="code-block-12" outputclass="language-python" code-type="xCode" class="pre codeblock language-python"><code>elif event_type == "session.delegation.created":
    if event["event_id"] in seen_delegation_events:
        continue
    seen_delegation_events.add(event["event_id"])
    task_id = event["delegation_id"]
    print(f"\n收到任务 {task_id}", flush=True)
    send("session.commentary.append",
         delegation_id=task_id,
         content="黑色折叠伞还有七把。")

    print("\n服务已受理任务结果", flush=True)
</code></pre>
<h4 id="验证任务派发和结果播报">验证任务派发和结果播报</h4>
<p>录下「请查一下黑色折叠伞有没有货」，保存为 <code>client.wav</code>。转换录音并运行脚本。</p>
<pre data-tag="codeblock" id="code-block-13" outputclass="language-bash" code-type="xCode" class="pre codeblock language-bash"><code>ffmpeg -i client.wav -ar 16000 -ac 1 -f s16le client.pcm

<p>先在终端确认应用收到了任务派发，而且服务已受理回传的结果。再打开 <code>reply.wav</code>，听模型是否说出了库存结果。接入真实库存接口后，用查询结果替换示例中的固定结果。</p>
<h3 id="配置和处理前台函数">配置和处理前台函数 <span id="live-call-frontend-functions"></span> <span id="live-function-calling"></span></h3>
<span id="在对话中调用函数"></span>
<p>如果应用的库存查询需要商品名称，可以在 <code>session.tools</code> 中声明一个函数，让前台模型从对话中提取商品名称，再按声明的格式传给应用。将以下字段加入 <code>session.update</code> 的 <code>session</code> 对象，其余会话配置沿用原值。</p>
<pre data-tag="codeblock" id="code-block-14" outputclass="language-json" code-type="xCode" class="pre codeblock language-json"><code>{
  "tools": [
    {
      "type": "function",
      "name": "lookup_stock",
      "description": "查询指定商品的库存数量",
      "parameters": {
        "type": "object",
        "properties": {
          "item": {"type": "string", "description": "商品名称"}
        },
        "required": ["item"]
      }
    }
  ]
}
</code></pre>
<ol>
<li>收到 <a href="/zh/model-studio/qwen-audio-live-server-events#live-session-event"><code>session.event</code></a> 后，读取 <code>event.item</code> 中 <code>type</code> 为 <code>function_call</code> 的调用项。</li>
<li>按 <code>name</code> 找到函数，将 <code>arguments</code> 从 JSON 字符串解析为参数，校验后执行。同一个 <code>call_id</code> 只执行一次。</li>
<li>发送 <a href="/zh/model-studio/qwen-audio-live-client-events#live-item-create"><code>session.item.create</code></a> 回传结果。将 <code>item.type</code> 设为 <code>function_call_output</code>，填入本次调用的 <code>item.call_id</code>。会话级任务的结果仍通过 <code>session.commentary.append</code> 按 <code>delegation_id</code> 回传。</li>
</ol>
<p>在 Client 模式下，前台模型等待函数结果时仍可接收用户语音并回复。应用可继续收发音频和处理事件。需要查询网页或其他实时信息时，可注册搜索服务，或由 Client 模式下的应用调用搜索服务。</p>
<h2 id="从-qwen-audio-realtime-接入">从 Qwen-Audio-Realtime 接入</h2>
