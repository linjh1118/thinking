<p>Evaluate four dimensions to find the right model.</p>
<h3 id="real-time-or-offline">Real-time or offline? <span id="b1a2c3d4e5f08"></span> <span id="b1a2c3d4e5f07"></span></h3>
<p>Real-time recognition returns results as the user speaks. Offline recognition transcribes a pre-recorded file after recording ends.</p>
<ul>
<li>
<p>Real-time recognition streams audio over WebSocket. Choose by use case:</p>
<ul>
<li>Short voice input, such as input methods and voice messages: use <code>qwen-audio-3.1-asr-flash-message</code> for low first-text and overall latency, optional text polishing, and a revised final result when a speech segment ends.</li>
<li>Continuous transcription, such as meetings and classroom notes: use <code>qwen-audio-3.1-asr-flash-streaming</code> when users read results as they arrive and intermediate-result accuracy is a priority.</li>
</ul>
</li>
<li>
<p><strong>Offline (file transcription)</strong>: Uses an HTTP API to submit audio files and retrieve transcription results. Suited for call center recordings, podcasts, and interviews. Recommended model: <code>qwen-audio-3.1-asr-flash-filetrans</code> (hot words, prompt context, speaker diarization).</p>
</li>
</ul>
<p>For client integrations that require stable latency, resilience on weak networks, and full-duplex noise suppression and echo cancellation, see the AOQ protocol comparison and supported models in <a href="/en/model-studio/realtime-api-overview#rtov-s02h2">Realtime API overview</a>.</p>
<p>For HTTP, WebSocket, and SDK integration options, see <a href="/en/model-studio/speech-recognition-api-reference">Speech recognition API reference</a>. Refer to the corresponding SDK documentation for supported models and parameters.</p>
<p>For real-time integration, see <a href="/en/model-studio/real-time-speech-recognition-user-guide">Real-time speech recognition</a>. For offline integration, see <a href="/en/model-studio/non-realtime-speech-recognition-user-guide">Non-real-time speech recognition</a>.</p>
<h3 id="domain-terminology">Domain terminology <span id="b1a2c3d4e5f51"></span> <span id="b1a2c3d4e5f50"></span></h3>
<p>Two approaches, ranked by flexibility:</p>
<ol>
<li><strong>Prompt context injection</strong>: Describe your domain in the system prompt. No setup required—the model adapts per request. Recommended models: <code>qwen-audio-3.1-asr-flash-streaming</code>, <code>qwen-audio-3.1-asr-flash-filetrans</code>, and <code>qwen-audio-3.1-asr-flash</code>.</li>
<li><strong>Hot words</strong>: Supply a weighted vocabulary list. Recommended models: <code>qwen-audio-3.1-asr-flash-streaming</code>, <code>qwen-audio-3.1-asr-flash-filetrans</code>, and <code>qwen-audio-3.1-asr-flash</code>.</li>
</ol>
<p><code>qwen-audio-3.1-asr-flash-message</code> supports instant hot words, precompiled hot words, and conversation context. Set <code>vocabulary</code> or <code>vocabulary_id</code> for hot words, and pass previous user transcriptions and assistant replies through <code>input.context</code>. For parameter definitions, see <a href="/en/model-studio/qwen-asr-message-client-events">Client events</a>.</p>
<h3 id="speaker-diarization">Speaker diarization <span id="b1a2c3d4e5f5b"></span> <span id="b1a2c3d4e5f5a"></span></h3>
<p><code>qwen-audio-3.1-asr-flash</code>, <code>qwen-audio-3.1-asr-flash-filetrans</code>, <code>qwen-audio-3.0-asr-flash-filetrans</code>, and Fun-ASR offline models (<code>fun-asr</code>) support speaker diarization. To identify who said what, use <code>qwen-audio-3.1-asr-flash-filetrans</code>.</p>
<h3 id="emotion-recognition">Emotion recognition <span id="b1a2c3d4e5f5e"></span> <span id="b1a2c3d4e5f5d"></span></h3>
<p>Qwen-ASR models detect emotions alongside transcription. Recommended models: <code>qwen3-asr-flash-realtime</code> (real-time) or <code>qwen3-asr-flash-filetrans</code> (offline).</p>
