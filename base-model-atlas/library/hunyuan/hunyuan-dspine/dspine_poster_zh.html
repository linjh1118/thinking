并行生成也需要一致前缀

独立并行预测的 token 各自可能合理，拼起来却未必相容。目标按前缀核验：一个早期错误会截断后面整段候选。

问题定位

浅层的前几个位置已经有可读出的预测；同样准确的前驱信息，越早进入后继计算越有帮助。

方法定位

DSpine 是依附目标的草稿模型，不独立作答。8B/27B 是目标模型标识，不是草稿的参数量。

目标模型、共享输入 embedding 与 LM head 冻结。草稿在一次前向中并行更新多个位置，因果信息通过网络深度逐层向后传播。

把前驱预测注入每一层

官方图：门控相邻注入、最后条件修正 · 点击看原图
层内消息

前驱与后继共同门控预测特征的残差写入。消息使用共同的更新前快照，保持位置并行。

最终候选选择

用已选前驱 token 修正后继的最后写入；top-K 候选对的转移分数预先缓存，避免顺序矩阵计算。

block-causal attention 防止训练注入的正确 token 反向泄漏。目标核验仍是最终接受机制。

两类监督

这些不是 27B 的训练配方。当前卡缺少足够训练与硬件信息，不能宣称完成复现。

部署前固定所有条件

Python3.11+；官方27B示例为单GPU、最多8请求、BF16、FA3。DSPINE草稿槽16，ReplaySSM与SSM float32 / extra_buffer配置需要匹配。

两个窗口不是一回事

草稿滑窗8,192；目标服务示例context 131,072。后者不代表草稿本身看到131K历史。

SPS 要按负载调

默认verify16只是起点；按GPU、并发、任务与核验预算调表。MLX支持不继承CUDA吞吐成绩。

本次没有下载权重、安装代码或运行服务；硬件最低配置、27B训练配方和真实Agent收益仍待验证。
