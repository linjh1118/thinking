Overview

WeMM-Video is a family of Chinese–English bilingual omni-modal foundation models for joint audio-visual understanding and reasoning. It accepts text, images, audio, and video and generates text responses. For video inputs, it can use the original soundtrack alongside the frames. The family includes 2B, 4B, and 9B dense models and a 35B-A3B mixture-of-experts model.

  • Inference modes. Instruct mode gives fast, direct responses. Thinking mode

supports explicit multi-step reasoning.

  • Training. Trained on approximately 1.2 trillion multimodal tokens through progressive pre-training and multi-stage post-training.

WeMM-Video examples of audio-visual understanding and reasoning, audio and music understanding, and image and text understanding.

Quick Start

Install dependencies

Use a Python 3.12 environment with an NVIDIA GPU, a driver compatible with CUDA 12.9, and FFmpeg. See the host prerequisites for TorchCodec's shared-library requirements. Run from the project root.

bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --index-url https://download.pytorch.org/whl/cu129 \
  torch==2.10.0 torchvision==0.25.0 torchcodec==0.10.0
python -m pip install transformers==5.2.0 accelerate pillow librosa soundfile scipy requests

Load from Hugging Face with Transformers

Run this Python example from the project root. It downloads the 2B BF16 checkpoint and processor from the Hub and reuses them for all five requests. Review the model repository's custom code before enabling trust_remote_code. Set revision to a commit SHA to pin the weights and custom code.

python
import torch
from transformers import AutoModelForImageTextToText, AutoProcessor

model_id = "tencent/WeMM-Video-2B"
revision = "main"
processor = AutoProcessor.from_pretrained(
    model_id, revision=revision, trust_remote_code=True
)
model = AutoModelForImageTextToText.from_pretrained(
    model_id, revision=revision, trust_remote_code=True,
    dtype=torch.bfloat16, device_map="auto",
)


def ask(prompt, *media):
    messages = [{
        "role": "user",
        "content": [*media, {"type": "text", "text": prompt}],
    }]
    inputs = processor.apply_chat_template(
        messages, tokenize=True, return_dict=True, return_tensors="pt",
        add_generation_prompt=True, enable_thinking=False,
    ).to(device=model.device, dtype=model.dtype)
    with torch.inference_mode():
        output = model.generate(**inputs, max_new_tokens=128, do_sample=False)
    answer_ids = output[0, inputs.input_ids.shape[1]:]
    return processor.tokenizer.decode(answer_ids, skip_special_tokens=True)


# Text. The expected answer is 10:05.
print(ask("A meeting starts at 09:30 and lasts 35 minutes. What time does it end?"))

# Image and audio from the Apollo 11 archives.
print(ask("Which planet is shown? Describe what you see.", {
    "type": "image", "image": "examples/media/apollo-11-earth.jpg",
}))
print(ask("Transcribe the English speech in this recording.", {
    "type": "audio", "audio": "examples/media/apollo-11-small-step.wav",
}))

# Use the same MP4 for frames alone or for frames with the original soundtrack.
clip = {
    "video": "examples/media/apollo-11-first-steps.mp4",
}
print(ask("Describe what happens on screen.", {"type": "video", **clip}))
print(ask("Describe the scene and summarize the speech.", {"type": "video_audio", **clip}))

The example uses instruct mode. Set enable_thinking=True in apply_chat_template to enable thinking mode.

To run just the video-with-audio example from the command line, use python examples/transformers_video.py. It accepts --video, --model, and --revision, plus optional --fps, --max-frames, and --total-pixels overrides.

Video sampling and memory

Video examples inherit wemm_defaults from the checkpoint's processor_config.json: fps=2.0, min_frames=4, max_frames=128, total_pixels=25165824, and min_pixels=4096. The serving client inherits the server's configuration and only sends sampling overrides when explicitly requested. The GGUF launcher and native runtime use the same video defaults. max_frames is an upper limit; the actual frame count also depends on clip duration and sampling FPS.

If GPU memory or compute is limited, lower the pixel budget, frame limit, and sampling FPS together. For example, this is a low-resource quick check:

bash
python examples/transformers_video.py --video examples/media/apollo-11-first-steps.mp4 \
  --fps 1 --max-frames 16 --total-pixels 262144

These options also work with examples/chat.py video-audio and native/run_hf.py. Smaller values trade spatial detail and temporal coverage for lower resource use and may miss brief actions or cuts. Increasing frames alone shares the same pixel budget across more frames; per-frame sizing also includes the processor's temporal factor of 2. See the serving guide for server-wide overrides and context-length settings.

Docker

The images contain the serving environment and open Bash by default. With Docker and the NVIDIA Container Toolkit configured, choose one backend below. Both examples use local port 8000. Export HF_TOKEN in the host shell when the checkpoint requires authentication.

Each request can contain up to four images, two videos, and two audio items within the configured context length.

vLLM

bash
docker compose build vllm-018

MODEL=tencent/WeMM-Video-2B
docker run --rm --gpus all --shm-size=8g \
  --publish 127.0.0.1:8000:8000 \
  --mount type=volume,source=wemm-video-hub,target=/root/.cache/huggingface \
  --env HF_TOKEN \
  wemm-video:vllm-0.18.0-cu129 \
  vllm serve "$MODEL" --served-model-name "$MODEL" --trust-remote-code --dtype bfloat16 \
  --host 0.0.0.0 --port 8000 --max-model-len 65536 \
  --no-enable-prefix-caching --mamba-ssm-cache-dtype float32 \
  --limit-mm-per-prompt '{"image":4,"video":2,"audio":2}'

SGLang

bash
docker compose build sglang-0516

MODEL=tencent/WeMM-Video-2B
docker run --rm --gpus all --shm-size=8g \
  --publish 127.0.0.1:8000:8000 \
  --mount type=volume,source=wemm-video-hub,target=/root/.cache/huggingface \
  --env HF_TOKEN \
  wemm-video:sglang-0.5.16-cu129 \
  python -m sglang.launch_server --model-path "$MODEL" --served-model-name "$MODEL" --trust-remote-code \
  --host 0.0.0.0 --port 8000 --dtype bfloat16 --context-length 65536 \
  --attention-backend triton --linear-attn-backend triton \
  --limit-mm-data-per-request '{"image":4,"video":2,"audio":2}'

Send a request

For both patched backends, send a video_url content item to POST /v1/chat/completions. Set video_url.use_audio to true to include the original soundtrack or false for frames only. Omit sampling fields to inherit the server defaults, or place fps, max_frames, and total_pixels inside video_url to override them for a clip. See the full HTTP request example for the Thinking-mode option.

The named volume keeps downloaded weights across container runs. When the server is ready, send the bundled clip from a second terminal in the project root.

bash
curl --fail --silent --show-error http://127.0.0.1:8000/health
python examples/chat.py video-audio --model tencent/WeMM-Video-2B

The examples cover text, images, audio, video, and video with audio.
