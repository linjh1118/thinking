Model Overview

Nemotron-Labs-VisualCreation is an agentic framework for creating expressive raster images and editable visual artifacts, including webpages, presentations, documents, charts, and scientific figures. Its Pixel as Code interface connects learned visual tokens and explicit programs through generation, rendering, and visual inspection.

The framework combines a Nemotron-native harness with specialized components for visual tokenization, autoregressive image generation, and structured visual coding. Nemotron-Labs-Image-30B-A3B is its raster image-generation component. The initial model release covers the image generator and its bundled visual tokenizer.

Pixel as Code unifies learned visual tokens and explicit programs through generation, rendering, and inspection <sub>Figure 1 from the paper. Raster appearance and editable structure share a generation-and-rendering interface.</sub>

Key Design

  • Represent appearance and structure. Discrete visual tokens capture raster

content. SVG, HTML/CSS, plotting programs, and document markup expose editable text, geometry, and layout. Hybrid artifacts combine generated images with explicit structure.

  • Plan for the deliverable. Routing selects the artifact family,

representation, rendering backend, and asset policy. Structured and hybrid requests additionally establish a layout contract.

  • Use rendered evidence. Visual selection chooses among raster candidates.

Browser-based creation uses renderer checks and visual audits to diagnose issues, assign targeted repairs, and retain artifact checkpoints.

Harness Architecture

The Nemotron-native harness routes requests through direct raster generation, browser-based structured or hybrid creation, and native-format generation <sub>Figure 5 from the paper. Route-specific control flow in the Nemotron-native harness.</sub>

Super-VL denotes Nemotron-3.5-Super-VL, Ultra denotes Nemotron 3 Ultra, and Image denotes Nemotron-Labs-Image-30B-A3B.

RouteGeneration and inspectionDeliverable
Direct rasterImage generates candidates. Super-VL performs visual selection.Selected raster image
Browser-based structured / hybridUltra resolves the layout and assets. Ultra and Super-VL act as Dual Coder. Renderer checks, visual audits, and pairwise selection guide bounded repairs.Editable artifact and rendered preview
Native presentation / document / SVGFormat-specific generators and renderers provide inspection and judging.Native artifact

The browser workflow freezes the request checklist and layout contract before generation. Audits assign issues to plan, asset, layout, code, interaction, or content owners. Repairs may regenerate an asset, revise the plan, or update the explicit representation. The default limits allow three accepted repairs within eight attempted cycles, with checkpoint selection retaining the strongest eligible artifact.

Image Model

Nemotron-Labs-Image-30B-A3B provides standalone autoregressive image generation. It uses progressive mid-training followed by GRPO for semantic alignment and image quality. Its visual-token outputs are rendered by the bundled Nemotron-Labs-Image-Tokenizer.

The image tokenizer keeps its internal Transformers model type, l24sq_vit. The external directory name does not change its architecture or weights.

1. Create an environment and install the dependencies

Use Linux with Python 3.12 and an NVIDIA driver compatible with CUDA 13.0. The inference example below uses four NVIDIA H100 80GB GPUs. Check that the GPUs are visible with nvidia-smi before installing the Python packages.

Create a separate environment and install the reference package versions:

python -m pip install --upgrade pip
python -m pip install \
  "torch==2.11.0" \
  "vllm==0.21.0" \
  "transformers==5.23.0" \
  "Pillow==12.3.0" \

  "einops>=0.8,<1" \
  "huggingface_hub>=1,<3"

3. Generate an image from a prompt

The following example generates one 1024×1024 image. Save it as infer.py and run python infer.py. It preserves the model's required chat template, visual-token framing, size header, and L24SQ decoding protocol.

python
import re
from pathlib import Path

import torch
from PIL import Image
from transformers import AutoModel, AutoTokenizer
from vllm import LLM, SamplingParams


MODEL_DIR = Path("./Nemotron-Labs-Image-30B-A3B").resolve()
DECODER_DIR = MODEL_DIR / "Nemotron-Labs-Image-Tokenizer"
OUTPUT_PATH = Path("output.png")

PROMPT = "A cinematic photograph of a red fox in a snowy pine forest at dawn."
WIDTH = 1024
HEIGHT = 1024
PATCH_SIZE = 16

SYSTEM_PROMPT = (
    "Generate an image matching the requested resolution by detailing the color, "
    "quantity, text, shape, size, texture, spatial relationships of the objects "
    "and background."
)


def extract_l24sq_codes(token_ids, tokenizer):
    """Validate one generated image block and return codebook indices."""
    image_start = tokenizer.convert_tokens_to_ids("<|img_start|>")
    image_end = tokenizer.convert_tokens_to_ids("<|img_end|>")
    visual_row = tokenizer.convert_tokens_to_ids("<|vis_row|>")
    vision = tokenizer.unitron_token_ranges["vision"]
    vision_start = int(vision["start_id"])
    vision_end = int(vision["end_id"])

    try:
        start = token_ids.index(image_start)
        end = token_ids.index(image_end, start + 1)
    except ValueError as exc:
        raise RuntimeError("Generation did not contain a complete image block") from exc

    prefix_ids = []
    rows = []
    current_row = None
    for token_id in token_ids[start + 1 : end]:
        if token_id == visual_row:
            if current_row is not None:
                rows.append(current_row)
            current_row = []
        elif vision_start <= token_id < vision_end:
            if current_row is None:
                raise RuntimeError("Visual token appeared before the first row marker")
            current_row.append(token_id - vision_start)
        elif current_row is None:
            prefix_ids.append(token_id)
        else:
            raise RuntimeError("Non-visual token appeared inside the image grid")
    if current_row is not None:
        rows.append(current_row)

    size_header = tokenizer.decode(prefix_ids, skip_special_tokens=False)
    match = re.search(r"height=(\d+)\s+width=(\d+)", size_header)
    if match is None:
        raise RuntimeError("Generation did not contain a valid size header")
    generated_height, generated_width = map(int, match.groups())
    if (generated_height, generated_width) != (HEIGHT, WIDTH):
        raise RuntimeError(
            f"Generated size {(generated_width, generated_height)} does not match "
            f"the requested size {(WIDTH, HEIGHT)}"
        )

    expected_grid = (HEIGHT // PATCH_SIZE, WIDTH // PATCH_SIZE)
    if len(rows) != expected_grid[0] or any(
        len(row) != expected_grid[1] for row in rows
    ):
        raise RuntimeError("Generated visual-token grid has the wrong shape")

    codes = [code for row in rows for code in row]
    return codes, expected_grid


def main():
    tokenizer = AutoTokenizer.from_pretrained(
        str(MODEL_DIR),
        trust_remote_code=True,
    )

    messages = [
        {"role": "system", "content": SYSTEM_PROMPT},
        {
            "role": "user",
            "content": f"Generate a {WIDTH}x{HEIGHT} image.\n\n{PROMPT}",
        },
    ]
    prompt_token_ids = tokenizer.apply_chat_template(
        messages,
        tokenize=True,
        add_generation_prompt=True,
        enable_thinking=False,
        return_tensors=None,
    )

    image_end_id = tokenizer.convert_tokens_to_ids("<|img_end|>")
    sampling = SamplingParams(
        temperature=0.9,
        top_p=1.0,
        top_k=-1,
        max_tokens=4352,
        seed=42,
        n=1,
        skip_special_tokens=False,
        detokenize=True,
        stop=["<|img_end|>"],
        stop_token_ids=[image_end_id],
        include_stop_str_in_output=True,
    )

    generator = LLM(
        model=str(MODEL_DIR),
        tokenizer=str(MODEL_DIR),
        trust_remote_code=True,
        tensor_parallel_size=4,
        moe_backend="triton",
        dtype="bfloat16",
        max_model_len=6144,
        gpu_memory_utilization=0.70,
        enforce_eager=True,
        seed=42,
    )
    result = generator.generate(
        [{"prompt_token_ids": prompt_token_ids}],
        sampling,
        use_tqdm=False,
    )[0]
    generated_token_ids = list(result.outputs[0].token_ids)
    codes, grid_size = extract_l24sq_codes(generated_token_ids, tokenizer)

    decoder = AutoModel.from_pretrained(
        str(DECODER_DIR),
        trust_remote_code=True,
        dtype=torch.bfloat16,
    ).to("cuda:0").eval()

    indices = torch.tensor(codes, dtype=torch.long, device="cuda:0")
    with torch.inference_mode():
        decoded = decoder.pack_decode(
            indices_list=[indices],
            grid_sizes=[grid_size],
        )[0]

    pixels = (
        ((decoded.float().clamp(-1, 1) + 1) / 2 * 255)
        .round()
        .to(torch.uint8)
        .permute(1, 2, 0)
        .cpu()
        .numpy()
    )
    Image.fromarray(pixels).save(OUTPUT_PATH)
    print(f"Saved {OUTPUT_PATH}")


if __name__ == "__main__":
    main()

To change the output resolution, edit WIDTH and HEIGHT near the top of the script. For example, use the following settings for a landscape image:

python
WIDTH = 1184
HEIGHT = 880

The script automatically includes the selected resolution in the generation prompt, validates the resulting visual-token grid, and decodes it at the requested size.

The example selects the Triton MoE backend, matching the validated inference configuration and avoiding FlashInfer MoE extension compilation during startup.

The generator and decoder may be run in separate processes if GPU memory is tight. Preserve the generated token IDs between the two stages.

Image resolutions

The model supports any-resolution image generation. For the best balance of quality, composition, and inference cost, the recommended resolutions are:

  • 1024x1024
  • 1184x880
  • 1248x832
  • 880x1184

Width and height must be positive multiples of 16. For other resolutions, the visual-token grid (WIDTH / 16 × HEIGHT / 16) must fit within max_tokens and the model context window. The recommended resolutions above fit the example's 4,352-token generation budget.

<strong>Limitations</strong>

Limitations

  • This is not a Diffusers pipeline and is not compatible with

AutoPipelineForText2Image.

  • Loading executes repository code through trust_remote_code=True; pin and

review a specific repository revision for controlled deployments.

  • Image generation is stochastic. Composition, anatomy, object counts,

spatial relationships, and rendered text may be incorrect.

  • Generated images can contain biases, false details, or content resembling

people, brands, copyrighted styles, and other training concepts.

  • Users are responsible for reviewing outputs and applying appropriate policy,

privacy, provenance, and content controls.
