Nemotron 3.5 Parse

Description:

Nemotron 3.5 Parse is a document image parser that produces structured, machine-readable text with semantic layout classes, bounding boxes, and reading order. It combines a C-RADIOv4-SO400M vision encoder with a 10-layer mBART decoder that consumes the visual sequence as a causal prefix. The release uses dynamic rectangular NaViT preprocessing, content-normalized coordinates, grouped-query self-attention (16 query heads and 8 key/value heads), a 72,505-token multilingual tokenizer, and chart-aware output through the <class_Chart> token. It is intended for document understanding, information retrieval, data extraction, and multimodal data-curation workflows.

Nemotron 3.5 Parse was developed by NVIDIA as a part of Nemotron.

This model is ready for commercial or non-commercial use.

Use Case:

Nemotron 3.5 Parse is designed for developers and teams building document intelligence, retrieval-augmented generation (RAG), curator, extractor, and agentic AI applications. It can convert scanned or rendered PDFs, presentation slides, forms, reports, tables, and mixed-content document pages into structured outputs for downstream indexing, retrieval, analytics, model training-data creation, and human-in-the-loop review.

Model Architecture:

Architecture Type: Transformer

Network Architecture:

  • Vision Encoder: NVIDIA C-RADIOv4-SO400M (vit_so400m_patch16_224) with dynamic rectangular NaViT preprocessing
  • Adapter Layer: 1D convolutions and normalization layers that compress the vision latent sequence before decoding
  • Decoder: 10-layer mBART causal visual-prefix decoder with 16 query heads and 8 key/value heads
  • Auxiliary Prediction Head: One trained one-step multi-token-prediction (MTP) head is included in model.safetensors. Transformers uses the normal decoder for generation; the vLLM plugin enables the bundled head for one-token speculative decoding.
  • Tokenizer: 72,505 entries with multilingual and task/control tokens including `, , , and <class_Chart>`; the decoder embedding is padded to 72,512 rows. Use of the tokenizer included in this model is governed by the MIT license and tokenizer attribution.
  • Number of Parameters: 630,800,496 unique trainable parameters (approximately 0.631B), including the MTP head; shared decoder embedding/output weights are counted once

Quick Start

Transformers installation

Use Python 3.12 and a fresh environment:

bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install "transformers==5.14.1" "torchvision==0.26.0" "timm==1.0.22"

Run hf auth login if repository access requires authentication. Transformers downloads the model weights, processor, and custom model code automatically. No Nemotron package installation is needed for Transformers inference.

Usage example

python
import torch
from PIL import Image
from transformers import AutoModel, AutoProcessor, GenerationConfig

model_path = "nvidia/Nemotron-3.5-Parse"
device = "cuda:0"

model = AutoModel.from_pretrained(
    model_path,
    trust_remote_code=True,
    dtype=torch.bfloat16
).to(device).eval()
processor = AutoProcessor.from_pretrained(model_path, trust_remote_code=True)

image = Image.open("path/to/your/image.jpg").convert("RGB")
task_prompt = "</s><s><output_markdown>"

inputs = processor(images=[image], text=task_prompt, return_tensors="pt", add_special_tokens=False).to(device)

generation_config = GenerationConfig.from_pretrained(model_path)
generation_config.max_new_tokens = 8744

with torch.inference_mode():
    outputs = model.generate(**inputs, generation_config=generation_config)

generated_text = processor.batch_decode(outputs, skip_special_tokens=False)[0]
print(generated_text)

Postprocessing

The shared helpers render a complete document as Markdown with HTML tables, and return structured blocks with normalized boxes and optional pixel boxes. They preserve model reading order, table spans, blank cells, and in-cell line breaks. They also decode rich table formatting, remove literal duplicate elements, repair empty serialization prefixes, and normalize existing list bullets and discretionary soft hyphens in text. Code and math are protected from typography cleanup.

Download the helpers and their shared implementation into your working directory (no Nemotron package installation is needed for this path):

bash
python -m pip install "beautifulsoup4==4.13.3"
hf download nvidia/Nemotron-3.5-Parse \
  --include 'postprocessing.py' 'latex2html.py' 'nemotron_parse/**' --local-dir .

Continue from the Transformers example above:

python
from pathlib import Path
from PIL import ImageDraw
from postprocessing import postprocess_document

document = postprocess_document(generated_text, image_size=image.size)
Path("prediction.md").write_text(document["markdown"], encoding="utf-8")
draw = ImageDraw.Draw(image)
for block in document["blocks"]:
    draw.rectangle(block["bbox_pixels"], outline="red", width=2)
image.save("prediction.png")

The existing extract_classes_bboxes, transform_bbox_to_original, and postprocess_text functions remain available. Supported table_format values: latex | HTML | markdown | json | json_hierarchical | csv. HTML and hierarchical JSON retain merged-cell structure; flat Markdown, CSV, and record JSON flatten spans. Headerless tables use neutral column names in flat exports, retaining every data row.

Explicit chart titles, subtitles, and panel labels are preserved with their tables. Header inference uses predicted spans and existing bold markup; it can be disabled. Numeric value/percentage column splitting and geometric chart-caption association are enabled by default. Both preserve existing predicted values/text and can be disabled. See postprocessing examples for controls and examples.

Inference with vLLM

vLLM requires the Nemotron plugin for this architecture and its MTP head. In a fresh Python 3.12 environment, download the repository and install the serving extras:

bash
python -m pip install "huggingface-hub==1.24.0"
hf download nvidia/Nemotron-3.5-Parse --local-dir nemotron-parse
cd nemotron-parse
python -m pip install ".[vllm,client]"

One-token MTP and the compatible FA3 scheduler are enabled automatically.

vLLM Inference example

Option 1: Python inference with MTP

python
from PIL import Image
from vllm import LLM, SamplingParams

def main():
    llm = LLM(
        model=".",
        dtype="bfloat16",
        trust_remote_code=True,
        distributed_executor_backend="uni",
        max_model_len=16384,
        max_num_seqs=64,
        max_num_batched_tokens=16384,
        limit_mm_per_prompt={"image": 1},
        enable_prefix_caching=False,
        attention_config={"flash_attn_version": 3},
    )
    sampling_params = SamplingParams(
        temperature=0,
        top_k=1,
        repetition_penalty=1.1,
        max_tokens=8744,
        skip_special_tokens=False,
    )
    image = Image.open("<YOUR-IMAGE-PATH>").convert("RGB")
    outputs = llm.generate([{
        "prompt": "\n</s><s><output_markdown>",
        "multi_modal_data": {"image": image},
    }], sampling_params, tokenization_kwargs={"add_special_tokens": False})
    print(outputs[0].outputs[0].text)

if __name__ == "__main__":
    main()

The offline prompt includes the image placeholder ``. Automatic special tokens are disabled because the task prompt already contains its control tokens.

    model="nemotron-parse",

            "role": "user",

                {
                    "type": "text",
                    "text": prompt_text,
                },
                {
                    "type": "image_url",
                    "image_url": {
                        "url": f"data:image/png;base64,{img_b64}",
                    },
                },
            ],
        }
    ],
    max_tokens=8744,
    temperature=0.0,
    extra_body={
        "repetition_penalty": 1.1,
        "top_k": 1,
        "skip_special_tokens": False,
    },
)
print(resp.choices[0].message.content)

Evaluation Results

ParseBench

  • Single pass: parse the full page once.
  • Double pass: parse the page, then refine Table/Chart crops selected from its predictions.
  • Triple pass: add a separate detection request and refine the union of detector and parser regions. Full-page parsing and detection can overlap.

On ParseBench, double pass gains 2.18 overall points over single pass. Triple pass adds 0.28 points over double pass at about 9% lower throughput. Double pass captures most of the measured accuracy gain; the table shows the speed tradeoff.
