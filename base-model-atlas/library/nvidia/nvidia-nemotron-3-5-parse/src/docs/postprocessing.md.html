Document postprocessing and multipass parsing

The public helpers operate on model predictions and ordinary page images. They do not load benchmark labels, scorer code, category IDs, reference answers, or page-specific rules. They are adapted from the general conversion and crop-merge components of the bundled ParseBench pipeline. The pinned reproduction bundle remains unchanged so its recorded hashes and results stay reproducible.

Installation

For vLLM, use the model card's repository-source installation:

bash
hf download nvidia/Nemotron-3.5-Parse --local-dir nemotron-parse
cd nemotron-parse
python -m pip install '.[vllm,client]'

This installs the plugin, public nemotron_parse Python package, compatibility modules, and nemotron-parse command. No prebuilt wheel is required. The repository source installs the vLLM plugin, parsing helpers and CLI together. Archived release artifacts and their digests are listed in the build evidence. Use version 3.5.0.post5 or later for the restored merge default and post7 or later for the corrected third-party notices.

For Transformers, keep the model card's inference dependencies. To download the helpers without installing the package:

bash
python -m pip install 'beautifulsoup4==4.13.3' 'Pillow==12.2.0' 'numpy==2.2.6' 'httpx==0.28.1'
hf download nvidia/Nemotron-3.5-Parse \
  --include 'postprocessing.py' 'latex2html.py' 'nemotron_parse/**' --local-dir .

Run Python in that directory, or put it on your Python import path. Basic text/table postprocessing only needs Beautiful Soup; the image wrappers also need Pillow and NumPy. The HTTP backend needs httpx. Downloaded source and installed packages provide the same public API.

Render an existing prediction

python
from nemotron_parse import postprocess_document, PostprocessOptions

options = PostprocessOptions(
    infer_headers=True,
    render_charts=True,
    split_chart_value_percent=True,
    relocate_chart_captions=True,
)
document = postprocess_document(raw_model_output, image_size=(width, height), options=options)
print(document['markdown'])
print(document['blocks'])

raw_out contains the cleaned model serialization. Each block has its original class, normalized bbox, literal text, and rendered content. Supplying image_size adds clipped, ordered bbox_pixels. markdown renders the complete page in model order, with section headings and HTML tables for span preservation. Raw per-block text remains available independently of presentation changes. Malformed table markup that cannot be converted is preserved rather than passed through a lossy row splitter; document warnings identify these blocks.

Default cleanup preserves empty cells, spans, line breaks, nested inline styles, and escaped literals. It removes exact repeated blocks at identical coordinates, repairs empty incomplete serialization prefixes, removes internal continuation markers, and normalizes existing bullets and soft hyphens in textual roles. Code/math roles and marked code/math text are protected from soft-hyphen cleanup. Table conversion is applied to Table/Chart blocks; literal LaTeX in prose, code, formulas, or Picture blocks retains its source representation. Header inference uses predicted span topology and existing bold styling, never an English vocabulary list. It can still make mistakes; disable infer_headers to use only explicit predicted headers. Unknown classes and page numbers are retained.

Chart titles, subtitles, and explicit panel labels can be rendered with their associated tables. Two guarded presentation choices are enabled by default and can be disabled:

  • split_chart_value_percent=True splits consistently predicted numeric pairs

such as 32 (16.6%) into Value and Percent subcolumns. It requires at least two matching nonempty cells, adds those column labels, and does not calculate values.

  • relocate_chart_captions=True associates a plain caption immediately above a

chart when geometry and text-preservation checks pass. Notes below remain standalone. Set relocate_chart_captions=False to retain the standalone caption in its source order.

normalize_text=False, deduplicate=False, and render_charts=False disable the corresponding cleanup/rendering choices. The existing root imports continue to work:

python
from postprocessing import extract_classes_bboxes, postprocess_text
from latex2html import convert_html_table_to_json_hierarchical

postprocess_text(..., cls='Table', table_format=...) supports LaTeX, HTML, Markdown, record JSON, hierarchical JSON, and CSV. HTML retains merged-cell structure. Flat exports expand spans and use neutral column names for headerless tables without consuming the first data row as a header. Duplicate column names are disambiguated without overwriting values. Hierarchical JSON retains the existing headers, columns, and flat data fields and additionally exposes body_cells with explicit text, span, and header-role metadata.

Parse a page with a running vLLM server

Start the server using the model card. Then:

python
from nemotron_parse.inference import DocumentParser

with DocumentParser(base_url='http://localhost:8000/v1', model='nemotron-parse') as parser:
    single = parser.parse('page.png')
    double = parser.parse_double('page.png')
    triple = parser.parse_triple('page.png', triple_regions='union')
    documents = parser.parse_many(['one.png', 'two.png'], mode='double', concurrency=128)
ModeWork performed
SingleFull-page parse and document rendering
DoubleFull-page parse, then Table/Chart crops from its predicted regions
TripleFull-page parse, separate detection, then Table/Chart crop parsing

A pass denotes a stage, not one request: each retained crop needs its own model call. triple_regions='union' retains detector regions first and adds parser regions after overlap filtering; 'detector' uses only the separate detector. The region budget defaults to 80 per page and can be changed with max_regions. Crops use 4% plus 12-pixel margins and JPEG quality 95, configurable margins, and content-normalized coordinates mapped back to the original image. Tiny crops are skipped. Crops are made in memory and no temporary image files remain.

The default merge_policy="alternatives" preserves differing overlapping Table/Chart predictions from the full-page and crop passes. Near-identical blocks are deduplicated using geometry and text. Guarded table refinement checks native grid validity and compatible column counts; the original block order is preserved and crop alternatives are inserted by their predicted geometry. This policy matches the reference approach using only model predictions, without labels, benchmark categories or scorer feedback.

A returned document can contain overlapping or conflicting Table/Chart hypotheses. Use DocumentParser(merge_policy="guarded") (CLI: --merge-policy guarded) when one selected prediction per overlapping same-class region is preferable. This option applies conservative structural replacement and rejects overlapping same-class additions. It can discard a correct alternative, reducing recall. Raw stage responses remain available with either policy.

Returned results include stages with original raw responses and usage, and inference with request counts, regions, sampling, and crop/rendering settings. Empty, failed, filtered, or token-limited generations raise GenerationError; its stage and response expose the failed response. Successful stage responses from the same page are only returned when parsing completes. No automatic retry policy changes the request settings.

Sampling is configurable per stage:

python
from nemotron_parse.inference import DocumentParser, GenerationSettings

with DocumentParser(
    fullpage=GenerationSettings(temperature=0, top_k=1, repetition_penalty=1.1),
    detection=GenerationSettings(temperature=0, top_k=1, max_tokens=4096),
    crop=GenerationSettings(temperature=0, top_k=1, repetition_penalty=1.0),
) as parser:
    document = parser.parse_double('page.png')

Defaults are temperature 0.2 / repetition penalty 1.05 for full-page and detection, and 0.1 / 1.0 for crops, top-k 50, top-p 1.0, seed 0. Token caps are 8,744 for parsing and 4,096 for detection. These are practical starting settings rather than a claim of optimal sampling for every document type.

Use an already loaded Transformers model

Continue from the model card's Transformers setup:

python
from nemotron_parse.inference import DocumentParser, TransformersBackend

backend = TransformersBackend(model, processor, generation_config=generation_config)
with DocumentParser(backend=backend) as parser:
    document = parser.parse_triple(image)

This uses the same image/crop orchestration without a server or plugin. The adapter serializes calls to the shared model, uses inference mode, applies stage settings, and restores the CPU/current-GPU RNG after generation. Model weights and processor remain caller-owned. Reaching the token cap is conservatively reported as truncation, including when generation forces an EOS at the cap.

Other inference implementations can supply a callable backend(image, *, prompt, stage, settings) returning {'raw_out': text, 'finish_reason': 'stop', 'usage': {...}}. A string return is also accepted, but then the custom backend must detect truncation itself. Custom backends used with parse_many should support concurrent calls or use concurrency 1.

Command line

bash
nemotron-parse --image page.png --mode double --output parsed-page
nemotron-parse --image-dir pages --mode triple --triple-regions union --output parsed-pages

The download-only equivalent is python -m nemotron_parse.inference with the same arguments. The default outputs are compact documents.jsonl.gz and metrics.json, containing blocks, raw stages, settings and timing. Add --write-page-files for individual Markdown and JSON exports. Use a new/empty output directory. Files are written only after all pages complete. The API accepts PIL images and image paths; the CLI accepts image files. Render PDF pages to images before calling it.

Prepared batches and timing

parser.prepare(images, workers=8) returns a reusable in-memory batch containing decoded RGB pixels and encoded image requests. Existing RGB JPEG/PNG/WebP payloads are retained without another lossy encode. Other inputs are encoded as PNG. The preparation time is reported separately, and cached images can occupy several GB for thousands of document pages.

parser.parse_prepared(batch, mode="double", concurrency=128, postprocess_workers=8) returns a BatchResult with documents and metrics. The default schedule="pipelined" overlaps independent full-page and detection requests, submits detector crops as soon as their regions are ready, and adds parser-only regions in the original union order. Double-pass crops similarly start as each page finishes its full-page request. Ready crops take the next available HTTP slot, and new pages fill remaining slots. All stages share one bounded concurrency window, including requests waiting inside vLLM. Crop preparation uses separate CPU threads; finished pages merge and render while other pages continue inference. Large batches use spawned rendering processes.

Run standalone scripts under a main guard, or choose postprocess_workers=1. HTTP parse_many uses this same pipelined batch engine and returns only the documents. Its default request window is 128; a custom backend retains the four-worker default. Pass concurrency=1 for a backend that requires serial calls. Use schedule="staged" for stage-barrier comparisons. A custom Transformers backend still serializes its shared model calls.

Metrics include separately reported initial preparation, pipeline elapsed time, request counts, token-limit counts, and processed-page and fully completed-page throughput. Pipeline time excludes initial preparation and output-file writing; model-dependent crop preparation is included. A benchmark should also report serialization and warmup/server-startup exclusions explicitly. The same prepared batch can be reused for different modes; each call generates its own responses and provides an independent pipeline timing. Pipelined stage spans overlap and must not be added together. request_service_seconds sums concurrent request latency, including server queue wait; it is not GPU compute time. peak_inflight_requests records the client window, while actual server running/waiting requests require vLLM metrics.

Strict generation handling remains the default. Set allow_partial=True (CLI: --allow-partial) only when partial results are useful: capped raw responses are preserved, affected pages have complete=False and generation_warnings, and truncated crops are excluded from refinement. HTTP/transport errors and empty responses still raise. A successful benchmark execution does not imply that every page completed within its token limit; inspect both coverage and throughput.

The CLI supports --no-split-chart-value-percent and --no-relocate-chart-captions to disable the default presentation rules.

Inference throughput with prepared pages

For prediction throughput, use result.metrics["inference_pages_per_second"] (package 3.5.0.post6 or later). Its wall clock runs from the first model request start to the last model response across all passes. It includes server queueing, image encoding inside the server, generation, HTTP transfer and any gaps waiting for predicted-region selection, crop encoding or dispatch. It excludes initial page preparation, startup/warmup, final merge/rendering after inference, and writes. pipeline_seconds and processed_pages_per_second retain their earlier meanings, including merge/rendering, for applications that need complete documents. Concurrent rendering can still compete for CPU during inference; that observed contention remains in the wall time. We do not subtract overlapping CPU time or sum concurrent request latencies to claim a higher rate.

This is realistic batch prediction throughput when pages are prepared ahead of time and enough work is queued. It is not PDF ingestion throughput or single-page latency, and is not a measured hardware ceiling. Document complexity, generation length, crop count, CPU capacity, network placement and batching affect speed. The numerator includes token-limited pages; these diagnostic runs explicitly allow partial output. Use complete_inference_pages_per_second for the number of fully completed pages divided by the same wall time. Strict errors remain the default outside these diagnostic runs.

python

result = parser.parse_prepared(
    prepared, mode="triple", concurrency=128, postprocess_workers=8,
)
print(result.metrics["inference_seconds"])
print(result.metrics["inference_pages_per_second"])

For double pass, use mode="double", concurrency=256.
