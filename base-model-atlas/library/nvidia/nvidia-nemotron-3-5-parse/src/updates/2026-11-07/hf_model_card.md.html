Nemotron 3.5 Parse

Turn document pages into structured information. Nemotron 3.5 Parse extracts text, tables, chart data, reading order, semantic classes, and bounding boxes from page images. Use it on scans, rendered PDFs, slides, forms, reports, and mixed document layouts; export the results as Markdown, HTML, or structured JSON.

Full-page predictions on synthetic documents. Static preview · All examples.

  • Leading ParseBench accuracy: 75.20 with triple-pass parsing, the highest

overall score among the systems in our reported comparison.

  • Broad multilingual OCR: evaluated across **163 language/script entries in

26 script groups**, plus 10 Indic languages. See language results.

  • Small and fast: 0.631B parameters, with an optional **89.3M-parameter

DFlash2 drafter**. See throughput measurements for the hardware, concurrency, and parsing mode behind each result.

New — November 4, 2026: Native DFlash2 speculative decoding is available in dflash2/, in the same repository as the target model.

One H200, BF16, 2,078 pages, median of three runs, using the best tested native draft length at each concurrency. See the benchmark protocol and data. This direct-engine, greedy benchmark is separate from the HTTP pass-mode timings.

Run Parse

Transformers

Use a fresh Python environment:

bash
python -m venv .venv
source .venv/bin/activate
python -m pip install transformers torchvision timm
python
import torch
from PIL import Image
from transformers import AutoModel, AutoProcessor, GenerationConfig

MODEL = "nvidia/Nemotron-3.5-Parse"
TASK_PROMPT = "</s><s><output_markdown>"

model = AutoModel.from_pretrained(
    MODEL, trust_remote_code=True, dtype=torch.bfloat16,
).to("cuda").eval()
processor = AutoProcessor.from_pretrained(MODEL, trust_remote_code=True)
image = Image.open("page.png").convert("RGB")
inputs = processor(
    images=[image], text=TASK_PROMPT,
    return_tensors="pt", add_special_tokens=False,
).to("cuda")
generation = GenerationConfig.from_pretrained(MODEL)
generation.max_new_tokens = 8744

with torch.inference_mode():
    output_ids = model.generate(**inputs, generation_config=generation)
raw_output = processor.batch_decode(output_ids, skip_special_tokens=False)[0]
print(raw_output)

Keep the control tokens in raw_output for postprocessing. Transformers uses the normal decoder; the speculative-decoding options below are for vLLM.

vLLM

Use vLLM with native Parse and DFlash2 support. The included speculator speeds up token generation:

Download the target and drafter together and start a server:

bash
hf download nvidia/Nemotron-3.5-Parse --local-dir ./parse35

vllm serve ./parse35 \
  --served-model-name nemotron-parse \
  --trust-remote-code \
  --speculative-config '{"method":"dflash","model":"./parse35/dflash2","num_speculative_tokens":32}'

Send one RGB page through the OpenAI-compatible API (pip install openai):

python
import base64
from openai import OpenAI

TASK_PROMPT = "</s><s><output_markdown>"
with open("page.png", "rb") as f:
    image_b64 = base64.b64encode(f.read()).decode()
client = OpenAI(base_url="http://localhost:8000/v1", api_key="EMPTY")
response = client.chat.completions.create(
    model="nemotron-parse",
    messages=[{"role": "user", "content": [
        {"type": "text", "text": TASK_PROMPT},
        {"type": "image_url", "image_url": {"url": "data:image/png;base64," + image_b64}},
    ]}],
    temperature=0, max_tokens=8744,
    extra_body={"top_k": 1, "repetition_penalty": 1.1, "skip_special_tokens": False},
)
raw_output = response.choices[0].message.content
print(raw_output)

The text content is the task prompt only. vLLM handles the image placeholder; do not manually prepend `` or a newline to this HTTP request.

Offline vLLM: use the same task tokens without an extra newline

For offline LLM.generate, put one image placeholder directly before the task prompt, without an intervening newline:

python
request = {
    "prompt": "" + TASK_PROMPT,
    "multi_modal_data": {"image": image},
}
outputs = llm.generate(
    [request], sampling_params,
    tokenization_kwargs={"add_special_tokens": False},
)

Here llm is an initialized vllm.LLM, image is a PIL RGB image, and sampling_params is your SamplingParams. Transformers and HTTP requests use the task prompt without a manually inserted image placeholder.

PDF input

The model consumes page images. Render each PDF page first; for example, with pip install pymupdf:

python
import pymupdf
from pathlib import Path

pages = Path("pages")
pages.mkdir(exist_ok=True)
page_paths = []
with pymupdf.open("document.pdf") as pdf:
    for number, page in enumerate(pdf):
        pix = page.get_pixmap(dpi=150, colorspace=pymupdf.csRGB, alpha=False)
        path = pages / f"page-{number:04d}.png"
        pix.save(str(path))
        page_paths.append(str(path))

Pass page_paths to parse_many below. Each result corresponds to one page; combine their Markdown if desired. The helper does not infer cross-page table continuations or a document-wide reading order.

Single, double, or triple pass

Pass count controls how much image analysis is performed. A speculator accelerates token generation within those requests; it does not select the pass count.

ModeWhat it doesReported ParseBench overallDFlash2 pages/s
SingleParse the full page once72.7418.57
DoubleParse the page, then refine predicted Table/Chart crops74.9214.60
TripleAlso detect regions separately; refine the detector/parser union75.2013.49

Single pass sends the whole page once and extracts its text, layout, tables and chart data. Start here when throughput is the priority.

Double pass uses the full-page prediction to locate tables and charts, parses those cropped regions at higher detail, and merges the refinements back into the page. Crops start as each page's first result becomes available.

Triple pass starts full-page parsing and independent layout detection together. It refines the union of their table/chart regions, including regions that either request missed. Ready crops run while other pages and stages are still in flight. Each retained crop is a separate request; a pass is a stage, rather than a fixed count of three requests.

Timing uses one H200 and all 2,078 ParseBench pages; median of three fresh runs per mode at its best tested serving configuration. See profiles, completion coverage and timing details. Scores are the existing reference-protocol results, separate from these DFlash2 timing runs. See the accuracy reproduction instructions.

The downloaded repository includes the parser helpers. Install their dependencies and make the downloaded source importable, without installing the serving plugin:

bash
python -m pip install beautifulsoup4 Pillow numpy httpx

With the server above running:

python
import sys
sys.path.insert(0, "./parse35")
from nemotron_parse.inference import DocumentParser

def main():
    with DocumentParser(
        base_url="http://localhost:8000/v1", model="nemotron-parse",
    ) as parser:
        documents = parser.parse_many(
            ["page.png"], mode="single", concurrency=128,
            triple_regions="union",  # used when mode="triple"
        )
    print(documents[0]["markdown"])
    print(documents[0]["blocks"])

if __name__ == "__main__":
    main()

parse_many uses the overlapping HTTP pipeline. In triple pass, parsing and detection run together, and crops are dispatched as their regions become ready.

By default, crop merging preserves differing full-page/crop alternatives. Returned documents can therefore contain overlapping table/chart hypotheses. Use DocumentParser(merge_policy="guarded") when you prefer conservative replacement and a single selected hypothesis, accepting the documented accuracy tradeoff. See batch parsing, crop settings, completion handling, and Transformers backends.

Task prompts

Parse uses control-token task prompts rather than a general-purpose chat instruction. The default is:

python
TASK_PROMPT = "</s><s><output_markdown>"

Keep token order and spelling unchanged. Disable automatic special-token insertion when tokenizing this complete prefix.

Tables and postprocessing

The model returns a serialization containing class and coordinate tokens. The helpers turn it into a complete document and preserve the original block text:

For Transformers-only use, download the helper source into the same local layout used by the vLLM example:

bash
python -m pip install beautifulsoup4 Pillow numpy httpx
hf download nvidia/Nemotron-3.5-Parse \
  --include 'postprocessing.py' 'latex2html.py' 'nemotron_parse/**' \
  --local-dir ./parse35
python
import sys
from pathlib import Path
from PIL import Image
sys.path.insert(0, "./parse35")
from nemotron_parse import postprocess_document, PostprocessOptions

image = Image.open("page.png").convert("RGB")
document = postprocess_document(raw_output, image_size=image.size)
Path("page.md").write_text(document["markdown"], encoding="utf-8")
print(document["blocks"])  # class, bbox, bbox_pixels, text, rendered content

image_size is (width, height). Boxes are normalized to the evaluated image content; bbox_pixels maps them back to pixels. Preserve class and coordinate tokens when generating and decoding. Document Markdown uses HTML tables so merged cells survive rendering. Raw per-block text remains available separately.

Convert a predicted table without running inference again:

python
from postprocessing import postprocess_text

table = next(block for block in document["blocks"] if block["class"] == "Table")
print(postprocess_text(table["text"], cls="Table", table_format="csv"))
print(postprocess_text(table["text"], cls="Table", table_format="json_hierarchical"))
FormatUse it for
HTMLRendering tables while preserving merged cells
json_hierarchicalStructure with cell spans and header-role metadata
markdown, csv, jsonFlat exports; merged-cell spans are expanded
latexThe predicted table's LaTeX representation

Cleanup retains blank cells, spans, line breaks, model order, and predicted values. Header inference can be disabled, as can chart-caption association and numeric value/percentage splitting:

python
options = PostprocessOptions(
    infer_headers=False,
    relocate_chart_captions=False,
    split_chart_value_percent=False,
)
document = postprocess_document(raw_output, image_size=image.size, options=options)

Model details and terms

Description, architecture, inputs, outputs, and runtime details

Description:

Nemotron 3.5 Parse is a document image parser that produces structured, machine-readable text with semantic layout classes, bounding boxes, and reading order. It combines a C-RADIOv4-SO400M vision encoder with a 10-layer mBART decoder that consumes the visual sequence as a causal prefix. The release uses dynamic rectangular NaViT preprocessing, content-normalized coordinates, grouped-query self-attention (16 query heads and 8 key/value heads), a 72,505-token multilingual tokenizer, and chart-aware output through the <class_Chart> token. It is intended for document understanding, information retrieval, data extraction, and multimodal data-curation workflows.

Nemotron 3.5 Parse was developed by NVIDIA as a part of Nemotron.

This model is ready for commercial or non-commercial use.

Model Architecture:

Architecture Type: Transformer

Network Architecture:

  • Vision Encoder: NVIDIA C-RADIOv4-SO400M (vit_so400m_patch16_224) with dynamic rectangular NaViT preprocessing
  • Adapter Layer: 1D convolutions and normalization layers that compress the vision latent sequence before decoding
  • Decoder: 10-layer mBART causal visual-prefix decoder with 16 query heads and 8 key/value heads
  • Auxiliary Prediction Head: One trained one-step multi-token-prediction (MTP) head is included in model.safetensors. Transformers uses the normal decoder for generation; the vLLM plugin enables the bundled head for one-token speculative decoding.
  • Tokenizer: 72,505 entries with multilingual and task/control tokens including `, , , and <class_Chart>`; the decoder embedding is padded to 72,512 rows. Use of the tokenizer included in this model is governed by the MIT license and tokenizer attribution.
  • Number of Parameters: 630,800,496 unique trainable parameters (approximately 0.631B), including the MTP head; shared decoder embedding/output weights are counted once

Input(s):

Input Type(s): Image, Text

Input Format(s):

  • Image: Red, Green, Blue (RGB)
  • Text: Prompt string

Input Parameters:

  • Image: Two-Dimensional (2D)
  • Text: One-Dimensional (1D)

Other Properties Related to Input:

  • Recommended maximum input resolution (Width, Height): 1664, 2048
  • Channel Count: 3
  • Prompt format: one task prompt composed from the supported control tokens. The default prompt extracts bounding boxes, semantic classes, and text in markdown format: </s><s><output_markdown>.

Output(s):

Output Type(s): Text

Output Format(s): String

Output Parameters: One-Dimensional (1D)

Other Properties Related to Output: Nemotron 3.5 Parse returns a string encoding document text, semantic element classes, and content-normalized bounding boxes. Scale x coordinates by the evaluated image width and y coordinates by its height. Postprocessing utilities can convert table or chart-associated text into LaTeX, HTML, markdown, JSON, or CSV where supported.
