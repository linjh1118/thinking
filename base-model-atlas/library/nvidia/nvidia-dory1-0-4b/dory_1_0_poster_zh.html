问题与定位：看清family与证据

Dory把每个token的计算深度变成可调旋钮。Input→共享Recurrent多轮→Output；每轮重注入输入。同一权重可跑1、2、4轮，不等于换三个checkpoint。

共享权重≠共享所有状态

标准循环可能为每轮保留KV。last-loop降低循环层缓存，但质量仅称接近，缺少完整逐任务与方差表，不写无损。

资料深度尚未达标

原卡和图不足完整报告级拆解，达不到GLM/Kimi标准；专属Tech Report/Blog未核实，4份安全子卡404，不能编造训练细节。

预训练与精度

6T tokens前约4.5T原生NVFP4，剩余BF16；不是全程4bit。之后300B做256K上下文扩展。

数据筛选与SFT

curated合成和多源数据、结构/重复过滤、compiler与数值验证。混合比例和loop训练分布未完整披露。

多环境异步GRPO

NeMo RL/Gym覆盖数学、代码、工具和多轮；训练推理解耦。reward/KL/rollout超参不从通用框架猜。

方法与边界：公开什么、缺什么

nGPT、局部与全注意力交错。per-loop KV随循环增大；last-loop只保留循环层最后一轮缓存，不代表全模型没有KV或计算不增加。

官方AA v4.3.2内部估计，非AA官方认证
图注与配置两种层口径

图注8/20/8个block；配置16/40/16个attention或MLP条目，共72。不能直接相乘当FLOPs。

推理框架仍有版本边界

vLLM支持在PR60149；llama.cpp在PR30306。锁定模型、代码revision与parser，不能认为任意正式版本都支持。

研读抽象：非官方完整前向公式
$$\begin{gathered}h^{(0)}=I(x)\\h^{(\ell+1)}=R(h^{(\ell)},x)\\y=O(h^{(L)})\end{gathered}$$
显式输出与潜计算分开

循环更多通常输出token更少，但每token计算更重。需要量实际端到端延迟，不能只计tokens/s。

固定六格实验

loops1/2/4×两种KV，锁定精度/服务/预算；测终态成功、无效工具、token、延迟与峰值显存，再单独测试量化。
