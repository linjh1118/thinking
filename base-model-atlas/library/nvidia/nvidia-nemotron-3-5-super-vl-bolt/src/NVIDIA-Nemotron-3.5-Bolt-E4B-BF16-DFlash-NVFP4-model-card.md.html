Model Overview

Description:

The NVIDIA-Nemotron-3.5-Bolt-E4B-DFlash model is the DFlash speculative decoding draft checkpoint for NVIDIA-Nemotron-3.5-Bolt-E4B, a reasoning language model post-trained by NVIDIA from Google's Gemma 4 E4B IT. For more information, please check Nemotron-3.5-Bolt-E4B-BF16. The NVIDIA-Nemotron-3.5-Bolt-E4B-DFlash model incorporates DFlash speculative decoding with NVIDIA Model Optimizer and is intended for lower-latency serving of NVIDIA-Nemotron-3.5-Bolt-E4B on data centre and workstation GPUs.

This repository provides the draft model quantized to NVFP4 (4-bit floating point) with NVIDIA Model Optimizer. By default the checkpoint is served as W4A16 (NVFP4 weights with 16-bit activations). The same weights also carry calibrated activation scales for W4A4 (NVFP4 weights and activations) on the w4a4 revision; see Usage.

This model is ready for commercial or non-commercial use.

Model Architecture:

Architecture Type: Transformer Network Architecture: Other - DFlash draft model (five Qwen3-style decoder layers) Number of Model Parameters: 1.03B (1,031,568,640), of which 671M (671,088,640) are an NVFP4-quantized copy of the target model's output head. The draft model shares the token embeddings of the target model, so they are not included in this checkpoint.

For more information about the underlying model's architecture, please see Nemotron-3.5-Bolt-E4B-BF16.

Input:

Input Type(s): Text, Image, Audio Input Format(s): Text: String; Image: Red, Green, Blue (RGB); Audio: Waveform Input Parameters: Text: One-Dimensional (1D); Image: Two-Dimensional (2D); Audio: One-Dimensional (1D) Other Properties Related to Input: Maximum context length of 131,072 tokens. Image and audio inputs are encoded by the target model; the draft model operates on the token sequence and attends to the most recent 1,024 tokens through its sliding-window attention.

Output:

Output Type(s): Text Output Format: String Output Parameters: One-Dimensional (1D): Sequences Other Properties Related to Output: The draft model proposes up to 7 candidate tokens per decoding step, and the target model verifies them, so the final output is generated by the target model.

DFlash Speculative Decoding

NVIDIA-Nemotron-3.5-Bolt-E4B-DFlash is a DFlash draft model for NVIDIA-Nemotron-3.5-Bolt-E4B. In each decoding step, the draft model takes the last verified token together with hidden states captured from five layers of the target model, and proposes the next 7 tokens of an 8-token block in a single non-causal forward pass. The target model verifies the proposed tokens in one forward pass and accepts the longest valid prefix, so more than one token can be generated per step. The mean number of tokens generated per step is the acceptance length, with a ceiling of 8.

The draft model was trained on a mix of thinking-enabled and thinking-disabled conversations. The acceptance lengths reported below were measured with thinking enabled.

Usage

To serve the checkpoint with vLLM (0.31.0 or newer):

bash
vllm serve nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16 \
  --speculative-config '{"model": "nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16-DFlash-NVFP4", "method": "dflash", "num_speculative_tokens": 7, "attention_backend": "flash_attn"}'

The default revision runs the draft model as W4A16. To run it as W4A4 (NVFP4 weights and activations), select the w4a4 revision:

bash
vllm serve nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16 \
  --speculative-config '{"model": "nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16-DFlash-NVFP4", "revision": "w4a4", "method": "dflash", "num_speculative_tokens": 7, "attention_backend": "flash_attn"}'

W4A4 needs NVFP4 activation kernels, which run on NVIDIA Blackwell GPUs; on GB300, use a vLLM build for CUDA 13.

Example request with thinking enabled, as in the evaluation below:

bash
curl http://localhost:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16", "messages": [{"role": "user", "content": "Explain speculative decoding in two sentences."}], "chat_template_kwargs": {"enable_thinking": true}}'

All acceptance lengths below were measured with this checkpoint in its default W4A16 configuration against the target model with thinking enabled, 4,096 output tokens, and concurrency 16 on one NVIDIA Blackwell GB300 GPU. Compared with the unquantized BF16 draft model, NVFP4 quantization lowers acceptance length by about 1% for W4A16 and by about 2% for W4A4.

Model Limitations:

The base model may generate inaccurate, incomplete, or otherwise undesirable responses, even when prompts are benign. It may reflect biases or content artifacts present in its training data, and output quality can vary by domain, language, reasoning depth, and context length. Developers should add application-specific safeguards and evaluate the system in the intended deployment environment before production use. The speedup from the draft model depends on the serving configuration.
