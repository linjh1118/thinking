# Model Overview

## Description:

The NVIDIA-Nemotron-3.5-Bolt-E4B-4GB-DFlash model is the GGUF (a binary model file format used by llama.cpp) version of [NVIDIA-Nemotron-3.5-Bolt-E4B-BF16-DFlash](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-BF16-DFlash-NVFP4), the DFlash speculative decoding draft checkpoint for NVIDIA-Nemotron-3.5-Bolt-E4B, a reasoning language model post-trained by NVIDIA from Google's [Gemma 4 E4B IT](https://huggingface.co/google/gemma-4-E4B-it). It is converted to GGUF in BF16 (bfloat16) for use with [llama.cpp](https://github.com/ggml-org/llama.cpp) and must be loaded together with the GGUF version of the target model, [Nemotron-3.5-Bolt-E4B-4GB](https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB). The draft model does not include token embeddings or an output head, and uses those of the target model at runtime. The model is intended for lower-latency local serving of NVIDIA-Nemotron-3.5-Bolt-E4B on workstation GPUs.

This model is ready for commercial or non-commercial use.

## Model Architecture:

**Architecture Type:** Transformer  
**Network Architecture:** Other - DFlash draft model (five Qwen3-style decoder layers)  
**Number of Model Parameters:** 360M (360,480,000), stored in BF16 in a single GGUF file of 736,812,096 bytes (736.81 MB / 702.68 MiB). The draft model shares the token embeddings and output head of the target model, so they are not included in this checkpoint.

For more information about the underlying model's architecture, please see [Nemotron-3.5-Bolt-E4B-BF16](https://huggingface.co/nvidia/Nemotron-3.5-Bolt-E4B-BF16).

## Input:

**Input Type(s):** Text    
**Input Format(s):** String  
**Input Parameters:** One-Dimensional (1D)  
**Other Properties Related to Input:** Maximum context length of 131,072 tokens, set in llama.cpp with `-c`. The draft model attends to the most recent 1,024 tokens through its sliding-window attention.  

## Output:

**Output Type(s):** Text  
**Output Format:** String  
**Output Parameters:** One-Dimensional (1D): Sequences  
**Other Properties Related to Output:** The draft model proposes up to 7 candidate tokens per decoding step, and the target model verifies them, so the final output is generated by the target model.

## DFlash Speculative Decoding

NVIDIA-Nemotron-3.5-Bolt-E4B-DFlash-GGUF is a DFlash draft model for NVIDIA-Nemotron-3.5-Bolt-E4B-GGUF. In each decoding step, the draft model takes the last verified token together with hidden states captured from five layers of the target model, and proposes the next 7 tokens of an 8-token block in a single non-causal forward pass. The target model verifies the proposed tokens in one forward pass and accepts the longest valid prefix, so more than one token can be generated per step. The mean number of tokens generated per step is the acceptance length, with a ceiling of 8.

The draft model was trained on a mix of thinking-enabled and thinking-disabled conversations. llama-server enables thinking by default (`--reasoning auto`), which matches the setting used for the acceptance lengths reported below.

## Usage

To serve the model with [llama.cpp](https://github.com/ggml-org/llama.cpp) **[b11808](https://github.com/ggml-org/llama.cpp/releases#release-b11808)**, load the target GGUF with `-m` and this draft GGUF with `-md`:

```bash
# [VERIFY: file names, quantization level, and flags after the llama.cpp test]
llama-server \
  -m NVIDIA-Nemotron-3.5-Bolt-E4B-Q4_K_M.gguf \
  -md NVIDIA-Nemotron-3.5-Bolt-E4B-DFlash-BF16.gguf \
  --spec-type draft-dflash \
  --spec-draft-n-max 7 \
  -ngl 99 \
  -fa on \
  --jinja \
  --port 8000
```
