<h4 id="technical-report"><a href="https://research.nvidia.com/labs/nemotron/files/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB-Technical-Report.pdf">Technical Report</a></h4>

<hr />
<h1 id="introducing-nvidia-nemotron-35-bolt-e4b-4gb">Introducing NVIDIA Nemotron 3.5 Bolt E4B 4GB</h1>

<p>Today, we’re excited to release <a href="https://huggingface.co/nvidia/NVIDIA-Nemotron-3.5-Bolt-E4B-4GB"><strong>Nemotron 3.5 Bolt E4B 4GB</strong></a> — our latest open small language model optimized for speed and intelligence per GB in conversational agents.</p>

<p>Bolt E4B builds on Gemma 4 E4B with Nemotron post-training. It combines natural conversation with multi-turn agentic capabilities to power voice/device assistants, interactive characters and robotic/IoT interfaces running on NVIDIA <a href="https://www.nvidia.com/en-us/geforce/rtx/">GeForce RTX</a>, <a href="https://www.nvidia.com/en-us/autonomous-machines/embedded-systems/">Jetson</a>, <a href="https://www.nvidia.com/en-us/products/rtx-spark/">RTX Spark</a> and <a href="https://www.nvidia.com/en-us/products/workstations/dgx-spark/">DGX Spark</a>.</p>

<p>Bolt E4B offers ~40% higher average quality against our <a href="https://huggingface.co/blog/nvidia/nemotron-3-nano-4b">prior model</a> on key conversational agent benchmarks and outputs up to ~80% fewer tokens vs peers.</p>

<p>Designed to pack conversational agent intelligence into as little as ~4GB in its target workloads, Bolt E4B enables responsive local experiences while preserving headroom for applications and other models in the same pipeline.</p>

<h2 id="model-features">Model Features</h2>

<ul>
  <li><strong>Multi-turn tool use</strong>: call application APIs to carry out tasks across a conversation, with integration guidance for asynchronous tool calls</li>
  <li><strong>Conversational mode</strong>: toggle to encourage concise, speech-ready responses for natural back-and-forth interactions</li>
  <li><strong>Configurable reasoning</strong>: enable reasoning for complex requests or disable it for faster responses, with integration options to cap thinking to meet latency targets</li>
  <li><strong>64k context</strong>: accommodate conversation history, instructions, tool definitions, retrieved information and application state</li>
  <li><strong>Multilingual capability</strong>: support for 35 languages, building on a base model pre-trained on +140 languages</li>
</ul>

<h2 id="agents-on-every-device">Agents On Every Device</h2>

<p>We’re always learning from how NVIDIA Jetson, GeForce RTX and DGX Spark customers — enterprises and enthusiasts alike — use our hardware to accelerate their workloads.</p>

<p>As language models become more capable, we’re seeing growing customer interest in using them for experiences like:</p>

<ul>
  <li><strong>Device &amp; Voice Assistants</strong>: Fast local assistants for PC, mobile, app, home or OS control; customer service; and in-cabin experiences for vehicles</li>
  <li><strong>Virtual &amp; Interactive Characters</strong>: In-game NPCs, companions, and other interactive characters that blend dialogue with actions while maintaining a persona</li>
  <li><strong>Embedded &amp; Industrial Agents</strong>: Human-machine interfaces for robotics and heavy machinery; system automation and industrial IoT</li>
</ul>

<p>Many large models are capable of powering these agents — but constraints around memory, latency, hardware compatibility, cost, or privacy concerns prevent developers from deploying these in production.</p>

<p>And so, they turn to faster, cheaper, smaller local models that can unlock these experiences.</p>

<h2 id="evaluating-real-time-interactive-agents">Evaluating Real-Time Interactive Agents</h2>

<p>Choosing a model for these experiences is not as simple as picking the highest score on today’s LLM leaderboards.</p>

<p>A model that excels at agentic coding is often not the best fit for a fast home assistant that’s fun to interact with — these agents need a different mix of capabilities. Through conversations with customers, several common characteristics emerge:</p>

<ul>
  <li>The model must often embody an agent that converses naturally with a human in the same physical or virtual space</li>
  <li>It must know whether, when and how to interleave dialogue with correct tool calls to take actions</li>
  <li>It must reliably honor explicit behavioral, persona, brand, or output constraints</li>
  <li>It must understand its environment by interpreting supplied app/world telemetry, retrieved database payloads or tool results</li>
  <li>And, it must ground all dialogue and actions in the relevant parts of all that context — especially amid distractors or as that context grows throughout a conversation</li>
</ul>

<p>Current benchmarks only partially capture what makes these agents work well, and no individual benchmark covers every capability an application needs. Ultimately, benchmark gains must translate into better behavior in the target application.</p>

Every benchmark uses the same reasoning mode across models. Reasoning mode varies by benchmark. Brevity Bench and When2Call-MT address gaps in existing evaluations — to be released at a later date.</p>

<p>Across all these benchmarks, Bolt E4B achieves roughly 40% higher average scores than our prior model, Nano 4B, and roughly 10% higher scores than other peers evaluated.</p>

<p>These quality gains also come with fewer output tokens — up to 80% fewer in reasoning enabled comparisons. Reducing unnecessary generation lowers decoding work and costs, and can shorten response times.</p>

<h2 id="training-methodologies--open-recipes">Training Methodologies &amp; Open Recipes</h2>

<p>Bolt E4B builds on <a href="https://huggingface.co/google/gemma-4-E4B-it">Gemma4-E4B-it</a> through Nemotron post-training methods across environments targeting instruction following, multi-turn tool-calling and conversational capabilities.</p>

<p>We used reinforcement learning with verifiable rewards (RLVR) and from human feedback (RLHF), powered by <a href="https://github.com/nvidia-nemo/rl">NeMo-RL</a> and <a href="https://github.com/NVIDIA-NeMo/gym">NeMo-Gym</a>. The training datasets are listed below, and the full recipe is available <a href="https://github.com/NVIDIA-NeMo/Automodel/blob/main/docs/model-coverage/vlm/nvidia/nvidia-nemotron-3-5-bolt-e4b-4gb-bf16.mdx">here</a>:</p>

<ul>
  <li>Tool-Calling:  <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-Agentic-Conversational-Tool-Use-Pivot-v1">Conversational Tool Use Pivot</a></li>
  <li>Tool-call schema:  <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-Agentic-Function-Calling-Pivot-v1">Function Calling Pivot</a></li>
  <li>Instruction Following:  <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-instruction_following">Instruction Following</a>, <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-SysBench-v1">SysBench</a>, <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-InverseIFEval-v1">InverseIFEval</a>, <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-CFBench-v1">CFBench</a>, <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-Instruction-Following-MultiTurnChat-v1">MultiTurnChat</a>, <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-Instruction-Following-Calendar-v2">Calendar</a></li>
  <li>Instruction Hierarchy: <a href="https://huggingface.co/datasets/nvidia/Nemotron-System-User-Instruction-Hierarchy-v1">System-User-Instruction-Hierarchy</a></li>
  <li>Structured Outputs:  <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-Instruction-Following-Structured-Outputs-v2">Structured Outputs</a></li>
  <li>Free-form formatting:  <a href="https://huggingface.co/datasets/nvidia/Nemotron-RL-Instruction-Following-Free-Form-Formatting-v1">Free-Form Formatting</a></li>
  <li>GenRM: Updated version of  <a href="https://huggingface.co/datasets/nvidia/Nemotron-RLHF-GenRM-v1">Nemotron-RLHF-GenRM-v1</a></li>
</ul>

<p>To emphasize non-reasoning accuracy, we used every sample in the RLVR/RLHF training blend in both reasoning and non-reasoning modes. We profiled rewards for each dataset separately in both modes, and maintained a 2:1 ratio of non-reasoning to reasoning samples in each training batch.</p>

<p>As post-training progressed, both reasoning traces and final answers became substantially longer. To control verbosity, we increased group-relative length penalties for reasoning and answer length in the GenRM environment. In all other environments, we disabled overlong filtering.</p>

<p>After post-training, we quantized the selected BF16 checkpoint to Q4_K_M using llama.cpp with importance-matrix (imatrix) calibration. Calibration used approximately 1M tokens of RL rollouts from the same training step as the selected checkpoint.</p>

<p>This release also includes a DFlash parallel drafter. It proposes all draft tokens in one forward pass, which the target verifies in parallel while preserving the target model’s  output distribution. DFlash delivers up to 21% higher throughput relative to Gemma-4-E4B’s original MTP drafter.</p>
