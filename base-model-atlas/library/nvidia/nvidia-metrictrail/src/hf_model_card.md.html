Description:

MetricTrail estimates camera motion and per-frame metric depth from long RGB image sequences for visual odometry and 3D reconstruction research. It combines single-image metric depth, learned sparse correspondences, and local geometric optimization, with supplied or RGB-estimated intrinsics and optional rectified stereo. MetricTrail 1.0 was developed by NVIDIA.

The repository provides a CLI that exports camera trajectories and caches per-frame depth. Model weights are not included in the source repository; the DINO-DPVO checkpoint is planned for a separate Hugging Face release. The CLI does not export dense point clouds or meshes. The dense-reconstruction results below use a separate research evaluation workflow.

This model is for research and development only.

Model Architecture:

Architecture Type: Learned recurrent visual odometry with frozen visual foundation-model features and explicit bundle adjustment.

Network Architecture: DPVO's sparse patch correspondence network with learned residual feature-fusion adapters, a frozen DINOv3-S/16 encoder, and a frozen MoGe-2 metric-depth provider. The complete system includes camera calibration and optional pose-graph correction.

Number of model parameters: The DINO-DPVO checkpoint for the separate Hugging Face release contains 3,425,860 learned parameters (3.43 million) across 100 FP32 weight/bias tensors. This count excludes the frozen DINOv3 backbone, external MoGe-2 depth model, calibration dependencies, and optional SALAD and RoMa models.

The local estimator alternates learned patch matching with joint optimization of camera poses and sparse patch inverse depths in a bounded active window. MoGe-2 independently predicts metric camera-Z depth for each image. These predictions initialize patch depths and remain robust soft constraints during optimization; multi-view evidence can override unreliable prior measurements. In the dense-reconstruction workflow, frame-level depth maps are placed in a shared world frame using the recovered poses and are not themselves bundle-adjustment variables.

Frozen DINOv3 features augment the matching map and recurrent patch context through learned residual adapters. Its 384-dimensional features are projected to 64 channels and split into two 32-channel branches that augment the 128-channel matching stream and 384-dimensional recurrent context. Final residual projections are initialized to zero so adaptation starts from the official DPVO checkpoint's predictions.

We train MetricTrail for 15,000 optimizer steps with global batch size 16 on 16 NVIDIA A100 80GB GPUs, taking approximately seven hours. Fusion branches first warm up on 5,000 TartanAir clips with odometry frozen; odometry and fusion branches are then jointly fine-tuned on the remaining 235,000 clips. DINOv3 stays frozen, and MoGe-2 is not used during adaptation. Joint training uses AdamW, learning rates of 8e-6 for odometry and 8e-5 for fusion, weight decay 1e-6, linear OneCycle annealing with 1% warmup, gradient clipping at 10, and seed 1234. Each clip uses 80 patches per frame and 18 recurrent refinements. The frozen DINOv3 forward pass uses BF16; adapters, odometry, differentiable bundle adjustment, and losses use FP32.

Input:

Input Type(s): A temporally ordered RGB image sequence and camera parameters; optionally synchronized left/right image sequences for stereo. A JSON configuration selects the data adapter and processing settings.

Input Format(s): Prepared PNG frames or KITTI NPZ files containing images as uint8 [N,3,H,W]. The repository also supplies Oxford Spires and LaMAria inventory adapters. Loaders produce CHW RGB float32 images in [0,1]. Arbitrary video containers are not decoded by this CLI.

Optional loop correction consumes a saved local trajectory NPZ, its successful JSON sidecar, and an externally generated candidate JSON containing frame pairs and scores. The candidate file records the baseline NPZ's SHA256; the candidate file's own SHA256 must also be supplied.

Input Parameters: A configured frame inventory with at least 16 images, positive FPS, and image dimensions (H,W). Intrinsics use [fx,fy,cx,cy] in processed-image pixel coordinates. In calibrated KITTI mode, intrinsics, K, or input_intrinsics in the NPZ may be a four-vector, a 3 x 3 matrix, or an [N,4] array; the last format uses its first row as the shared camera model. Supplied-intrinsic adapters also exist for VBR and LaMAria. RGB-only mode estimates one shared camera model.

Stereo takes a synchronized, rectified right-image PNG inventory and a positive stereo_baseline_m, with a fixed horizontal rig translation. The public configuration does not expose an arbitrary stereo extrinsic matrix. Metric camera-Z depth is predicted internally by MoGe-2 ViT-L without a normal head, available as Ruicheng/moge-2-vitl.

Other Properties Related to Input:

  • Training uses 15-frame clips resized while preserving aspect ratio and

center-cropped to 480 x 640. Inference raster size depends on the protocol; the canonical KITTI input is 280 x 504, and the 7Scenes trajectory protocol uses 434 x 574. The shipped KITTI and VBR configurations use 280 x 504; Oxford uses 378 x 518. The 7Scenes evaluation uses a separate workflow; this repository does not include a 7Scenes adapter.

  • Images and camera intrinsics must undergo consistent resize and crop

transforms. Stereo requires synchronization, rectification, and a correct horizontal baseline consistent with the processed images.

  • RGB-only calibration estimates intrinsics from a finite prefix, fixes the

camera model, and replays that prefix before continuing online. Our evaluation initializes with the first 32 frames, and robust128 calibration uses 128 selected keyframes. The repository exposes configurable calibration budgets. A shared focal correction is optimized while the principal point remains fixed.

  • The implementation's metric-depth validity check requires a valid provider

mask, finite depth, and camera-Z depth in the inclusive range 0.2-500 m. If a full-resolution prediction, its registered stride-4 depth raster, or all sampled patch centers contain no valid depth, the sequence terminates and the run cannot commit a successful complete trajectory. Failed runs may leave cache or older output files; use stage validation to establish success.

  • max_frames=0 uses the full configured inventory. The default DPVO frame

buffer has capacity 32,768; buffer exhaustion raises an error. The bounded active optimization window does not make sequence duration or total cached data unlimited. The shared-intrinsic model assumes consistent camera geometry.

Output:

Output Type(s): Per-frame camera trajectories, intrinsics, cached frame-level metric depth and provider masks, and processing/audit metadata.

Output Format(s): Trajectory NPZ files with accompanying JSON records. The frontend cache stores raw depth.f32 and mask.u8 arrays with JSON contract, progress, and successful-completion records. It does not export dense point clouds, meshes, or sparse patch geometry.

Output Parameters: c2w and inverse w2c have shape [N,4,4]; intrinsics has shape [N,4]. The trajectory includes frame_ids, source_frame_ids, input_hw, and stereo metadata. Poses refer to cam0, the left camera for stereo. Cached camera-Z depth is FP32 [N,H,W]; the raw provider mask is uint8 [N,H,W]. Consumers must also check finite depth and range; the cached mask alone is not the final validity test.

KITTI local predictions are written under output_root/local/inference/; other adapters use output_root/local/inference/predictions/. The separate loop-correction command writes optional LC predictions under output_root/LC/inference/ and also retains local_c2w and the loop-edge count. Depth caches are under output_root/frontend-cache/<dataset>/<case>/.

Dense geometry is assembled by back-projecting camera-Z depth with intrinsics and transforming it by c2w. The CLI outputs the depth and poses needed for this operation but does not export dense reconstructions. Metric scale remains an estimate. Learned correspondence weights should not be interpreted as calibrated pose or depth uncertainty.

Other Properties Related to Output: Output length follows the processed frame inventory. Trajectories use meters for translation and homogeneous camera-to-world/world-to-camera matrices; cached depth uses meters along the camera Z axis. Depth predictions are valid only where the provider mask is valid, values are finite, and depth is in the inclusive range 0.2-500 m. The pipeline raises an error for frames with no usable depth priors. Check successful-completion records before consuming outputs; failed runs can retain intermediate caches or older files. The model does not provide calibrated pose/depth uncertainty or a guarantee of geometric correctness.

Software Integration:

Runtime Engine(s): PyTorch/CUDA. The documented environment is Python 3.10, PyTorch 2.5.1 and CUDA 12.4, with xformers for MoGe-2 attention, yacs, OpenCV, Pillow, and SciPy. Separately invoked loop correction uses NumPy/SciPy on CPU, with no PyTorch/CUDA, PyPose, FAISS or SALAD runtime dependency. The package metadata permits broader versions, but those combinations have not been validated. No precompiled DPVO CUDA extensions are included. Before tracking, build cuda_corr, cuda_ba, and lietorch_backends from source in the inference environment, using a compatible C++ compiler, the CUDA toolkit including nvcc, and Eigen 3.4.0 headers.

Supported Hardware Microarchitecture Compatibility:

NVIDIA Ampere (A100)

A CUDA device is required. Compatibility with other GPUs and a minimum memory requirement have not been established.

Supported Operating System(s): Linux x86_64 is the documented tracking environment. DPVO CUDA extensions must be built from source before tracking. Validation results for other environments are not documented.

Run with PYTHONNOUSERSITE=1. The primary command is python -m metrictrail.cli --config <config.json>; the default device is cuda:0. --case, --resume, --preflight, and --stop-after {calibration,local} control selection and stage execution. Preflight checks external files and relevant runtime imports; it does not validate model quality.

The main pipeline ends at the local trajectory with enable_lc: false. Run optional loop correction separately on CPU with python -m metrictrail.lc_cli --config <config.json> --case <case> --candidate-file <candidates.json> --candidate-sha256 <sha256>. MetricTrail consumes the supplied candidate pairs; it does not perform place retrieval or launch an external retrieval tool.

Validate the implementation, camera model, data preprocessing, output conventions, failure handling, and use-case performance before integrating the system into a larger application. A measured benchmark memory footprint does not by itself establish a supported hardware requirement.

Model Version(s):

MetricTrail 1.0: The registered research model release. Integrate this version by preparing RGB frame inventories and a JSON configuration, obtaining the separately distributed MetricTrail checkpoint and compatible upstream weights under their respective terms, and invoking python -m metrictrail.cli --config <config.json>. Inference:

Acceleration Engine: PyTorch/CUDA with DPVO CUDA extensions and xformers attention for MoGe-2. The default configuration enables FP16 for MoGe-2 and a depth-overlap queue of four. DINOv3 feature extraction uses BF16; the trained checkpoint stores FP32 tensors. No TensorRT or Triton export is provided.

Test Hardware: NVIDIA Ampere A100. The inference GPU's memory capacity and a minimum supported hardware configuration are not specified.

Known limitations include dependence on depth-provider accuracy, degraded sparse correspondence under low parallax, rapid rotation, rolling shutter, and motion blur, and sensitivity to the shared camera model. Dynamic-scene reconstruction improvements are not uniform: the TUM-Dynamic scores trail leading evaluated methods. MetricTrail uses no explicit dynamic-object mask or dynamics-specific objective. Optional retrieved loop edges assume near-duplicate views are approximately coincident without pairwise geometric verification; incorrect matches can affect the trajectory.
