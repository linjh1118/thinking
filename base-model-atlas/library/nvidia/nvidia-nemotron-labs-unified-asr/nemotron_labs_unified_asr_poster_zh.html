问题：离线与在线为何有落差

离线可以看完整句，在线必须在未来音频未知时提交。统一模型共享 encoder、predictor、joint，减少两套系统的维护，但不能消除实时性的准确率代价。

一个checkpoint，不是通用文本新正代

英文Parakeet-unified的25语种扩展；中文不在ASR语言列表。转写文本，不直接生成语音。

公开数据与未公开细节

约10k小时人工转写+660k小时Granary伪标注；温度采样。完整超参、MCR消融和各语言时长不足，不能冒充完整报告精读。

初始化

24层encoder来自Parakeet TDT v3；解码目标为RNNT，8倍下采样仍非因果。

联合工作模式

完整上下文与left/chunk/right分块训练共享全部参数，MCR减小模式差距。

数据与词表

25语种共用SentencePiece；人工与伪标注保持标点和大小写。

机制：模式一致性与语言提示

离线用全上下文；流式用分块 attention 与 Dynamic Chunked Convolution。MCR 约束两种模式一致。图为官方架构，不把切块调用误写成完整训练方法。

官方：WER—算法延迟完整权衡图
统计口径必须保留

44-run均值不是25个语言均分再平均。cleaned英文集合不能与历史uncleaned榜单直接比较。

不要把auto语言模式当评测模式

支持auto，但卡片成绩用显式language-ID。最早的错误token已提交后通常无法撤回。

算法延迟定义
Lalgorithmic=C+R

80ms chunk +80ms right=160ms；不含采集、网络、排队、GPU重算和TTS。

语言提示

one-hot语言向量沿时间广播，与声学特征拼接并投影；低延迟时避免首批token误判语言。

推理不是缓存免费

当前buffered每步重算左上下文。直接cache-aware会破坏训练/推理匹配，2秒以下左上下文明显退化。

3

实验：延迟下降不等于全项领先

WER%越低越好。所有结果使用显式语言提示，5.6秒左上下文。英文7个cleaned集合、全语种44次dataset-language运行，口径不同不能混均分。
