Cosmos3-H-Dreams

Action-conditioned surgical video simulation with recorded action replay and live headset controller input, built on FlashDreams.

Starting from a surgical scene image, Cosmos3-H-Dreams generates video in chunks conditioned on instrument actions. Replay recorded actions to an MP4, or control the simulation from a headset browser and watch the output on the headset or a PC.

Quick Start

Run these commands from the repository root. You need a compatible Cosmos3-H-Dreams checkpoint and an initial scene image. Model weights and user assets are supplied separately; the repository includes an example scene image and action trajectory, with their provenance and licenses recorded in THIRD-PARTY-NOTICES.

1. Install dependencies

With Python 3.12, uv, and a compatible NVIDIA GPU environment available:

bash
uv sync --package flashdreams-cosmos3-h-dreams --locked

2. Prepare the session

Place your checkpoint at data_local/checkpoints/model.safetensors and scene PNGs under data_local/scenes/. The bundled real-time configuration uses the available example data in example_data/scenes; edit that file if your assets live elsewhere.

For the headset browser, generate an HTTPS certificate. Replace <server-LAN-IP> with the server address reachable from the headset:

bash
openssl req -x509 -newkey rsa:2048 -nodes \
  -keyout key.pem -out cert.pem -days 365 \
  -subj "/CN=headset" -addext "subjectAltName=IP:<server-LAN-IP>"

3. Start the simulation

bash
uv run --no-sync cosmos3-h-dreams-run headset \
  --session-config cosmos3_h_dreams/configs/real_time_2steps.yaml \
  --checkpoint PATH/TO/CHECKPOINT/c3-h-d_2-step_model_bf16.safetensors

Open https://<server-LAN-IP>:8443/headset in the headset browser, accept the certificate warning, and select Enter VR. Wait for model loading and compilation, then track both controllers, release the triggers, and hold still for calibration. Open https://<server-LAN-IP>:8443/viewer on a PC to watch the same simulation.

The example uses two denoising steps, TAEHV decoding, compiled FadeMem caching, and HTTPS/MJPEG video. Initial compilation takes longer than subsequent generation.

For recorded actions and MP4 output, see offline replay.

System Requirements

ComponentRequirement
PlatformLinux with an NVIDIA CUDA-capable GPU
GPU memoryWith the default configuration (480x832 resolution and 12 history latents), the required VRAM is over 32GB.
Python3.12 by default via .python-version; package range is >=3.12,<3.15
Browser test toolingNode.js 14.18.0 or newer; use a currently supported LTS release
Package manageruv 0.11.8 or newer; use the committed lockfile
CUDA environmentDriver compatible with the installed PyTorch CUDA build; the workspace defaults to CUDA 13
Replay outputffmpeg available on PATH for MP4 output
Live controlHeadset with a WebXR-compatible browser and two tracked controllers; HTTPS access to the server
AssetsCompatible checkpoint and initial frame; [N, 28] action array for replay

First use may download tokenizer and decoder assets. Allow storage for these, the model checkpoint, the Python environment, and compiler caches. GPU memory use and throughput depend on resolution, chunk size, cache, and decoder settings.

Acknowledgments

Cosmos3-H-Dreams builds on FlashDreams, NVIDIA's inference and serving framework for autoregressive video and world models. We thank its authors and contributors.

Our FadeMem cache mode independently implements the memory consolidation method introduced by Yu Lu, Junjie Yang, Piotr Koniusz, YuXin Song, and Yi Yang in FadeMem: Distance-Aware Memory Consolidation for Autoregressive Video Diffusion (2026).
