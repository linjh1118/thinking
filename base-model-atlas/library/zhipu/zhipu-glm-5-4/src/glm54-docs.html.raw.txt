<h2 class="flex whitespace-pre-wrap group font-semibold" id="overview" aria-labelledby="_R_39deehkd74t9_"><a href="#overview" class="anchor-link" aria-label="Navigate to header: Overview"></a><span id="_R_39deehkd74t9_" class="min-w-0 break-words cursor-pointer">Overview</span></h2>
<span data-as="p"><strong>GLM-5.4</strong> is Z.ai’s latest flagship model and the first built on the Loop Transformer architecture, reaching intelligence levels comparable to 2T-3T parameter models. It marks the start of Generalized Coding, where code becomes the foundation for solving a much wider range of tasks and unlocking new capabilities:</span>
<span data-as="p"><strong>Loop Transformer Architecture</strong></span>
<span data-as="p">GLM-5.4 introduces a Loop Transformer architecture that reuses 28 layers of the GLM-5 base model across two iterations, enabling deeper reasoning without increasing parameter count. Combined with optimized KV caching and sparse attention, it delivers stronger reasoning performance while keeping deployment costs under control, particularly at 1M context lengths.</span>
<span data-as="p"><strong>Generalized Coding</strong></span>
<span data-as="p">Driven by improvements in both coding and vision, GLM-5.4 generalizes well beyond traditional software development. It can write code to generate and edit videos, build complete games, and handle 3D modeling and mechanical design.</span>

<h2 class="flex whitespace-pre-wrap group font-semibold" id="key-advancements" aria-labelledby="_R_v9deehkd74t9_"><a href="#key-advancements" class="anchor-link" aria-label="Navigate to header: Key Advancements"></a><span id="_R_v9deehkd74t9_" class="cursor-pointer">Key Advancements</span></h2>
<span data-as="p">Over the past three months, we have aggressively scaled both loop depth and model size in parallel. The first surprise came from the Loop Transformer architecture itself. <span data-as="p">GLM-5.4 is our first flagship model built on the Loop Transformer architecture, reaching intelligence levels comparable to 2T-3T parameter models.</span>
<span data-as="p">GLM-5.4 marks the start of Generalized Coding, where code becomes the foundation for solving a much wider range of tasks and unlocking new capabilities.</span>
<span data-as="p">The model still has some limitations. Most notably, it tends to get caught in overly long “marathon thinking” loops, though this prolonged reflection and self-correction does consistently improve accuracy beyond its parameter count.</span>

<span data-as="p">As we noted in our GLM-5.3 technical blog, memory-intensive tasks benefit from more parameters, while reasoning-intensive tasks benefit from more effective compute. Large-scale software engineering, cybersecurity, 3D modeling, and physical control are all ultra-long-chain reasoning tasks. The model must follow multi-step causal chains while maintaining global logical consistency. Stacking parameters and memorizing data cannot solve this.</span>
<h5>From Pre-Trained Base to Loop Transformer</h5>
<span data-as="p">In a standard Transformer, each layer runs once per forward pass. In a Loop Transformer, a group of weight-shared layers runs for multiple iterations, refining the hidden states from the previous pass. This gives us a deeper network without increasing the parameter count.</span>
<span data-as="p">The idea is not new. The 2018 Universal Transformer proposed weight-shared depth, and recent work on recurrent depth and looped language models has shown gains at small scales. However, while weight sharing improves parameter efficiency, looped models trained from scratch still lag behind unshared models under the same pre-training compute budget. Instead of pre-training from scratch, we adapted an already pre-trained base model into a Loop Transformer through continued training. This lets us raise the intelligence ceiling with a relatively small compute overhead.</span>
<h5>Architectural Modifications at 750B Scale</h5>
<span data-as="p">GLM-5.4 loops 28 layers of the GLM-5 base model for two iterations. To balance performance gains with deployment costs at the 750B scale, we made three changes after extensive experimentation:</span>
<h6>Gated Progressive Updates</h6>
<span data-as="p">When converting middle layers of an existing model into a multi-pass loop, directly overwriting hidden states causes activation norms to blow up across iterations. Downstream layers then receive representations outside their expected scale and distribution.</span>
<span data-as="p">GLM-5.4 adds independent per-token gates for each iteration to proportionally write candidate updates back into the residual stream. After training, these gates develop a clear division of labor. The first pass builds global context and writes conservatively with small gate values to keep scales stable. The second pass reuses this state to refine the output, opening the gates to write full updates. The gates also adjust step size dynamically based on token difficulty: on harder tokens, the first pass writes more aggressively so complex predictions benefit more from iterative refinement.</span>
<h6>Hybrid KV Cache (Global Sharing + Independent Sliding Window)</h6>
<span data-as="p">A naive implementation keeps a full KV cache for every loop iteration, multiplying memory usage with the loop count. Instead, we build on cross-loop KV sharing by supplementing it with a local sliding window for the new pass: the second loop reuses the sparse KV selected in the first pass, while retaining its own newly generated KV within the sliding window. These two KV streams can overlap at the same positions, allowing the model to attend to both the first-pass context representations and the updated local representations from the second pass.</span>
<span data-as="p">As a result, an extra loop only costs one sliding window of KV cache rather than a full context cache. At 1M context lengths, this keeps GLM-5.4’s deployment cost increase over GLM-5.3 well under control.</span>
<h6>Sparse Attention Index Reuse</h6>
<span data-as="p">GLM-5.4’s base model uses sparse attention. The second loop directly reuses the attention indices generated by the first loop’s indexer, adding zero indexing overhead. Our experiments show this performs nearly identically to recomputing indices on every pass.</span>
<h5>Scaling Correctness &amp; Controlled Iso-Parameter Ablations</h5>
<span data-as="p">Looping is also a strict test of Scaling Correctness: any architectural change must still work at scale. Before committing our flagship model to it, we validated the Loop architecture progressively across 1B, 4B, 30B, and 750B base models.</span>
<span data-as="p">On a 30B model with the exact same architecture as our 750B base, we ran a controlled iso-parameter comparison. With identical parameter counts and only ~10% more total training compute, the looped version showed clear gains:</span>

<span data-as="p">Two findings stand out:</span>
<ul>
<li>Longer reasoning chains benefit more. The largest gains show up in math, scientific reasoning, and long-context tasks, which are core to Generalized Coding.</li>
<li>Fewer tokens spent on thinking. Across most benchmarks like GPQA-Diamond and MMLU-Pro, average output length drops by 10–14%, mostly from shorter chains of thought. In effect, part of the reasoning shifts from explicit output tokens into the implicit depth of the loop.</li>
</ul>
<h5>Inference Efficiency</h5>
<span data-as="p">GLM-5.4 reaches up to 200 tokens/s during off-peak hours and maintains 70–80 tokens/s at peak load. Achieving this throughput with a multi-pass Loop architecture required close co-design between the model and our inference infrastructure. Alongside the memory and retrieval savings from our KV cache and sparse index designs, we fused core kernels at the systems level to cut down intermediate memory reads and writes, eliminating the fragmented overhead amplified by looping.</span>
