Model Introduction

Figure 1. A unified visual tokenizer for general-purpose modeling. Native-resolution images are represented through a shared discrete vocabulary for reconstruction, understanding, generation, and editing. The figure summarizes the paper's tokenizer and downstream systems; see the repository scope below for the components included here.

We introduce dNaViT, a Discrete Native-resolution Vision Transformer that turns native-resolution images into discrete visual primitives analogous to language tokens. Building on our preliminary work in LongCat-Next, dNaViT explores how far a finite discrete vocabulary can go in representing the richness of the visual world: a shared interface for reconstruction, classification, multimodal understanding, generation, and editing.

A frozen pretrained vision encoder supplies semantic features. A lightweight Residual Modulator (ResMod) enriches these features with reconstruction-aware detail, and grouped product quantization maps them to discrete codes. Separate semantic and pixel reconstruction branches guide the shared representation, while progressive training balances their objectives and mitigates gradient interference. The same codes support faithful image decoding and downstream token-based modeling; an optional code-conditioned Refiner improves perceptual quality without changing the underlying representation.

Key Features

🌟 Native-Resolution Visual Tokenization

dNaViT supports variable resolutions and aspect ratios rather than requiring a single fixed square input. Smart resizing approximately preserves aspect ratios and aligns image dimensions to the 32-pixel stride; variable-length packing keeps training within a configurable token budget. Image-specific token-grid dimensions are retained through quantization and token unmerging, keeping both reconstruction branches spatially aligned with the resized input across different resolutions and aspect ratios.

🌟 Semantic Features with Reconstruction-Aware Detail

ResMod aggregates intermediate features from a frozen Qwen3-VL vision backbone and learns token-wise residual scale-and-shift updates. Its zero-initialized head preserves the pretrained semantic base at initialization, then learns to incorporate complementary reconstruction-relevant detail without training the backbone. Both decoders consume the same quantized embeddings: the semantic branch reconstructs a fixed post-ResMod feature target using cosine and MSE losses, while the pixel branch reconstructs the image.

Figure 3. Architecture and residual modulation. A frozen representation encoder and ResMod produce features for group-wise product quantization. ResMod fuses intermediate features through a zero-initialized scale-and-shift residual, while separate pixel and semantic ViT decoders supervise the shared discrete representation.

🌟 Scalable Capacity through Grouped Product Quantization

Channel-wise codebooks increase discrete capacity without increasing the spatial grid size. At stride 32, an image is represented on an H/32 × W/32 grid, with multiple code indices at each position. Increasing the group count increases the code payload, not the number of spatial positions.

Figure 4. Tokenization and unified codes for downstream tasks. Each spatial feature is split into channel groups and quantized with group-specific codebooks. Understanding supplies only the indices to the language model through newly initialized group-wise embedding tables trained jointly with the LM. Reconstruction looks up the frozen tokenizer's codebook embeddings. Generation and editing predict grouped indices through a multi-sub-token head and decode through the same tokenizer interface, optionally conditioned on a reference image. The downstream LM components shown here are not included in this directory.

🌟 Progressive Three-Stage Training

Training proceeds from continuous pixel pretraining (A) to discrete semantic reconstruction (B) and joint reconstruction (C). Stage B stops pixel gradients at the quantized representation; Stage C restores this path and uses a frozen copy of the Stage B ResMod to keep semantic targets stable. These correspond to Stages 1, 2, and 3 in the manuscript; configuration filenames retain the existing A/B/C names.

Code-Conditioned Refiner

Although the ViT pixel decoder faithfully preserves image content, a Refiner can further enhance perceptual quality with sharper, more realistic details. Our code-conditioned Refiner replaces the ViT pixel decoder with a flow decoder built on a pretrained image-generation prior. It conditions directly on the discrete code embeddings, rather than an intermediate RGB reconstruction, and requires no text conditioning. This separates the shared representation from the choice of decoder while retaining the same underlying codes.

Figure 6. Code-conditioned Refiner. Discrete code embeddings condition a flow decoder through global context tokens and time-conditioned spatial residuals, without text conditioning. A multi-step teacher is distilled into a one-step student with adversarial supervision. Increasing the quantization group count improves reconstruction fidelity, while the G16 variant with the one-step Refiner enhances perceptual quality. The manuscript calls this refined variant dNaViT-G16-R.

Inference. Refiner inference scripts are provided on Hugging Face. The G16/G64 reconstruction results below use the ViT pixel decoder without refinement.

Figure numbers follow the manuscript. Click any figure to view its original PDF; image sources and export settings are recorded in assets/figures.

Quick Start

From the LongCat-Next repository root, enter the tokenizer directory before following the installation, training, and evaluation commands below:

bash
cd dNaViT

Use a separate environment for dNaViT; its dependencies are listed in dNaViT/requirements.txt, independently of the repository root and sft/.

1. Install dependencies

Use Linux with an NVIDIA GPU and a CUDA-compatible PyTorch installation. The dependency file records PyTorch 2.6.0 and Transformers 4.57.0 as the tested versions. Python 3.10 or newer is recommended.

From the dNaViT/ directory:

bash
python -m venv ../dnavit-env
source ../dnavit-env/bin/activate
pip install -r requirements.txt

The vision backbone uses FlashAttention 2. Install a flash-attn build compatible with your PyTorch and CUDA versions. If you keep the default experiment tracking configuration, also install wandb:

bash
pip install wandb

Alternatively, pass training.enable_wandb=false to the training launcher.

2. Prepare pretrained weights

Download the Qwen3-VL backbone and the auxiliary weights required by the training losses. The default directory layout is:

The Stage A configuration constructs the DINO discriminator at initialization, even though adversarial updates start beyond its configured training duration. The provided Stage B and Stage C configurations disable the discriminator.

To store the auxiliary loss weights elsewhere, set:

bash
export DNAVIT_PRETRAINED=/path/to/auxiliary-weights

This environment variable controls auxiliary weights only. Set model.vq_model.qwen3vit_path separately if the Qwen3-VL checkpoint is outside pretrained/Qwen3-VL-8B-Instruct/. See weight resolution for details.

3. Prepare data

The provided configurations use a JSONL dataset with one image record per line:

json
{"input": "<img_start>/path/to/image.jpg<img_end>", "source": "dataset_name", "img_size": [480, 640]}

The image path must appear inside <img_start>...</img_end>. Relative paths resolve from the working directory. img_size stores the original [height, width] and helps the sampler estimate token counts without decoding the image.

Set dataset.params.jsonl_paths in each stage configuration to your training JSONL files. The files under example_data illustrate the data formats with one placeholder image; replace them with your training data.

<strong>Resolution, batching, and validation data</strong>

  • dataset.params.min_pixels and max_pixels bound the resized image area.
  • dataset.params.max_tokens_per_sample limits each image's token count.
  • training.max_batch_tokens sets the packed batch budget. The JSONL loader

uses this budget instead of training.per_gpu_batch_size.

  • An optional <fixres_256> marker inside the image wrapper selects a fixed

square resolution for that sample.

  • For training-time PSNR evaluation, set dataset.params.eval_data_path to

your validation images, or disable the monitor with psnr_eval.enable=false.

  • Stage B and Stage C also enable linear probing. Set

linear_probe.imagenet_path to an ImageFolder training dataset, or use linear_probe.enable=false.

For ImageFolder datasets, organize images as <root>/<class_name>/<image>. The fixed-resolution training loader is available through dataset.type=c2i.

Training

Training stages

StageObjective and gradient flowConfiguration
A / 1 · Continuous pixel pretrainingBypass codebook quantization and jointly train ResMod and the pixel reconstruction path to expose reconstruction-relevant detail.Stage A
B / 2 · Discrete semantic reconstructionFreeze ResMod and use its output as both the quantizer input and the fixed feature target. Train the quantizer and semantic decoder through feature reconstruction and quantization losses; pixel losses update only the branch consuming detached quantized embeddings.Stage B
C / 3 · Joint reconstructionRemove detachment from the pixel branch and jointly train the quantizer, both decoders, and student ResMod. A frozen Stage B teacher ResMod supplies the semantic target; the provided configuration trains the student ResMod at 0.1× learning rate.Stage C

The Qwen3-VL backbone remains frozen in all three provided configurations.

Launch training

After configuring weight and dataset paths, run each stage from the dNaViT/ directory. These commands illustrate initialization from the preceding stage:

bash
# Stage A: continuous autoencoder
NPROC=8 bash run_tok.sh configs/dnavit_stageA_anyres_32x.yaml

# Stage B: initialize from Stage A
NPROC=8 bash run_tok.sh configs/dnavit_stageB_anyres_g16_32x.yaml \
  experiment.init_weight_path=runs/dnavit_stageA_anyres_32x/exp1/checkpoint-latest/unwrapped_model

# Stage C: initialize from Stage B
NPROC=8 bash run_tok.sh configs/dnavit_stageC_anyres_g16_32x.yaml \
  experiment.init_weight_path=runs/dnavit_stageB_anyres_g16_32x/exp1/checkpoint-latest/unwrapped_model

NPROC selects the GPU count. run_tok.sh launches Accelerate, and additional arguments override configuration values using OmegaConf dotlist syntax:

bash
NPROC=4 bash run_tok.sh configs/dnavit_stageA_anyres_32x.yaml \
  'dataset.params.jsonl_paths=[/path/to/train.jsonl]' \
  model.vq_model.qwen3vit_path=/path/to/Qwen3-VL-8B-Instruct \
  training.max_batch_tokens=8192 \
  training.enable_wandb=false \
  psnr_eval.enable=false

<strong>Checkpoints, resuming, and experiment tracking</strong>

Training writes to runs/<experiment.name>/<experiment.exp>/ by default. Checkpoints are saved as checkpoint-<step>/, with checkpoint-latest pointing to the most recent checkpoint.

With experiment.resume=true, restarting the same run resumes its saved training state. An existing resumable checkpoint takes precedence over experiment.init_weight_path, which initializes weights for a fresh run. Use a new experiment name or output directory when starting a separate experiment.

The launcher defaults to WANDB_MODE=offline. Set WANDB_MODE=online to enable online tracking when using W&B.

Evaluation

ImageNet-256 reconstruction

The evaluation script resizes each image's shorter edge to 256 pixels, applies a 256 × 256 center crop, and compares the reconstruction with that same crop. It reports PSNR and SSIM, with reconstructed pixels rounded to the 8-bit grid. Optional rFID compares reconstructed and reference Inception features.

bash
# PSNR and SSIM on one GPU
bash eval_tok.sh configs/dnavit_stageC_anyres_g16_32x.yaml \
  /path/to/checkpoint/ema_model /path/to/imagenet/val 256

# Add rFID and distribute evaluation across four GPUs
FID=1 NPROC=4 bash eval_tok.sh configs/dnavit_stageC_anyres_g16_32x.yaml \
  /path/to/checkpoint/ema_model /path/to/imagenet/val 256

Use a checkpoint compatible with the selected configuration. --ckpt accepts a weight file or a directory containing pytorch_model.bin, such as unwrapped_model/ or ema_model/. rFID requires pytorch-fid and its Inception weights.

For configuration overrides or a saved metrics file, use the Python entry point:

bash
python scripts/eval_recon.py \
  --config configs/dnavit_stageC_anyres_g16_32x.yaml \
  --ckpt /path/to/checkpoint/ema_model \
  --data-path /path/to/imagenet/val \
  --image-size 256 --bf16 --fid \
  --result-file reconstruction_metrics.txt \
  --override model.vq_model.qwen3vit_path=/path/to/Qwen3-VL-8B-Instruct

The wrapper also accepts BATCH for per-GPU batch size and NUM_SAMPLES for a smaller evaluation subset. Use the complete validation set for benchmark results.
