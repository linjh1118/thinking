问题与架构：560B 上做实时全模态交互

Omni-model real-time interaction 面对四个相互牵制的难题：cross-modal heterogeneity（text/speech/image/video 结构差异巨大）、unified offline + streaming（算法需求完全不同）、millisecond-level latency（560B 推理本身就是工程奇迹）、training efficiency（FSDP 在 560B 上不实用，pipeline bubble 被异构性放大）。

图 1：整体架构 — 三个轻量外挂模块 + LongCat-Flash LLM backbone
核心哲学：Encoder-Decoder 拼接式 omni

保留 LongCat-Flash 的 ScMoE + zero-computation experts + MLA 原封不动，外挂 3 个轻量模块（ViT 637M + Audio Encoder ~600M + Audio Decoder ~600M），通过 6 阶段 curriculum 实现 early-fusion 而不破坏单模态性能。这是和 [[2603_LongCat_Next|LongCat-Next]] 离散 token 路线的方法论分歧。

ViT 配置（LongCat-ViT 637M）

基于自家 UnivTIT 工作，Patch 14，hidden 1280，32 层，2D-RoPE，native resolution encoding（patch 范围 576-5832，不强行 resize）+ 2× pixel-unshuffle，14.6B 样本 contrastive pretraining。避免极端宽高比信息丢失。

LLM Backbone：继承 LongCat-Flash

560B / 27B 激活的 ScMoE，MLA + zero-computation experts，per-token 变计算预算。Stage 0 文本预训练 checkpoint 作为 omni 起点，完全不动 LLM 架构。这是 LongCat 系列的"基座哲学"。

图 2：Audio Encoder — FSMN + CTC 实现流式输入编码
Audio Encoder 设计：为了 latency 牺牲一切

Fbank 80-dim 输入 → Pre-FFN 8× downsample（每帧 80ms） → FSMN 层替换 self-attention（self-attention KV cache 在长流式音频上是灾难）→ 最后 6 层 one-frame look-ahead → CTC loss 训练。Stage 5 用 ASR + audio understanding 数据对齐 continuous feature。

2

Speech LLM + 流式音视频交互

Speech LLM 的设计哲学是 discrete token 用于 LLM 训练，continuous feature 用于输入理解——两套并行。Audio Codec 4 codebook：1 个语义 codebook（让 LLM 容易预测）+ 3 个声学 codebook（补音色/情绪/prosody）。

图 3：Speech LLM 模式 — discrete token 训练 + 4 个并行 prediction head
Audio Tokenizer（LongCat-Audio-Codec）

16.67 Hz frame rate，把波形切成 4 codebook discrete token。Stage 1-4 用 discrete token 输入（训练效率高、next-token prediction 对齐），但发现离散化丢细节，Stage 5 又加 audio encoder 用 continuous feature 重训。

Audio Decoder：GAN + Code2Wav

LSTM + Conv + causal transposed conv，look-ahead 仅 3 帧（≈180ms）。不用 diffusion/flow-matching code2mel（虽然质量更好），因为推理慢；直接 GAN 训练的 Code2Wav 满足低延迟需求。

图 4：Asynchronous Streaming Pipeline — 端到端 <100ms 首包延迟
机制 1：Streaming Audio-Visual Feature Interleaving

离线可直接 concat(audio, video)；流式必须尽早 prefill。Chunk-wise 交错格式（每 chunk 1 秒）：<timestamp>: <video> <audio-start> <audio> ...，timestamp 用文本形式 Second{i}。

机制 2：Sparse-Dense Sampling Strategy

用户输入期：chunk=1s，video 2 FPS（dense）→ 保留信息；模型回复期：chunk=2s，video 0.5 FPS（sparse）→ buffer 到下一轮 prepend。模型边回答边"看"视频。

端到端 Latency <100ms

每个 packet = 1s 音频 + 2 帧视频；流式 prefill（边接收边算）；用户停顿期 600-700ms 用于 VAD 端点检测 和 prefill overlap；端点检测后 <100ms 内 返回首包。

Modality-Decoupled Parallelism（MDP）

模态 encoder 用 HSDP，LLM decoder 用 PP+ZeRO-1 DP+CP+EP。InnerDP 让模态 encoder DP rank 与 LLM decoder 一一对应。4 阶段执行：Data Loading → Modality Encoder Forward → LLM Fwd+Bwd → Modality Encoder Bwd。多模态训练保持 >90% text-only throughput，单 device 内存从 137GB 压到 72GB。

3

训练 & Benchmark：6 阶段 curriculum + 开源 SOTA

全篇最重要的训练设计：按 "sequence modeling 难度"递进——text → speech → image → video，逐步加模态，避免一种模态的训练拖垮另一种。关键经验：先训 speech 再训 image（反过来会让 speech 能力大幅退化）。

① Encoder-Decoder 拼接

560B MoE 基座原封不动，外挂 ViT 637M + Audio Encoder/Decoder ~1.2B。模块可独立优化、bit 级一致性、易部署——拼接派的成熟作品。

② Audio-Visual 实时

Chunk-wise 交错 + Sparse-Dense Sampling：用户输入期 1s/2FPS（dense），模型回复期 2s/0.5FPS（sparse）。模型边回答边"看"视频。

③ <100ms 首包延迟

流式 prefill 与 VAD 端点检测 overlap，端点结束后 <100ms 返回首包。560B 规模下做端到端流式音视频，工程奇迹。

④ 模块化挂载基座

多模态训练后文本能力不仅没退化，反而微涨（GPQA +0.67 / MATH +1.98 / MultiPL-E +1.51）。早期融合策略成功的最强证据，easy 复现。
