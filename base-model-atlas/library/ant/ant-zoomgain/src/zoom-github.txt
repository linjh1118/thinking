🔍 ZoomGain
Mining Global-to-Zoom Perception Gaps for Fine-Grained Visual Supervision
📄 Paper
·
📊 ZoomGainBench
·
🤗 RL Data
·
🧠 ZoomGain-4B
·
🧠 ZoomGain-9B
ZoomGain
builds questions about a full image from visual details that become clear when you zoom in. We use this global-to-zoom perception gap to construct supervision for vision-language models. In the paper, the best of 28 models scored
61.08
on ZoomGainBench, and ZoomGain-9B reached superior performance on multiple fine-grained perception and general perception benchmarks.

🔬 How ZoomGain Works
Ground the target.
Multiple models independently locate a target described in the full scene. Their agreement identifies a region to crop.
Mine evidence.
Compare captions of the same region at both scales, then turn details revealed by the crop into questions about the full image.
Verify questions and answers.
Cross-check answers on the crop, filter ambiguous questions and questions answerable without the image, and build plausible distractors for multiple-choice items.

📊 Evaluate on ZoomGainBench
📦 Download the benchmark
ZoomGainBench contains
1,000 questions over 941 images
covering attribute recognition, counting, and OCR. Each annotation includes English and Chinese question text, a reference answer, scoring rules, and an evidence bounding box in image pixel coordinates.
BENCH_DIR=
"
$ASSET_DIR
/data/ZoomGainBench
"
hf download inclusionAI/ZoomGainBench annotations.jsonl images.zip \
  --repo-type dataset --local-dir
"
$BENCH_DIR
"
unzip -q
"
$BENCH_DIR
/images.zip
"
-d
"
$BENCH_DIR
"
Keep
images/
next to
annotations.jsonl
. The evaluator loads the full image from each annotation's relative
image_path
and uses
evidence_bbox
to validate the evidence location.
🚀 Run evaluation
Install the dependencies from the model section and run the benchmark from the repository root. Replace the example
MODEL_PATH
with the path to a local checkpoint directory for any compatible model.
MODEL_PATH=
"
local/path/to/Qwen3.5-4B
"
\
ANNOTATIONS=
"
$BENCH_DIR
/annotations.jsonl
"
\
OUTPUT_DIR=
"
outputs/qwen3.5-4b-bench
"
\
GPUS=0 PORT=18811 LANGUAGE=all \
bash eval_ZoomGainBench/eval.sh
LANGUAGE=all
evaluates both languages for
2,000 tasks
. Use
LANGUAGE=en
for English or
LANGUAGE=cn
for Chinese.
GPUS=0,1
with
TP=1
runs two independent replicas. Set
TP=2
to use both GPUs for one replica.
Append
--dry-run
to validate the model and dataset or
--limit 10
for a short GPU run. Evaluation defaults to temperature
0
with Qwen3.5 thinking disabled.
Read
report.md
for the evaluation scores,
summary.json
for aggregate metrics, and
results.json
for per-question results.
responses.jsonl
contains the raw model responses.

⚙️ Install the training environment
Use a Python 3.10 environment with a CUDA toolkit and a C++ compiler for any CUDA extensions that need to build locally. The example below uses the CUDA 12.8 PyTorch wheels.
PyTorch wheel index
python -m pip install torch==2.10.0 torchvision==0.25.0 \
  --index-url https://download.pytorch.org/whl/cu128
python -m pip install packaging psutil ninja
python -m pip install --no-build-isolation flash-attn==2.8.3 causal-conv1d==1.6.2.post1
python -m pip install -r requirements.txt
The launch scripts load the bundled EasyR1 code directly. Point
BASE_MODEL
at the original Qwen3.5 checkpoint to start RL training from the same model family used in the paper.
