LemonDecider 4B

Model ID: lemondecider-4b-20261112-v3.1 Base model: Qwen/Qwen3.5-4B

LemonDecider makes typed decisions from a text or structured-JSON state and named questions. It returns choice probabilities, yes/no probabilities (noul), or ordinal scores without generating an answer token stream. This release processes questions independently, retaining the complete state and options for each question. Inputs are never truncated.

Training

Stage 1: general decision learning

The initial stage establishes broad typed-decision capabilities through supervised fine-tuning on approximately 1.20 million decision/QA examples, covering choice, noul, and score tasks.

Data categories:

  • Service and action decisions: intent routing, classification, and action selection;
  • Language judgment: sentiment, inference, factuality, and paraphrase-style checks;
  • Knowledge and reasoning: knowledge QA, commonsense, logic, and arithmetic;
  • Retrieval and selection: relevance judgments and candidate selection;
  • Preference and quality judgments: response quality and ordered comparisons;
  • Probability and ordinal judgments: yes/no probabilities and graded ratings.

Model-aware incremental data construction

The guiding idea is to build data around what the base model has not yet mastered, rather than blindly accumulating more examples:

  • Incorrect answers become training candidates directly, concentrating supervision

on observed weaknesses.

  • Correct answers are followed by one more question or reasoning step, or an added

condition, to create more challenging variants instead of repeatedly training on easy cases.

Following this principle, 35,467 incremental decision examples were assembled through selection, rewriting, and difficulty enhancement. The emphasis is on the learning value of each example, not dataset size alone.

Stage 2: targeted decision refinement

Stage 2 continues supervised fine-tuning of the existing decision model on the incremental corpus, focusing on difficult decisions and more demanding conditions while retaining the same three output types. The resulting updates are consolidated into full weights, with calibrated probability postprocessing. The released package is self-contained and does not require a separate adapter or base-model download.

Usage

Install a hardware-compatible PyTorch/torchvision build in a Python 3.12 environment, then install the remaining dependencies. Do not overwrite an accelerator vendor's PyTorch build with a generic CUDA wheel. The tested runtime used PyTorch 2.9.0 and Transformers 5.17.0; other hardware/software combinations should be smoke-tested locally. Download the entire model directory before loading. Custom code executes during loading, so review the packaged Python files first.

bash
python -m pip install -r requirements.txt
python verify.py

Python: typed decisions

python
import json
import sys
from pathlib import Path

checkpoint = Path("./LemonDecider").resolve()
sys.path.insert(0, str(checkpoint))
from model import DecisionModel

model = DecisionModel(checkpoint, device="cuda:0")
request = {
    "state": "The customer wants to return a damaged package.",
    "questions": {
        "action": {
            "type": "choice",
            "instructions": "Choose the next action.",
            "criteria": {
                "refund": "Offer a refund",
                "tracking": "Check tracking"
            }
        },
        "damaged": {
            "type": "noul",
            "instructions": "Is the package damaged?"
        }
    }
}
print(json.dumps(model.predict(request), indent=2))

CLI and HTTP

From the model directory:

bash
python model.py --device cuda:0 --input example.json
# Alternatively, start the local HTTP service:
python model.py --serve --device cuda:0 --port 8000
# In another terminal, when API-key authentication is unset:
curl -s http://127.0.0.1:8000/health
curl -s http://127.0.0.1:8000/v1/systemone \
  -H 'Content-Type: application/json' --data-binary @example.json

HTTP endpoints are GET /health, GET /v1/models, and POST /v1/systemone. The service binds to localhost by default. Set LEMONDECIDER_API_KEY to require bearer authentication on all endpoints; binding to a non-loopback address requires that key to be set. Use HTTPS and appropriate access controls in production. Health responses do not expose local checkpoint paths.

Requests may contain multiple named questions. Each is processed independently; short inputs use the package's configured second reading within the input sequence. Oversized structured states may fall back to plain JSON without optional index annotations, but original content and options are not truncated. If a question still exceeds capacity, the request fails with HTTP 422. Do not apply another chat template or temperature transformation outside the supplied runtime.

For installation details, input schemas and additional examples, see QUICKSTART.md.

Intended use & limitations

  • Designed for routing, classification, structured choices and ordinal judgments,

not open-ended text generation.

  • A probability output is not a correctness or calibration guarantee.
  • noul is the probability of the affirmative answer. score is the expected

zero-based ordinal level and need not be an integer.

  • Capacity is 8,192 tokens per rendered question, not the backbone's positional limit.
  • The serving API is text-only; serialized vision tensors do not imply image support.
  • The bundled renderer and postprocessing are part of the inference contract.
  • Local development results do not establish independent generalization, performance

on private tests, or reliability on real deployment traffic.

  • The model is not a safety system. Validate it for the intended domain and population

before deployment.
