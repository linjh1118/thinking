TLDR

金融 Harness 不是“给 LLM 接几个 API”，而是一个把执行、工具、程序性知识、状态证据、验证治理与训练评测连起来的七层系统。2026 年最强的新信号是显式 Skills；最硬的落地门槛是 point-in-time、确定性验证、权限审批和审计链。

一句话结论

金融 Agent 的研究重心正在从 model capability 转向 Harness reliability：金融的独特性不在多几个数据 API，而在 point-in-time、程序性 Skills、证据可追溯、确定性金融验证和受监管行动边界的联合设计。

七层体系

模型提出动作；Harness 决定动作是否允许、如何执行、如何记录、如何验证以及失败后怎样恢复。

1
环境与执行底座PIT 数据快照、沙箱、回测器、券商模拟器、Excel/ERP 工作区关键元数据：cutoff、universe、价格调整、成本、动作生效语义

关键反例：临时自生成 Skill

同一 episode 内让 Agent 临时生成 Skills，成本更高但收益很小；说明价值来自经过策展、验证和复用的程序性知识，而不是多写一段“反思”。

研究含义：比较 No Skill / Curated / Self-generated / Error-distilled / Governed-evolved，且固定 backbone、tools 与预算。

三个“不要混淆”

Tool ≠ Skill

Tool 是能力接口；Skill 是调用工具完成目标的可复用程序。Tool Card 描述“怎么调用”，Skill 描述“何时、为何、按什么步骤调用并怎样验收”。

Memory ≠ Skill

经验、belief 和反思可以是 skill-adjacent，但若没有触发条件、程序、版本与验证，不应直接称为 Skill package。

LLM 风险角色 ≠ 合规控制

risk officer/fund manager 角色只能提供软判断，不能替代预交易限额、权限、拒单、人工批准和审计状态机。

TLDR

金融 Skill 的最小单元不是 prompt，而是“触发/反触发 + SOP + 可执行组件 + 模板/示例 + 输入输出契约 + verifier + 版本与权限”。已公开的 Skills 主要覆盖研究、估值、建模、风险组合、交易税务和交付物质检。

一个金融 Skill package 应包含什么

1 · Trigger / Anti-trigger

适用任务、实体、期间、数据条件；明确禁用条件、冲突和需要升级给人的情形。

2 · SOP / SKILL.md

输入确认、步骤、允许工具、异常处理、证据要求和交付格式。

3 · Executable component

估值、风险、会计勾稽、表格操作、格式化或数据转换脚本。

4 · Template / Example

IC memo、earnings note、model tabs、证据表和 worked examples。

5 · Contract

needs / produces、schema、预算、权限、tool allowlist 和 destructive level。

6 · Verifier

数字容差、会计恒等式、引用覆盖、PIT、公式重算、结构与回归测试。

7 · Version / Provenance

来源、作者/审核人、适用版本、供应商/工具版本、依赖和变更记录。

8 · Promotion / Rollback

在 holdout 上过门后推广；监测边际效用、错误、冲突、成本和 drift，支持降级。

到底有哪些金融 Skills？

以下是报告中出现、可落为显式 Skill package 的完整能力族；同一 Skill 可由确定性、hybrid 或 autonomous runner 执行。

Ticker Snapshot
研究PIT

按截止时点汇总公司、证券、价格、事件与可见披露；输出带来源的 point-in-time 快照。

Equity Deep Dive
基本面报告

从业务、财务、竞争、催化剂、风险到估值形成证据型股票深度研究。

Financial Statement Analysis
财报会计

解析三表、同比环比、利润质量、现金流、异常科目、重述与口径变化。

Earnings Analysis / Note
财报季交付物

整合 earnings release、电话会、预期与实际，生成 earnings note 并核对引用。

DCF Valuation
估值计算

预测 FCF、WACC、终值、敏感性和每股价值；校验单位、期间、桥接和公式。

Relative Valuation / Comps
估值可比公司

筛选 peers、统一口径、计算交易倍数与统计区间，产出 comps table 和估值区间。

Precedent Transactions
投行估值

筛选先例交易、计算控制权溢价与交易倍数，并验证公告日点时可见信息。

Consensus Check
预期差证据

将公司指引、卖方一致预期、历史预测和实际结果对齐，检查口径与时间。

Three-statement Modeling
建模Excel

联动损益表、资产负债表和现金流量表；用勾稽与重算验证动态正确性。

LBO Modeling
投行/PEExcel

构建 sources & uses、债务瀑布、利息循环、退出假设、IRR/MOIC 与敏感性。

M&A / Merger Model
投行交易

合并对价、融资、购买价分摊、协同、增厚摊薄和 pro forma 财务。

Credit / Lender Model
信贷契约

现金流偿债、杠杆、利息覆盖、covenant headroom 和 downside 情景。

Risk Decomposition
风险组合

计算 VaR、beta、因子/行业/个券贡献、压力情景与限额占用。

Portfolio Construction / Rebalancing
组合约束

基于目标、风险、流动性、成本、账户权限与 allowlist 生成目标权重和再平衡草案。

Tax-loss Harvesting
财富管理税务

识别亏损头寸、替代标的和 wash-sale 风险；只生成待专业人士批准的建议。

IC Memo
投资委员会证据

把 thesis、证据、反证、估值、风险、情景和待决事项组织为可审阅 memo。

Excel Audit / Model QA
表格Verifier

检查硬编码、公式断裂、循环、单位、格式、跨表一致性和重算后的动态正确性。

Evidence & Citation Audit
ProvenanceVerifier

建立 claim→source→tool→version 链，检查引用覆盖、来源质量、截止时点和撤回/重述。

到底有哪些金融 Tools？

1 · 权威检索

SEC EDGARXBRL交易所监管公司披露

  • filings、submissions、company facts、原始附件
  • 必须处理 filing date、period、unit、restatement、amendment

2 · 商业数据连接器

LSEGCapital IQFactSetDaloopaMorningstarPitchBookMoody's

  • 行情、预期、基本面、交易、信用与私募数据
  • 核心约束是 entitlement、许可用途、版本和 vendor fallback

3 · 确定性计算

CalculatorDCF/WACCCompsVaRBetaFactor

  • 会计勾稽、单位换算、估值、风险和投资组合指标
  • 应优先使用确定性函数而非让 LLM 心算或充当 judge

4 · 代码与表格

Python sandboxExcelSheetsFile parserCharts

  • 读写/重算 workbook、跨文件引用、文档解析和可视化
  • 验证公式状态、静态值、动态 perturbation 与 over-edit

5 · 企业系统

ERPAR/APGeneral LedgerKYCCRMOMS/EMS

  • 企业财务运营、客户与订单工作流
  • 字段级脱敏、least privilege、审批与用途限制是默认能力

6 · 交易执行

Paper brokerLive brokerOrder statusCancelPortfolioRisk limit

  • target weight → order → check → execute → reconcile
  • 预交易限额、symbol/account allowlist、幂等、kill switch 必须在 LLM 外

三阶段演进

2023—2024 · 认知架构期

Memory / Role / Reflection

FinMem、FinAgent、FinCon、CryptoTrade、FinRobot。证明 LLM 可以嵌入闭环金融决策，但回测协议、成本和可复现性不足。

2024—2025 · 多 Agent / 研发自动化

Debate / Code / Backtest

TradingAgents、InvestorBench、R&D-Agent(Q)、FinVerse。把投研和量化开发拆成可执行工作流，但角色价值缺少消融。

2026 · Harness 原生期

Skill / PIT / Evidence / Gate

FinToolBench、FinanceHarness、FinSkillBench、ASDA、FundaPod、FinTrace、CLQT。程序知识、证据、权限和验证开始显式化。

TLDR

成熟评测已从答案正确率转向长轨迹和真实交付物：投行 data room、多文件 Office、Excel 重算、动态 perturbation、跨文件一致性和有效性门。RL 最适合长期模拟和可确定验证任务；对开放式研究报告应优先 process reward、偏好学习与 verifier 组合。

RL 适用性：按 reward 可验证程度分层

高：确定性环境 + 长期后果

EnterpriseArena 的长期 CFO 模拟、GAUGE 的 validity gates、受控交易/组合环境。适合 RL/规划，但必须有 PIT、成本、动作语义和不可绕过约束。

中：轨迹与偏好可监督

FinTrace、FinSkillBench、BankerToolBench、BlueFin、BigFinanceBench。适合 SFT/DPO/process reward；注意 judge 偏差、数据污染和 reward hacking。

低：开放式报告或小样本职业任务

FrontierFinance、FinDeepResearch 更适合严格测试与专家 rubric。若直接做 RL，reward 稀疏、昂贵且可能把写作风格误当正确性。

TLDR

生产级金融 Harness 的核心控制原语是确定性的：政策注册表、权限、限额、拒绝执行、审批、证据账本、版本清单、持续监测和回滚。LLM 可以提出与解释，但不能成为唯一控制面。

证据强度怎么写

高强度

开放数据/代码、清晰 task/verifier、跨模型实验或独立 Harness 复现。

中强度

开放论文与部分代码，但关键 API、工具或执行器受限。

设计证据

案例与架构完整，但缺少大规模、可对照的定量评估。

概念证据

主要在合成环境或技术报告中自证；不应用作生产性能结论。

更具发表潜力的方向

Governed Financial Skill Lifecycle: Point-in-Time Distillation, Verification, Promotion and Rollback for Financial Agents

1 · 错误分类器

retrieval、period/unit、formula、finance convention、temporal leakage、evidence、tool/permission、policy violation。

2 · Skill 蒸馏器

重复失败 → SKILL.md + executable component + example + verifier + trigger/anti-trigger。

3 · PIT 验证器

按 cutoff 重放数据与工具，检查未来信息、重述版本、计算和引用。

4 · Promotion gate

在 chronological/entity/tool-version holdout 显著提升且不增加风险违规，才进入 registry。

5 · Router / Composer

联合检索 Skill、Tool、数据源，按 task/intent/permission/cost 生成 typed DAG。

6 · Monitor / Rollback

监测 marginal utility、触发准确率、冲突、成本、错误与 drift，支持版本降级。

十个研究空白

1 · 受治理的 Skill 生命周期

生成、验证、专家评审、promotion、监测、失效和 rollback 尚未闭环。

2 · 跨模型 / 跨 Harness 可移植性

不同工具命名、上下文预算和编排器下，Skill 收益是否稳定。

3 · Tool ontology 与安全路由

统一 entity、period、unit、restatement、entitlement、intent、freshness 和 destructive level。

4 · 模型与 Harness 贡献归因

同时改模型、prompt、tools、数据和 Agent 数量，无法解释增益来源。

5 · PIT 与现实执行协议

未来泄漏、幸存者偏差、公司行动、延迟、成交、滑点、融资和成本。

6 · 从软治理到硬治理

LLM risk officer 不能替代限额、权限、幂等、审批、market-access control、kill switch。

7 · 证据 / 记忆失效

重述、regime 变化、来源撤回或冲突后，如何自动降权和失效。

8 · 评测器自身风险

LLM judge 的金融 convention 偏差；需确定性 checks、rubric、adversarial tests 与 judge disagreement。

9 · 隐私与指令攻击

KYC/AML、FP&A、客户数据、prompt injection、tool spoofing 和跨任务污染。

10 · 生产证据缺口

产业系统控制更强但细节不公开；学术性能证据与生产设计证据必须分开。

实验陷阱清单

  • 不要同时更换 backbone、prompt、tool set 和 Agent 数量。
  • 不要只报告 Sharpe/收益；至少报告成本、最大回撤、PIT、universe 与执行语义。
  • 不要用 LLM judge 替代所有数字和会计检查。
  • 不要把“生成过一段反思”当作 Skill。
  • 不要让测试轨迹反向污染 Skill bank。
  • 不要把 paper trading 或历史回测写成 live/production validation。
  • 不要把人工审批描述成一句 prompt；必须在 Harness 层有不可绕过状态机。
