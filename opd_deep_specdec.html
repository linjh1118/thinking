⚡ 推测解码蒸馏（11 篇深度解读）

本节 TLDR

推测解码（Speculative Decoding）的核心：用小草稿模型（drafter）快速提议 token，大验证器（verifier）并行验证，拒绝不符合的 token。这节的 OPD 目标不是提升模型智能，而是训练草稿模型更精准地模拟验证器的分布——从而提高接受率，加速推理。关键论文：DistillSpec（奠基）、OSD（在线适配）、EAGLE-3（当前 SOTA 自推测系列）、CORAL（多步对齐）。

推测解码工作原理 & OPD 的角色

背景导引
推测解码基础
标准自回归解码：大模型一次生成 1 个 token，每步需要完整 forward pass
延迟 = N × (大模型单步时间)

推测解码（Speculative Decoding）：
Step 1：草稿模型（小，快）连续生成 K 个候选 token
Step 2：大验证器（原模型）并行验证所有 K 个 token
接受概率：α_i = min(1, π_verifier(x_i|·) / π_draft(x_i|·))
Step 3：接受前 m 个 token（m ≤ K），拒绝后续

加速比 ≈ K × 接受率 α
α 越高（草稿越像验证器），加速比越大
→ OPD 的目标：提高 α（训练草稿模型更像验证器）
OPD 在推测解码中的角色

训练草稿模型面临典型的 distribution mismatch 问题：标准 SFT 在固定数据上训练，但推理时草稿模型在自己生成的前缀上继续生成——正是 OPD 最擅长解决的分布偏移问题。

DistillSpec: On-Policy Distillation for Speculative Decoding

ICLR 2024 Google DeepMind2023.10
开创性贡献

DistillSpec 是第一篇系统研究"用 OPD 训练推测解码草稿模型"的论文。它奠定了这个方向的基础框架：在草稿模型自己生成的 token 样本上，最小化与验证器的 KL 散度。

四种 OPD 损失的比较实验
在草稿样本 y ~ π_draft 上：

FKL：
L = Σ_t π_T(y_t|·) · log(π_T(y_t|·)/π_draft(y_t|·))
RKL：
L = Σ_t π_draft(y_t|·) · log(π_draft(y_t|·)/π_T(y_t|·))
JSD：
L = 0.5·FKL + 0.5·RKL
TVD：
L = 0.5 · Σ_t |π_T(y_t|·) - π_draft(y_t|·)|
哪种散度最适合推测解码？
损失类型接受率 α加速比分析
SFT（off-policy）0.742.1×基线
FKL（on-policy）0.792.4×覆盖验证器所有模式
RKL（on-policy）0.812.6×专注主模式，接受率更高
JSD（on-policy）0.832.8×折中最优
TVD（on-policy）0.822.7×接近 JSD

JSD 在推测解码场景下表现最佳——原因：推测解码的接受率取决于两个分布的重叠程度，JSD 作为对称散度同时考虑了两个方向的差异，与接受率的相关性最强。

为什么 OPD > SFT for SD？

草稿模型的训练-推理 mismatch 特别严重：推理时草稿在自己生成的前缀上继续生成（误差累积），而 SFT 在干净的固定数据上训练。DistillSpec 的 on-policy 训练直接在草稿自己生成的前缀上做 KL，消除了这种 mismatch。接受率提升 0.09（0.74→0.83）使加速比提升约 33%。

OSD: Online Speculative Decoding

UC Berkeley / NVIDIA2023.10
推测解码 on-policy 训练的经典论文

OSD 提出了一个极其简洁的思路：在推测解码的拒绝步骤本身提取训练信号。每次验证器拒绝草稿 token，就意味着草稿模型犯了一个错误——这正是最有价值的学习信号！

在拒绝 token 上进行在线 KD
标准推测解码流程（推理时）：
草稿生成：(x_1, x_2, ..., x_K)
验证器接受 x_1,...,x_m，拒绝 x_{m+1}

OSD：利用拒绝点做在线训练
被拒绝位置 m+1 处：
→ 草稿概率：π_draft(x_{m+1}|·)（错误的）
→ 验证器概率：π_T(x_{m+1}|·)（正确的）
L_online = D_KL(π_T(·|·) ‖ π_draft(·|·))  在位置 m+1

每次拒绝 = 一次免费的训练样本（完全 on-policy，零额外成本！）
零额外成本的在线学习

OSD 最大的工程优势：不需要额外的训练数据收集 pipeline。验证器在正常推理过程中自然产生拒绝信号，草稿模型在推理中自动更新。适合部署后持续适配的场景。

实验：持续适配效果
场景初始接受率OSD 适配后提升
领域内（代码）0.810.84+0.03
领域外（法律）0.680.79+0.11
用户特定风格0.720.83+0.11

OSD 对领域外适配效果特别显著——草稿模型通过在线学习用户特定分布，持续提升接受率。

EAGLE-3: Training-Time Test with On-Policy Multi-Step

PKU / Microsoft Research2025.03
EAGLE 系列演进
版本核心创新接受率
EAGLE-1（2024.01）利用验证器特征作为额外输入0.85
EAGLE-2（2024.06）动态树推测（自适应草稿 tree）0.87
EAGLE-3（2025.03）Training-Time Test（TTT）on-policy0.91
Training-Time Test（TTT）：OPD 的关键创新

EAGLE-3 的核心是"在训练时模拟多步草稿 rollout"——而不是单步训练：

EAGLE-1/2 的训练方式（单步，off-policy 风格）：
在固定数据集的 token 位置上训练草稿预测
问题：推理时草稿在自己前 K 步的预测上继续生成（错误累积）

EAGLE-3（TTT，真正 on-policy）：
Step 1：草稿模型生成 K 步连续 token（完整多步 rollout）
Step 2：在每步 草稿 rollout 的前缀上，用验证器特征监督
L = Σ_{k=1}^{K} [Smooth-L1(f_draft_k, f_verifier_k) + CE(y_{k+1}|draft_rollout)]
f = 验证器隐藏层特征，Smooth-L1 = 特征对齐损失
CE = 下一 token 预测损失（在 draft rollout 前缀上）
自推测（Self-Speculative）设计

EAGLE-3 的草稿模型复用验证器的中间层特征（不是独立的小模型），实现"自推测"：草稿 token 由同一个大模型的早期层生成，后续层进行验证。这减少了草稿-验证器分布差异，接受率相对外部草稿模型高约 8-12%。

CORAL: Cross-Step Representation Alignment

ACL 2025 2025.02
多步草稿的 train/test mismatch

即使用 OPD 单步训练草稿，在推理时草稿模型需要连续生成 K=5-10 步，每步的输入是上一步自己的预测（不是验证器的真实 token）。CORAL 专门解决这种"跨步 mismatch"。

跨步表示对齐
标准单步 OPD 训练（步骤 k 独立）：
对每个 token 位置 t，在验证器真实前缀上训练
→ 训练时前缀来自真实数据，推理时前缀来自草稿自己的预测（mismatch）

CORAL：跨步前缀对齐
训练时模拟 K 步连续草稿生成，并在跨步前缀上对齐隐层表示：
L_CORAL = Σ_{k=1}^{K} ‖h_draft(step k) - h_verifier(step k)‖² + L_CE
h = 最后层隐层表示，在 K 步连续 rollout 后对齐
→ 确保草稿的隐层状态与验证器在相同 token 位置对齐，无论前缀来自哪里
与 EAGLE-3 的关系

CORAL 和 EAGLE-3 都意识到了跨步 mismatch 问题，解决方案有重叠（都在模拟多步 rollout 训练），但角度不同：EAGLE-3 强调特征（f_verifier）监督，CORAL 强调表示（h）对齐。两者可以组合：CORAL 的跨步对齐损失可以作为 EAGLE-3 的附加项，进一步提升接受率。

其余推测解码 OPD 方法速览

7 篇
HASS（2024.08）—— 多步草稿轨迹（Multi-step draft trajectory）蒸馏，专门处理 K 步连续草稿生成的联合分布对齐问题。引入"draft chain"的序列级 KL 损失。
Draft Model Scaling（2025.08）—— 系统研究草稿模型大小 vs 接受率的 scaling law。发现草稿模型大小约为验证器的 5-10% 时效率最优（更大边际收益递减）。
Cascade Speculative Decoding（2025.04）—— 多级推测（小→中→大），每级都用 OPD 训练对齐上一级分布。在超大模型（>100B）上加速比最高可达 6×。
Medusa v2（2024.12）—— 多个解码头（hydra heads）并联，每个头预测后续不同步数的 token，全部用 on-policy 损失训练。多头联合接受率比单头提升约 15%。
REST-mcts（2025.10）—— 将 MCTS 引入草稿 token 搜索，用 OPD 训练 MCTS 的先验策略（draft policy）。适合推理任务（数学、代码），需要探索多步候选路径时效果优于标准推测解码。
SpecInfer（2024.10）—— 树式推测解码（tree-based SD）+ on-policy 草稿训练。多棵候选 tree 并行验证，OPD 训练 tree prior（树节点分裂概率）。
BiTA（2024.07）—— Bidirectional Token Alignment：草稿模型向前（从草稿看验证器）和向后（从验证器看草稿）双向对齐，用非对称 KL 训练。类似 DistiLLM-2 的对比损失思路在推测解码中的应用。
