🤖 Agent & 具身 OPD（5 篇深度解读）

本节 TLDR

Agent OPD 的特殊性在于：学生不是生成文本，而是在真实环境中执行动作（调用工具、操作 GUI、控制机器人）。OPD 信号来自教师在这些真实轨迹上的监督，而非虚构的文本序列。关键难题：动作空间离散（工具调用）或连续（机器人关节角度），需要适配 KL 或 L2 损失；轨迹可能很长（数十步），信用分配（credit assignment）困难。

SCoRe: Small Agent Matches 72B Teacher via Error Correction

Alibaba ModelScope2025.09
核心思想：纠正最早的错误

SCoRe 的洞察非常精准：在 Agent 任务中，错误是连锁的——第一步错了，后续全错。如果 72B 教师能识别出学生轨迹中最早发生的第一个错误，并提供正确的替代动作，这个精准纠正比重新生成完整轨迹更高效。

三阶段训练
阶段 1：学生（7B）生成完整轨迹
τ = (o_1, a_1, o_2, a_2, ..., o_T, a_T)  （观察-动作序列）
用外部验证器判断轨迹是否成功（任务完成率）

阶段 2：72B 教师定位最早错误
对失败轨迹，教师逐步回溯找到第一个错误动作 a_k*
教师提供纠正动作 a_k_correct（只纠正这一步，后续保持学生原有动作）

阶段 3：SFT-on-corrections + 短视界 RL
L = L_SFT(a_k_correct | o_1,...,o_k) + λ · L_RL(后续 k+1 到 T 步短视界奖励)
为什么 7B 能匹配 72B？

SCoRe 的实验显示：7B 学生在 12 个 Agent benchmark 上达到了 72B 教师 95% 以上的性能。核心原因：Agent 任务中的大多数错误集中在少数几类关键决策点（如 API 选择、参数格式），而不是均匀分布在所有步骤上。SCoRe 的精准纠正机制恰好击中了这些关键点，7B 学生的参数容量对"学会这些纠正模式"是足够的。

实验结果
方法ToolBench 成功率APIBench 准确率WebArena 分数

72B 教师直接推理78.4%89.1%23.6%

RPD: Refined Policy Distillation for Vision-Language-Action Models

IROS 2026 TU Munich / University of Freiburg2025.03
机器人控制的 OPD

RPD 是最干净的机器人 VLA（Vision-Language-Action）OPD 实现。VLA 模型直接从图像 + 语言指令预测机器人末端执行器的连续动作（6DoF 关节角度 + 夹爪）。

核心设计
教师 VLA（大模型，如 RT-2-X）：
输入：(图像观察, 语言指令)
输出：连续动作分布 π_T(a | s)

学生 VLA（小模型，目标 ≤1B 参数）：
在真实机器人上（或仿真）执行动作：a_student ~ π_S(·|s)  （on-policy）

OPD 损失（连续动作空间，用 L2 替代 KL）：
L_OPD = ‖μ_T(s) - μ_S(s)‖² + ‖Σ_T(s) - Σ_S(s)‖_F²
μ = 动作分布均值，Σ = 协方差

PPO 任务奖励（任务成功 = +1）+ OPD：
L_total = L_PPO + λ · L_OPD
连续动作 OPD vs 离散 token OPD 的差异
维度离散 token OPD（LLM）连续动作 OPD（VLA）
输出空间离散 token（词汇表 ~32K）连续向量（6-7 维）
OPD 损失KL 散度L2 / Wasserstein 距离
信号稠密度每 token 一个损失值每时间步一个损失值
分布表示softmax 概率向量高斯分布（均值+协方差）
机器人 OPD 的关键挑战

真实机器人实验中，on-policy 数据收集成本极高（需要机器人时间、场景重置）。RPD 用仿真预训练 + 少量真实微调的策略缓解了这个问题：在仿真环境中做大规模 OPD 训练，再迁移到真实机器人（需约 50-100 条真实轨迹）。仿真-真实差距（sim-to-real gap）是主要性能瓶颈。

VLA-OPD: Bridging Offline SFT and Online RL for Robot Learning

HKUST Guangzhou2026.03
解决离线 SFT 和在线 RL 的鸿沟

机器人学习的痛点：离线 SFT（在专家演示数据上）学到的策略在真实执行时性能大幅下降（分布偏移）；纯在线 RL 探索效率太低（安全限制下无法随机探索）。VLA-OPD 用 OPD 作为桥接：在学生自己执行的真实轨迹上，用专家教师提供密集监督。

Reverse KL 的特殊优势（机器人场景）

VLA-OPD 论文专门分析了为什么机器人动作 OPD 必须用 Reverse KL 而不是 Forward KL 或 Hard-CE：

  • FKL（前向 KL，mean-seeking）：强迫学生覆盖所有动作模式 → 机器人动作分布通常是多峰的（多种等效执行方式），FKL 会产生"折中"动作（两峰之间），导致执行失败。
  • Hard-CE（行为克隆）：坍缩到单一模式 → 丢失动作多样性，过拟合专家演示，泛化差。
  • RKL（反向 KL，mode-seeking）：学生集中学习教师最高概率的动作模式，同时保留探索空间 → 在安全约束下最优。
灾难性遗忘缓解

持续在线 OPD 训练的副作用：新任务训练会覆盖旧任务知识。VLA-OPD 通过保留教师（原始专家模型）的 logit 监督作为"锚点"，防止学生偏离太远，自然地缓解了遗忘问题。

LLM4Teach: Small RL Agent Guided by LLM Teacher

ZJ Lab AMMI2023.11
具身 OPD 先驱（2023 年）

LLM4Teach 发表于 2023 年 11 月，比 OPD 这个概念正式命名（2023.06）晚 5 个月，但与 OPD 并行开发。它是具身 AI（Embodied AI）中最早实现严格 on-policy 蒸馏的论文。

LLM 教师 + RL 学生的混合架构
学生：小型 RL 策略网络（仅 0.5M-5M 参数），在网格世界/导航任务中行动
教师：大型 LLM（GPT-4 或 Vicuna-13B），通过文字描述当前状态，生成推荐动作

OPD 信号（动作级蒸馏）：
L_distill = -log π_student(a_teacher | s)
a_teacher = LLM 推荐的动作（在学生当前状态 s 上）

RL 退火：α(t) = max(0, 1 - t/T_anneal)
L_total = α(t) · L_distill + (1-α(t)) · L_RL
训练初期 OPD 主导（引导探索），后期 RL 接管（任务优化）
RL 退火的设计哲学

LLM4Teach 的退火机制解决了 OPD 和 RL 的根本矛盾：OPD 在前期提供"如何行动"的方向感（减少盲目探索），RL 在后期提供"是否完成任务"的最终验证（避免被教师上限锁死）。这个退火思想后来影响了 LUFFY、HDPO 等混合方案。

在 OPD 概念前的先驱地位
时间线事件
2023.06GKD / MiniLLM 正式命名 OPD（语言模型领域）
2023.11LLM4Teach 独立实现具身 OPD（强化学习领域）
2024-2026OPD 概念在 Agent、VLA、具身 AI 领域迅速扩展
历史意义

LLM4Teach 证明了"LLM 教小型 RL Agent"这条路是可行的——在 OPD 概念兴起之前就给出了正确答案。它的成功在 2023 年底并没有得到足够关注，但现在回头看，它预见了 SCoRe、RPD 等后续工作的核心设计。如果你在做具身 OPD 项目，LLM4Teach 是必读的先驱论文。

OpenClaw-RL: GRPO + OPD Unified Agent Trainer

Gen-Verse Team2026.03
多域 Agent 的统一训练框架

OpenClaw-RL 是目前覆盖最广的 Agent OPD 框架，同时支持：终端操作（Shell）、GUI 操作（Web Browser / Desktop）、代码仓库（SWE-bench 风格）、工具调用（Function Calling）四大 Agent 场景。

后知之明提示（Hindsight Prompt）机制
Step 1：学生执行任务，收集轨迹
τ = (o_1, a_1, ..., o_T, a_T)，最终结果 r ∈ {0, 1}

Step 2：判别模型提取后知之明提示
给定完整轨迹 τ（包括最终结果），判别模型提取
"关键决策点"和"如果在 step k 做了 a_k' 会更好"的后知之明

Step 3：教师在后知之明上下文中重新评估
π_T(a_k | o_1,...,o_k, hindsight_context)
→ 教师 token-logprob 差距 = 方向优势（directional advantage）

统一损失（二值 RL + OPD）：
L = L_GRPO(r) + α · Σ_k KL(π_T_hindsight ‖ π_S)
多域实验结果
场景基线（纯 GRPO）OpenClaw-RL提升
TerminalBench42.3%51.7%+9.4pp
WebArena18.2%24.6%+6.4pp
SWE-Bench-Lite31.4%38.9%+7.5pp
ToolBench65.1%72.4%+7.3pp
后知之明机制的独特价值

传统 OPD 中教师只能基于当前状态评估（不知道最终结果）。OpenClaw-RL 的后知之明机制让教师在"已知结果"的条件下重新评估每一步，这使得教师能更精准地指出"哪一步是关键错误"——而不是均匀地对所有步骤施加 KL 监督。这是 Agent OPD 相比语言 OPD 最重要的创新之一。
