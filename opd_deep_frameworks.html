GKDTrainer 快速上手
from trl import GKDTrainer, GKDConfig

config = GKDConfig(
    beta=0.5,           # 学生 rollout 混合比例（0=纯off-policy, 1=纯on-policy）
    lmbda=0.5,          # FKL/RKL 混合比例（0=纯RKL, 1=纯FKL）
    seq_kd=False,       # True=序列级KD, False=token级KD
    temperature=0.9,    # 学生采样温度
)

trainer = GKDTrainer(
    model=student_model,
    teacher_model=teacher_model,
    args=config,
    train_dataset=dataset,
)
trainer.train()
TRL 的最大优势：文档和社区

TRL 的 OPD trainer 有完整的文档、示例脚本、单元测试。遇到问题可以在 GitHub Issues 找到 99% 已有的解答。对于学术实验和 PoC 验证，TRL 的易用性无可替代。生产场景下，TRL 的单卡训练效率（不支持 vLLM 集成）是主要瓶颈。

verl — ByteDance Seed RL Framework

生产就绪 ByteDance Seed GitHub 18k+ ★
OPD 实现：recipe/on_policy_distill/

verl 的 OPD recipe 是目前生产就绪度最高的开源实现，字节内部已在 Doubao 模型训练中大规模使用。核心设计：

  • Forward KL + 稀疏 top-K 教师 logits：只传输教师 top-K（默认 K=200）的 token 概率，大幅减少教师→学生通信带宽
  • vLLM 集成：教师推理用 vLLM 高吞吐推理引擎，学生训练用 FSDP/Megatron，完全解耦
  • Ray 分布式：教师和学生可以在不同 GPU 上并行运行，消除教师推理对训练的阻塞
架构图
[Ray Cluster]
  ├── [教师节点 × N]  vLLM 推理，生成 rollout + top-K logits
  │     ↓ (top-K logits, shape: [B, T, K])
  ├── [学生训练节点 × M]  FSDP/Megatron，计算 KL 损失，反向传播
  └── [数据缓冲区]  rollout 队列（异步，解耦教师/学生速度差）
关键超参数
参数默认值说明
kl_coef0.05KL 损失权重
top_k_logits200教师传输的 token 数，K 越大越准但带宽更大
kl_loss_type"forward_kl"可选 "reverse_kl"/"jsd"
rollout_batch_size512每次生成的 rollout 数量
rollout_n8每个 prompt 生成多少条 rollout
verl OPD 的已知局限

当前版本（2026.04）不支持跨 tokenizer 蒸馏（教师和学生必须用相同 tokenizer）；VLM 支持还在开发中（仅支持纯文本模型）。如果需要这两个功能，考虑 KDFlow。

KDFlow — Knowledge Distillation First Framework

KD 专项 BJTU（北京交通大学）2026.03
核心创新：传输隐层特征而非 logits

KDFlow 的架构与所有其他框架都不同：它传输教师的隐层状态（hidden states）而非 logits，然后在学生端重新计算 logits。

为什么传输隐层更高效？
维度传输 logits（其他框架）传输 hidden states（KDFlow）
数据量V × T（V=词汇表大小，通常 32K-128K）D × T（D=隐层维度，通常 4K-8K）
带宽节省基线4-32× 更少（D/V）
精度只有 top-K 近似完整分布（无截断）
跨架构支持需要相同 tokenizer可支持（隐层投影对齐）
性能基准
框架吞吐量（tokens/s/GPU）KD 质量（MATH）
verl (top-K logits)2,84074.2%
TRL (GKDTrainer)1,21073.8%
KDFlow4,060（1.43×→3.35× vs 其他）75.1%

KDFlow 在 Qwen3-VL 上的实验特别值得关注——它是唯一已经支持视觉语言模型 OPD 的高性能框架。

slime — GLM Post-Training Framework

Tsinghua THUDM GLM-4.5/4.6/4.7 训练框架
OPD 作为 RL 优势估计器的加性惩罚

slime 的 OPD 实现与其他框架有一个独特设计：Reverse KL token 级 OPD 不是作为独立损失项，而是作为任意优势估计器（advantage estimator）的加性惩罚嵌入 RL 训练。

实现细节
# slime 伪代码
for batch in rollout_buffer:
    # RL 优势估计
    advantages = compute_advantage(batch.rewards, batch.values)

    # OPD 惩罚：RKL token 级别
    with torch.no_grad():
        teacher_logprobs = teacher_model(batch.obs)
    kl_penalty = (student_logprobs - teacher_logprobs).mean(dim=-1)

    # 组合
    modified_advantages = advantages - kl_coef * kl_penalty

    # PPO/GRPO 更新
    loss = policy_loss(modified_advantages)

这种设计与 G-OPD 的理论框架完全吻合：OPD 等价于 KL 约束的 RL，约束以 Lagrangian 形式体现在优势函数上。

其余框架速览

7 个

NeMo-RL

NVIDIA  |  2026.01  |  替代已归档的 NeMo-Aligner

原生 OPD 支持（FKL/RKL/混合可配置 via kl_type）。Ray + Megatron + vLLM 三件套，适合 NVIDIA H100/B200 集群。对于超大模型（>100B）是首选框架，Megatron 的 3D 并行（TP/PP/DP）比 FSDP 更高效。

SkyRL

UC Berkeley NovaSky  |  OPD 支持从 2025.11 PR#585 加入

Reverse KL + 重要性采样。Ray + vLLM/SGLang 可切换。学术研究友好，代码库干净，适合做 RL+OPD 混合方法的消融实验。

rllm

UC Berkeley Sky Lab

examples/math_distill/opsd/ 提供 OPSD 自蒸馏实现。RKL 优势 = log P_teacher − log P_student。适合学习 OPSD 概念的代码参考，但生产稳定性不如 verl/TRL。

ROLL

Alibaba  |  Megatron 后端  |  VLM 支持

一等公民 DistillPipeline，various_divergence.py 实现多种散度（FKL/RKL/JSD/TVD）。Megatron 后端支持 Alibaba 内部超大规模训练。VLM 支持（多模态 OPD）是 ROLL 的差异化优势。

选型总结：2026 年最终建议

新项目默认选择：verl（生产最稳定，ByteDance 实战验证，文档完善）
跨架构/VLM 需求：KDFlow（唯一同时支持跨 tokenizer 和 VLM 的高性能框架）
快速 PoC：TRL（5 行代码搞定，OPD trainer 最齐全）
NVIDIA 集群：NeMo-RL（Megatron 原生，H100/B200 最优化）
