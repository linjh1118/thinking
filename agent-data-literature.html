Trace 优化：操作分类与代表工作

依据 Data Survey V3 / V3.1 的 Trace 正文归纳，并非原稿已有的独立表格。一篇论文可支持多个环节；下列工作提供各环节的代表性证据，不意味着它们均覆盖完整流程。点击代表工作可跳到下方论文。

优化环节核心问题方法代表工作证据边界
生成与采样去哪些状态收集经验？教师／学生 rollout，离线／在线采样，Best-of-N、共享前缀分支与树搜索。SWE-Master、SWE-TRACE记录策略、scaffold 与搜索预算；搜索得到的成功不能等同单次 rollout。
验证与筛选哪些轨迹可信且值得学？重放、正确性、防作弊、行为质量、可学性与策略覆盖。SWE-Fuse、LiteCoder-Terminal、LARK、NaturalThoughts、Trajectory Data Curation正确性不是完整排序标准；需控制难度、规模、学生模型和覆盖度。
轨迹分流不同结果如何利用？将直接成功、纠错成功、未解决失败与环境故障分别保留、加权或送修。SWE-Master、TRAJDEBUG、HarnessFix代表工作分别支持难度筛选、错误生命周期和系统故障路由，并非都实现了整套分流流程。
分支与步骤优化哪些动作真正有贡献？同一 checkpoint 比较候选动作，以步骤评分和路径选择生成更有效的经验。SWE-TRACE隐藏补丁对齐等是生成时特权信号；修改有状态动作后需重放并重建后缀。
压缩与失败归因哪些内容可删，错误在哪里？压缩冗余推理；定位关键错误，区分策略错误与 harness／验证器问题。Compress-Distill、BRIDGE、AgentRx、OAT、TRAJDEBUG、HarnessFix压缩与归因是不同子方向；推理文本压缩证据不能直接外推到有状态 Agent，异常也不等于因果责任。
经验转化最终形成什么学习产物？将经验转成紧凑／恢复型 SFT、偏好对、过程奖励或可复用的分层流程。SWE-TRACE、STAIR、Reusable Modules分别支撑路径／过程监督、流程抽象及组合接口；同状态偏好等完整产物谱系属于综述归纳。
